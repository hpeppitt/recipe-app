# Recipe Lab

A mobile-first recipe app where recipes are generated by AI and **branch like a version
tree**. Ask for a recipe, then ask for a variation of it, and another of that one; the
lineage is navigable. Recipes can be published to a shared library, favourited, and improved
by suggestions from other people.

Text-first by design: recipes carry no photos, permanently and on purpose. The identity of
the product is generation plus the tree. (Profile avatars are the one image in the app, and
they are capped at 128px.)

## Stack

React 19 + Vite 7 + TypeScript, Tailwind CSS v4, React Router v7. Dexie (IndexedDB) locally
and Firestore in the cloud, written to in parallel. Firebase Auth for anonymous and
passwordless email sign-in. Gemini via Firebase AI Logic, which holds the API key
server-side. Zod validates every AI response.

## Getting started

```bash
npm install
cp .env.example .env    # fill in your Firebase project values
npm run dev
```

Without a `.env` the app still runs in **local-only mode**: browse, import, export, and
share via URL, but no recipe generation — generation goes through Firebase, so there is no
proxy to call. See [docs/operations.md](docs/operations.md) for what each variable does and
why none of them is a secret.

```bash
npm run build    # type-check + production build
npm run lint     # 0 errors is the baseline
npm test         # 153 tests
```

## Status

A polished private beta rather than a shipped product. The engineering floor is solid: rules
enforced server-side, graceful degradation without Firebase, an accessibility pass done, 153
tests, and a fully cleared audit backlog. What is missing is product-grade operations — there
is no CI and nothing reports a client-side error — plus manual recipe editing, and rules that
actually enforce the invite-only circle. Those are Phase 1 and 2 of the
[roadmap](ROADMAP.md).
