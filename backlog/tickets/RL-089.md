## Context

The Organic design puts the sign-in prompt (5a), the avatar editor (14a), the email-link
states (15b), the recipe "More" menu and the tree intro (16a) in one bottom-sheet pattern.
The spec (`docs/design/organic/export/App Spec.dc.html`, Pantry sheet entry) states it:
"Sheet 36px top radius, 44×5 grabber, backdrop neutral-900 at 45%, tap backdrop to close."
Exact markup is at the end of `App Prototype.dc.html` (the `hasSheet` block).

Values to copy:

- Backdrop: `neutral-900` at 45% (`backdrop:bg-neutral-900/45` on a native dialog).
- Panel: anchored to the bottom, full width up to the app column (`max-w-lg`), `bg-surface`,
  top corners 36px (`rounded-t-[36px]`), padding `12px 22px 28px`, vertical gap 16px,
  `shadow-lg`, `max-height: 90%`, scrolls inside when taller.
- Grabber: 44x5px, `rounded-full`, `bg-neutral-400`, centred, first child. Decorative.

Existing modals (`ConfirmDialog`, `AuthModal`, `SignUpDialog`) use the native `<dialog>`
with `showModal()`, `aria-labelledby` and `onClose`, which gives focus trapping and Escape for
free. The sheet must do the same rather than hand-roll focus management.

Light only (RL-065): write no `dark:` classes.

## Acceptance criteria

- [x] `src/components/ui/Sheet.tsx` exports `Sheet({ open, onClose, labelledBy, dismissible = true, children })` built on a native `<dialog>` opened with `showModal()` and closed when `open` turns false, with the values above.
- [x] When `dismissible` is true: Escape closes (via the dialog's `cancel`/`close` path calling `onClose`), and a pointer down and up on the backdrop (outside the panel) closes. When false, Escape is prevented and the backdrop does nothing (needed for "Signing you in…", RL-109).
- [x] `aria-labelledby` is set from `labelledBy`. Focus moves into the sheet on open and returns to the opener on close (native behaviour; verify, do not reimplement).
- [x] Respects `prefers-reduced-motion`: any slide-up animation is off when reduced motion is requested. A 200ms slide-up is optional otherwise.
- [x] `Sheet.test.tsx` covers: renders children when open, calls `onClose` on Escape when dismissible, does not when not dismissible, calls `onClose` on a backdrop click and not on a click inside the panel.
- [x] `docs/architecture.md` lists `Sheet` in the `ui/` primitive set.
- [x] A `backlog/QA.md` entry: nothing uses it yet; RL-108 and RL-094 carry the visual checks.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Converting any existing modal to the sheet (each screen ticket does its own). Drag to
dismiss on the grabber.

## Verification

Unit tests; `ui-reviewer`. jsdom has partial `<dialog>` support; follow whatever pattern
`ConfirmDialog`'s tests already use.

## Notes

Built on native dialog like ConfirmDialog. Escape is handled via `cancel` (prevented, then `onClose` if dismissible) so the parent's `open` stays the single source of truth. Backdrop detection: pointerdown and click both targeting the dialog, with the panel as an inner div. No slide-up animation. ConfirmDialog has no tests, so the jsdom showModal stub follows SettingsPage.test.
