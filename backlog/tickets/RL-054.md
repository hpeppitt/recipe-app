## Context

The seam for product events is `services/analytics.ts`: every `track*` function goes
through one private `logEvent`, and `setAnalyticsUserId` is called from `AuthContext`.
`src/lib/telemetry.ts` and `src/services/telemetry.ts`, which the author's request named, are
the error beacon to `clientErrors`, not product analytics, so PostHog belongs in
`services/analytics.ts`. The error beacon stays as it is.

RL-052 adds the consent gate and a consent hook point in that file. RL-053 supplies the
project key, host and the approval to add `posthog-js`.

## Acceptance criteria

- [ ] `posthog-js` is added as a dependency (approved in RL-053) and loaded with a dynamic `import()` only after consent is granted, so it is not in the initial bundle and makes no request before opting in.
- [ ] It is initialised with `api_host` from `VITE_POSTHOG_HOST`, `autocapture: false`, `disable_session_recording: true`, `person_profiles: 'identified_only'`, and a manual pageview on route change. `VITE_POSTHOG_KEY` and `VITE_POSTHOG_HOST` are documented in `.env.example` with a note that the key is public by design.
- [ ] `logEvent` sends each event to PostHog, the only provider (GA4 is removed in RL-058). Event names and properties come from one table in `src/lib/analyticsEvents.ts`, tested so no event carries an email, display name, prompt or recipe text.
- [ ] `setAnalyticsUserId` calls `posthog.identify(uid)` only for a user with `emailVerified` and only after consent; anonymous and signed-out users stay anonymous. Sign-out calls `posthog.reset()`.
- [ ] Withdrawing consent in Settings calls `opt_out_capturing()` and `reset()` through RL-052's consent hook.
- [ ] Missing env vars or local-only mode mean PostHog never loads, with no errors.
- [ ] `docs/architecture.md` describes the analytics fan-out; `docs/operations.md` lists the new env vars.
- [ ] A `backlog/QA.md` entry: on the preview build, confirm no request to the PostHog host before consent; after "Allow", events appear in PostHog's live view; a verified user shows as identified by uid and an anonymous one does not.

## Out of scope

Feature flags, surveys, session recording, server-side events, and GA4 (removed in RL-058).

## Verification

`npm test`, `npm run build` (check the main chunk does not contain posthog), `npm run lint`,
then the browser check above.
