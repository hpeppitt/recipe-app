## Context

The human QA pass needs something to open on a phone. Firebase Hosting preview channels
give a throwaway URL per deploy without touching live. The workflow should run on every
push to `main` and on demand, so `/qa-pass` can point at a URL rather than asking the
author to build locally.

## Acceptance criteria

- [ ] `.github/workflows/preview.yml` builds and deploys `dist/` to a preview channel named `qa` with a 7-day expiry, on push to `main` and on `workflow_dispatch`.
- [ ] It uses `FirebaseExtended/action-hosting-deploy` with a `FIREBASE_SERVICE_ACCOUNT` repository secret and the `VITE_*` values from repository variables; the workflow skips with a clear message if the secret is absent rather than failing CI.
- [ ] `docs/operations.md` documents the secret, the variables, and the channel URL shape.
- [ ] `backlog/QA.md` tells the author the secret must be added by them (an agent cannot).

## Out of scope

Deploying rules, indexes or functions from CI. Live deploys stay manual via `/release`.

## Verification

The workflow file is valid (run `npx action-validator` or at least a YAML parse). The first real run needs the secret and is the author's.
