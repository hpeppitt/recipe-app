## Context

The human QA pass needs something to open on a phone. Firebase Hosting preview channels
give a throwaway URL per deploy without touching live. The workflow should run on every
push to `main` and on demand, so `/qa-pass` can point at a URL rather than asking the
author to build locally.

## Acceptance criteria

- [x] `.github/workflows/preview.yml` builds and deploys `dist/` to a preview channel named `qa` with a 7-day expiry, on push to `main` and on `workflow_dispatch`.
- [x] It uses `FirebaseExtended/action-hosting-deploy` with a `FIREBASE_SERVICE_ACCOUNT` repository secret and the `VITE_*` values from repository variables; the workflow skips with a clear message if the secret is absent rather than failing CI.
- [x] `docs/operations.md` documents the secret, the variables, and the channel URL shape.
- [x] `backlog/QA.md` tells the author the secret must be added by them (an agent cannot).

## Out of scope

Deploying rules, indexes or functions from CI. Live deploys stay manual via `/release`.

## Verification

The workflow file is valid (run `npx action-validator` or at least a YAML parse). The first real run needs the secret and is the author's.

## Notes

- Actions pinned by version tag, matching ci.yml (checkout@v4, setup-node@v4, Node 22, npm cache); the deploy action uses `@v0`, its documented floating tag. No SHA pinning, since ci.yml does not.
- Gates not repeated: ci.yml already runs on push to main.
