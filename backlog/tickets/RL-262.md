## Context

Two page tests fail now and then in CI and pass on rerun. Both assert focus synchronously right
after a `findBy*`, but the component moves focus in a passive `useEffect`:

- `src/pages/SharedRecipePage.test.tsx`, "saves one copy keeping the original author, then offers
  Open in my library". `SharedRecipePage.tsx` focuses `openSavedRef` in a `useEffect` on `savedId`
  (the comment above it explains why). The test awaits
  `findByRole('button', { name: 'Open in my library' })`, then checks
  `document.activeElement` at once. Under load it is still the body.
- `src/pages/ImportPage.test.tsx`, "a failed save says Saving, then shows the chat error, refocuses
  the button, writes nothing and stays". `src/components/recipe/ImportReview.tsx` refocuses the
  failed choice's button in a `useEffect` on `[saveError, choice]`. The test awaits
  `findByRole('alert')`, then checks `document.activeElement` at once. Under load it is still the
  preview `h2`, which the `[preview]` effect focused earlier.

Root cause: the promise is resolved or rejected outside `act`, so React commits the new DOM and
runs passive effects as separate steps. `findBy*` resolves on the DOM mutation from the commit,
which can come before the effect that moves focus. The product behaviour is correct; the
assertion is early. The repo already uses the fix shape:
`await waitFor(() => expect(document.activeElement).toBe(...))` in
`src/components/tree/ShopFamilySheet.test.tsx`.

The draft also named `SettingsPage.test.tsx` "revokes the object URL after a delay". That one is
already deterministic: since #137 (3b92431) it captures the revoke timer in `revokeTimers` and
fires it by hand, so it is not part of this ticket.
