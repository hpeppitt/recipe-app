## Context

Filed by the loop, not groomed. `SharedRecipePage.test.tsx` "saves one copy keeping the original
author, then offers Open in my library" asserts focus lands on a button, but under load focus is
still on the body. It failed CI on PR #189 (passed on rerun) and once locally during RL-159.
`SettingsPage.test.tsx` "revokes the object URL after a delay, not at once" asserts a real 1000 ms
`setTimeout` has not fired yet, so a slow runner fails it (seen on PR #115).

## Acceptance criteria

- [ ] The SharedRecipePage focus assertion waits for focus (`waitFor`) or the component moves focus synchronously; the test passes 20 runs in a row with `--repeat` or a loop.
- [ ] The SettingsPage revoke test uses fake timers instead of a real timeout.
- [ ] No production behaviour changes unless the focus move itself is racy, in which case the fix is in the component and noted.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

Other tests.
