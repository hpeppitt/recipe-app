## Context

Recency is the only discovery axis on Explore. Tags already exist on every recipe. ROADMAP
3.2 scopes a curated chip row (seeded from `lib/constants.ts`, not the corpus) querying
`where('tags','array-contains',tag)` + `orderBy('createdAt')`, which needs one composite
index.

## Acceptance criteria

- [x] A chip row above the Explore feed with a curated tag list; one active chip at a time; the chip filters the paged query.
- [x] The composite index is added to `firestore.indexes.json` and documented in `docs/data-model.md`.
- [x] Deploying that index is listed in `backlog/QA.md` for the author, because an index deploy is a production change.

## Out of scope

Free-text tag browsing, tag counts.

## Verification

Emulator query with the index, or a unit test on the query builder. The index deploy itself is the author's.

## Notes

Marked `irreversible` only because it needs an index deploy; the code is fully reversible.

Implemented 2026-10-15. `getPublishedRecipesPage(cursor, pageSize, tag)` adds `where('tags','array-contains',tag)` before the existing `orderBy('createdAt','desc')`; `useCloudLibrary(enabled, tag)` refetches from page one on a tag change. Chips use `EXPLORE_TAGS` (`lib/constants.ts`) and the shared `Chip`. The index is guarded by `src/lib/indexes.test.ts`. Emulator run (`firebase emulators:exec --only firestore --project demo-rl009`, runQuery on `recipes`, tag + createdAt desc): signed-out 200, signed-in verified (unsigned test JWT) 200; the rule is `allow read: if true`. The emulator does not enforce indexes, so READY in production is untested. 390 px layout and dark mode are in QA.md. Tag case risk is in DECISIONS.md.
