## Context

From 1024px (`lg`) the recipe page shows a Family button in its footer (`RecipeDetailPage.tsx`
~625, `hidden lg:inline-flex`) and the header's Version tree icon (`RecipeHeader.tsx`, Network
icon, `href=/recipe/:id/tree`); both leave the recipe for `/recipe/:id/tree`. RL-116 listed 21b
out of scope; the author made it v1 on 2026-10-20. Below 1024px nothing changes.

The views exist: `TreeView` (`tree`, `currentId`, `onOpen`), `TimelineView` and `MapView`
(`recipes`, `currentId`), fed by `useRecipeTree(rootId)` (`tree`, `recipes`); the page already
has `family` and `ancestors` from `useRecipeLineage`. `Sheet.tsx` shows the house pattern for a
native `<dialog>` (focus trap, Escape, focus return from the browser). Links that open another
recipe must carry the list origin (`carriedListOrigin`, `src/lib/paneMode.ts`).

### Design

Right-side modal pull-out over the page: a `<dialog>` 420px wide, full height, `bg-surface-secondary`
(the spec's surface), padding 28px 22px 0, column gap 14px, `shadow-lg`; backdrop
neutral-900 at 40% (`backdrop:` styles like `Sheet`), clicking it closes. Contents top to bottom:
- Header row: "<root title> family" in the heading font 20px, flex 1; a compact `SegmentedControl`
  Tree / Timeline / Map on a ground background (selected = accent fill, ground text); a 44px
  close button (X).
- The chosen view for this family with `currentId` = this recipe. Tree is the default each time
  the panel opens; the choice is panel state, not the URL.
- Pinned at the bottom (margin-top auto, 24px bottom margin): primary button 50px tall,
  `GitBranchPlus` icon, "Branch from this one", to `/recipe/<id>/vary`.

## Acceptance criteria

- [ ] `FamilyPanel` component (`open`, `onClose`, `recipe`, `recipes`, `tree`) renders the design above on a native dialog; Escape and the backdrop close it; focus moves into it on open and back to the opener on close.
- [ ] From `lg` (use the existing `useMediaQuery` hook) the footer Family button and the header tree icon open the panel; below `lg` they behave as today. The More sheet's "See the family" keeps navigating at every width.
- [ ] Tapping a node or a stop's Open in the panel closes it and opens that recipe with the list origin carried, so in the two-pane layout the list stays beside it. "Branch from this one" closes it and navigates to `/recipe/<id>/vary` (RL-134's sign-in sheet applies if it has merged).
- [ ] The views fit 376px of content width: Tree scrolls sideways for deep chains as it does on the tree page; Map's big-family banner still offers Timeline (switching the panel's view, not the URL).
- [ ] Tests: opens from the Family button at lg (mock the media query), not below; segmented control switches views; Escape closes; node tap navigates and closes.
- [ ] `docs/capabilities.md` "Version tree view" row mentions the wide-screen panel.
- [ ] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

The tree page itself, the 16a intro, the carousel (21b notes the carousel is not needed beside
the tree; it stays, by the author's 21a choice), Activity in the two-pane layout.

## Verification

Gates: tests, `ui-reviewer`. Human at 1280x800 and 1024x768: open a recipe from Explore,
press Family, switch Tree, Timeline and Map, open another version from the panel (the list stays
on the left), press Branch from this one; Escape and backdrop close. At 1023px the button still
goes to the tree page.
