## Context

Author answer of 2026-10-18: an import lands as Saved only and is never published.

Today `importRecipes(raw)` (`src/db/recipes.ts`, called from `SettingsPage.tsx`) validates
with `parseImportedRecipes` (`src/lib/import.ts`) and `bulkPut`s the rows. A row keeps the
`createdBy` in the file, and one with none gets `{ uid: 'local', displayName: null }` from
`ImportedRecipeSchema`. The importer's uid is never stamped in, but a file exported from
this account carries it. Two sync rules then remove the row:

- RL-076/RL-078 remove an own row (`createdBy.uid` equal to the user) that the cloud
  snapshot lacks.
- RL-076's tidy removes rows whose uid is in `getPreviousUids()` (`src/services/storage.ts`).
  An old export from this device, the pre-wipe ones included, carries such a uid.

RL-084 counts a row as Created or Branched only when `createdBy.uid` is the user, and puts
`'local'` rows in Saved (the author confirmed that default). So the smallest rule is to
re-stamp exactly those two cases as `'local'`, keeping the display name. The original owner
is still shown, and both sync rules and the Created/Branched split leave the row alone. Rows
from anyone else keep their owner unchanged. Rows with no owner already become `'local'`,
which is Saved, and that stays: there is no owner to show, and stamping the importer would
make the row their own and so removable.

One collision needs a rule. A file row whose id is already in Dexie as one of the user's own
recipes is the cloud-backed copy. Overwriting it with a `'local'` stamp would make it look
Saved until the next snapshot. Leave such rows as they are and count them.

`lib/` cannot read storage (`docs/architecture.md`), so the uids are passed in.

## Acceptance criteria

- [x] `parseImportedRecipes(raw, now, protectedUids)` re-stamps a row whose `createdBy.uid` is in `protectedUids` as `{ uid: 'local', displayName: <its displayName> }`. All other rows, including rows with no owner (`'local'` by the schema default), are unchanged. The default for `protectedUids` is `[]`.
- [x] `importRecipes(raw, { uid, previousUids })` passes `[uid, ...previousUids]` (uid omitted when signed out) and does not overwrite a row already in Dexie whose `createdBy.uid === uid`. Those rows are counted in a new `alreadyInAccount` field of `ImportResult`.
- [x] `SettingsPage.tsx` passes the signed-in uid and `getPreviousUids()`. `describeImport` adds "{n} already in your account, left as they are." when `alreadyInAccount > 0`.
- [x] No import path calls `publishRecipe` or writes to Firestore.
- [x] Tests: `src/lib/import.test.ts` covers re-stamping the importer's uid and a previous uid, another owner kept, a missing owner as `'local'`. `src/db/recipes.test.ts` covers the own-row collision being left alone and counted.
- [x] `docs/capabilities.md` import row and the 1b entry in `docs/decisions.md` state the rule: imports are Saved copies, never published, never stamped with an account uid of this device.
- [x] A `backlog/QA.md` entry: as a verified user on the preview, export, delete one recipe from its page, import the file; the deleted one comes back under Saved, not Created or Branched, and is still there after a reload; the import message counts the rest as already in your account.
