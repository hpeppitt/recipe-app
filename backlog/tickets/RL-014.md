## Context

Whatever RL-001 decides, the shape is the same: `services/gemini.ts` is the named seam for
the AI transport (see docs/architecture.md). The client keeps building the chat UI and
validating with Zod; the proxy owns the system prompt, the model name, the per-user quota
and the key. Regroom this ticket once RL-001 picks option A (Blaze + `functions/`) or B
(Cloudflare Worker, Firebase stays on Spark); the acceptance criteria below are the
option-independent part.

## Acceptance criteria

- [ ] `services/gemini.ts` becomes `services/generation.ts` exposing the same `ChatSession` interface; callers do not change.
- [ ] The proxy verifies a Firebase ID token, enforces a per-user daily and monthly generation quota, and returns a structured error the client maps in `lib/errors.ts` to copy that says when the quota resets.
- [ ] The model name and provider are server-side configuration, not client code, and the system prompt no longer ships in the bundle.
- [ ] The response is validated against the recipe JSON schema server-side (provider structured output) and again by Zod on the client.
- [ ] Local-only mode behaves exactly as today: composer disabled with the existing notice.
- [ ] `docs/architecture.md`, `docs/operations.md` (new env vars and deploy step), `docs/data-model.md` (quota storage) and `docs/decisions.md` are updated.

## Out of scope

Changing the prompt content, the recipe schema, or the chat UI.

## Verification

Unit tests for the quota logic (pure, in the proxy's own test suite). The deploy of the proxy is the author's and goes on the QA checklist.
