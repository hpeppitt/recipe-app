## Context

The route takes its final name now so Phase 2's Kitchen (RL-214) only adds a tile. Outside
`AppShell` with its own back button, like `/settings`. Data from `useOwnCooks` (RL-196), copy
from RL-195.

### The design (the implementer has no other copy)

- Back button row (50px top padding on mobile, 12px sides).
- Caprasimo 30px "Cook log", then 13px `neutral-700` `cookLogSummary`.
- Cards (16px 22px 0, gap 12px): padding 12px, 28px radius, `bg-surface-secondary`, gap 12px:
  a 64px rounded square (22px radius) with the emoji at 30px on a rotating tint (`accent-200`,
  `accent-2-200`, `bg-surface-secondary`), then the recipe title 15px bold, `cookWhen` 12px
  `neutral-700`, and the note 13px italic `neutral-800` in quotes when present; a tag at the top
  right, 11px semibold with icon: Branched (`bg-accent-2-200`, `text-accent-2-900`), Again
  (`bg-surface`, since the card is already `bg-surface-secondary`), Tweak (`bg-accent-100`,
  `text-accent-900`). A card links to the recipe; a Branched tag links to the branch.
- Empty: 19a empty state "Nothing cooked yet" · "Tap Cooked on any recipe after you make it."
  · "Explore recipes". Signed out or anonymous: the 19a pattern with Sign in.
- Entry: on the own profile, a full-width row under the tiles: `ChefHat` icon, "Cook log",
  count at the right, chevron, linking here.

## Acceptance criteria

- [ ] Route `/kitchen/log`, lazy; the profile row; layout and states as above.
- [ ] The cook record stores no title, so titles and emoji come from Dexie, else `getPublishedRecipe` for at most 20 missing ids per visit (kept in memory), showing "A deleted recipe" when missing.
- [ ] Tests: summary, tags, empty, signed out, missing recipe.
- [ ] `docs/capabilities.md` row and Routes table.
- [ ] A `backlog/QA.md` entry: log three cooks (one with a note, one Needs a tweak, one grown into a branch) and check the page and tags at 390px, light and dark.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
