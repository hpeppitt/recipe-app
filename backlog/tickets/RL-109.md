## Context

The author picked 15b: "Sheet · opened on another device ... The page underneath stays put,
so the person lands where the link pointed. Expired and signing-in become the same sheet with
different copy." (`docs/design/organic/export/Collaboration and Account.dc.html` 15b; spec
row "Edge states" in `App Spec.dc.html`). 15c, the stranded identity notice, does not apply:
it was removed in RL-032 because an anonymous account owns no cloud data (decision 2 note).

Today `src/components/auth/EmailLinkStatus.tsx`, mounted in `AppShell` above the outlet,
renders an inline banner per `linkState` from `AuthContext`: `completing` ("Signing you
in…" with a spinner), `needs-email` (email field plus the Terms box, then
`submitLinkEmail`), `done` with `linked` ("You're signed in, and your recipes came with you"),
and failures `expired`, `email-taken`, `failed` with Dismiss. The order of operations in
`docs/decisions.md` ("Email-link completion has a required order of operations") lives in
`AuthContext` and must not change; this ticket only changes how the states are shown. Copy
stays, except one correction below.

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`; neutral-800 text is `text-text-secondary`. Light only. 44px targets.

Values to copy, in `Sheet` (RL-089), gap 14px:

- A 52px circle with a 24px icon, then a `font-heading` 24px headline (line-height 1.1),
  then 14px `text-text-secondary` body, then actions.
- `completing`: `bg-surface-secondary` circle with the existing `Spinner`; "Signing you
  in…"; no body, no actions; `dismissible={false}`; `role="status"` text.
- `needs-email`: `bg-accent-2-200 text-accent-2-800` circle, `Smartphone` icon; headline
  "Finish signing in here"; body is today's explanation ("You opened this link in a
  different browser from the one that asked for it, so we need the address again to check
  the link belongs to you."); the Terms box; an email field (label "Email", pill 50px,
  1.5px accent border on focus); primary 52px "Sign in" (was "Continue"); errors as today.
  Dismissible.
- `expired`, `email-taken`, `failed`: `bg-accent-200 text-accent-800` circle, `Hourglass`
  for expired and `TriangleAlert` otherwise; today's titles and bodies; one secondary
  "OK" (was "Dismiss") that calls `dismissLinkState`. Dismissible. Correction to the
  `email-taken` body, because an anonymous account cannot make recipes (decision 1a): "...so
  bookmarks you made here as a guest stay on this device under your guest name rather than
  moving across. Request a new link to continue."
- `done` with `linked`: `bg-accent-2-200` circle with `Check`; "You're signed in, and your
  bookmarks came with you" (was "recipes", same decision 1a reason); body unchanged;
  primary "Got it".

## Notes

- 2026-10-19 implementer: `EmailLinkStatus` now renders one `Sheet` whose `open` is derived from `linkState` (closed on `idle` and on `done` without `linked`), so dismissing closes it for good and it closes by itself when completion ends in a plain sign-in. The same sheet stays open across needs-email, completing and a failure, and moves focus to each new headline (the Email field on needs-email). `onClose` is `dismissLinkState` for every state; `dismissible` is false only for `completing`. No AuthContext, service or rules change.
- `EmailField` (AuthSheetParts) gained an optional `inputRef` prop so the field can be focused after the dialog opens. It is the 52px RL-108 field, not the 50px in the design values, so both sheets match. Its label is "Email" (was the aria-label "Email address").
- The needs-email headline is the design's "Finish signing in here" (was "Confirm the email address to finish signing in").
- The done and error states lost their `role="status"` and `role="alert"`: the sheet is announced by its headline on open and focus moves to the new headline on each change, so a live region would announce it twice. Only the completing text and the tick-the-box error are live. After review, the body is the dialog's accessible description (new optional `Sheet` prop `describedBy`) for every state but completing.
- Tests moved from the shared TermsAcceptance suite stay there (button name now "Sign in"); new `EmailLinkStatus.test.tsx` covers each headline and action, the non-dismissible spinner, Escape, backdrop and action closes each calling `dismissLinkState` once, the Terms block, focus, and that only the three context fields are read. Each negative assertion was checked by breaking the code and watching it fail.
- Review fixes, 2026-10-19: `Sheet` now listens for the dialog's native `close` event. When the browser closes it while `open` is still true (Chrome can, on a second Escape without user activation), it reopens a non-dismissible sheet and calls `onClose` for a dismissible one; a close the parent asked for is a no-op (an `openRef` updated in the open effect). The needs-email form moved into a child (`NeedsEmailForm`) that unmounts with the state, so the address, tick and error reset with each attempt. The address is trimmed at the call site; the email input already strips padding itself, so that test guards the contract and cannot single out the trim. Other Sheet users' tests pass unchanged.
