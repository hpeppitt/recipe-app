## Context

RL-048 introduces `writeWindows` and the transaction pattern for suggestions and replies.
Two other write paths can be used to flood people or the library:

- Notifications. Favouriting and unfavouriting, or following and unfollowing, in a loop
  writes a notification each time (`addCloudFavorite`, `followUser` in
  `services/firestore.ts`). RL-015 fixes their shape; this caps their rate.
- Recipe creates. Publishing is gated by verification and RL-016's size caps, but nothing
  stops a script creating thousands of documents.

Caps (groomer's choice): notifications 60 per hour, recipe creates 30 per day.

## Acceptance criteria

- [ ] `writeWindows` accepts the actions `notification` and `recipe`, with their caps and windows in the rules and in `src/lib/rateLimit.ts`.
- [ ] Notification create and recipe create require the `getAfter` check for their action.
- [ ] Every notification write in `services/firestore.ts` goes through the window transaction. When limited, the notification is skipped silently (no user-facing error, since notifications are fire-and-forget) and reported with context `rate-limited-notification`.
- [ ] `publishRecipe`'s create path goes through the window transaction; when limited it throws `RateLimitedError`, mapped in `lib/errors.ts` to "You've published a lot today. Try again tomorrow." The re-publish (update) path is not limited.
- [ ] Tests in `src/lib/rateLimit.test.ts` cover the new actions.
- [ ] `docs/data-model.md` updated.

## Out of scope

Limits on favourites and follows themselves (only their notifications), and the deploy
(RL-051).

## Verification

`npm test`. Emulator probes: notification create without the window write (deny), the 61st
in an hour (deny), the 31st recipe create in a day (deny), a re-publish at the cap (allow).
