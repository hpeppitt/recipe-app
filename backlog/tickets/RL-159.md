## Context

Written for RL-157's recommended answers; regroom if the author chose otherwise. Today the More
sheet's "Delete" (`RecipeHeader.tsx` ~156) opens "Delete Recipe" / "This will delete "<title>"
and all N variation(s) beneath it" (`RecipeDetailPage.tsx` ~518), and `handleDelete` runs the
cloud subtree delete first, then the local one (RL-080 order; `runCloudDelete`, 10 s bound,
"Couldn't delete this recipe" with Try again). Dexie has no `update()` (data-model.md "Gotcha");
use get then put. RL-158 allows the batch in the repo rules; test against the emulator.

### Design (19a)

Menu row "Delete version" on a branch (danger, accent-700). Dialog: title "Delete this
version?" (heading 22px), body "Its <N> branches stay, and move up to <parent title>." (N =
direct children; 1 branch "Its branch stays, and moves up to ..."; 0 children "This can't be
undone."), buttons Keep it (secondary) and Delete (destructive accent-700), as `ConfirmDialog`.

## Acceptance criteria

- [ ] For a branch: `deletePublishedVersion(uid, recipe, childIds)` commits one batch: delete the version, and update each direct child to `{ parentId: recipe.parentId, depth: child.depth - 1 }`. Cloud first within 10 s; on success, local: delete the row and put each local child with the new `parentId` and `depth`; on failure nothing local changes and the existing failure dialog shows.
- [ ] Local-only and unverified owners do the local half only.
- [ ] The original keeps today's whole-family delete when every version is the owner's; when another cook has a version in the family, the menu row reads "Delete" disabled-looking with the line "Other cooks have branches here, so the original stays." (RL-157 answer 3b) and no dialog opens.
- [ ] After deleting a version the page goes to its parent (`/recipe/<parentId>`, replace), not to `/`.
- [ ] `src/db/recipes.ts` gains `reparentChildren(childIds, parentId)` (get then put) with a test; `deleteRecipeTree` stays for originals.
- [ ] Tests: batch contents for a version with own and others' children; local reparent; failure leaves the device untouched; dialog copy for 0, 1 and 3 children; original blocked when others have versions.
- [ ] `docs/capabilities.md` "Delete a recipe" row and `docs/architecture.md` describe version delete and the original rule; decisions.md was updated by RL-157.
- [ ] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Deploy (RL-160). Notifying moved branches' authors. Promoting a child to original.
