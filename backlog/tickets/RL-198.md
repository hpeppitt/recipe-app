## Context

The footer (`RecipeDetailPage.tsx` ~620-655, RL-104) shows Family (lg only), Suggest or Edit,
and the wider Branch this recipe. Flex bases are tuned so it fits at 320px (comment at ~628).
Method steps tick through hidden checkboxes (`InstructionList.tsx`, RL-103), not persisted.
Signed-out and anonymous visitors get the sign-in sheet (RL-134 routes Branch through it;
`AuthAction` in `AuthSheetParts.tsx` names the headline).

## Acceptance criteria

- [x] A "Cooked" button (`ChefHat` icon, same secondary style as Suggest) sits between Suggest/Edit and Branch, on the recipe page and `/shared/:id`. At widths under 360px the Suggest, Edit and Cooked icons hide (text stays), as Suggest's does today; the three buttons and Branch fit at 320px with no wrap.
- [x] Cooked opens `CookedSheet` for verified users; others get the sign-in sheet with a new `AuthAction` `{ kind: 'cook' }` ("Sign in to log a cook", `ChefHat`). Local-only mode hides Cooked.
- [x] Ticking the last method step (when every step is ticked, or the last one alone) opens the sheet once per recipe visit for verified users; unticking does not reopen it; signed-out users are not interrupted.
- [x] After a save the Made-by row (RL-199, when present) refreshes. (Not present yet: RL-199 adds the refresh in useCookedEntry onSaved.) (Not applicable yet: the page does not use useRecipeCooks; RL-199 must pass a refresh to onSaved in useCookedEntry.)
- [x] Tests: button visibility by auth state, sheet open, last-step trigger once, layout classes at small widths.
- [x] `docs/capabilities.md` Log a cook row becomes shipped (rules deployed by RL-209).
- [x] A `backlog/QA.md` entry: at 320px and 390px the footer fits; Cooked opens the sheet; tick every step on another recipe: the sheet appears once; signed out, Cooked opens the sign-in sheet. Light and dark. Live only after RL-209.
- [x] `npm test`, `npm run lint`, `npm run build` pass.
