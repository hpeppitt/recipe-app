## Context

The author is the only user and has authorised wiping all previous data, including every
Firebase Auth user and with no backup (author answers, 2026-10-14), so the new rules
(RL-040 and the audit rules) start from a clean slate. That makes the pre-gate anonymous
recipes (RL-011), any bad-owner suggestions (RL-017), out-of-range `createdAt` values
(RL-016), non-data avatar URLs (RL-019) and stranded identities (RL-032) disappear rather
than needing cleanup. Deleting production data is on the "What needs a human" list in
`backlog/README.md`.

Collections in use (`docs/data-model.md`): `recipes`, `favorites`, `suggestions` with its
`messages` subcollections, `notifications`, `profiles`, `follows`, `clientErrors` (including
the `/__deploy-check` document from 2026-08-08), `rateLimits`. No backup is taken.

Sequence: this ticket runs first, then RL-022 (indexes, client release, rules). Do not use the
live app between the wipe and the rules deploy.

## Acceptance criteria

- [ ] Dry run against the emulator: seed it through `npm run dev:emulated` (a published recipe with a variation, a suggestion with a reply, a favourite, a follow, a notification), then run `firebase firestore:delete --all-collections --force` with `FIRESTORE_EMULATOR_HOST` set, and confirm in the emulator UI that every collection and subcollection is empty.
- [x] Live run by the author: `firebase firestore:delete --all-collections --project recipe-lab-3832b`, then the console shows no collections.
- [x] Every Firebase Auth user is deleted (Authentication > Users in the console, or a one-off Admin SDK script run locally with application default credentials and kept outside the repo), and the Users list shows none. The author's account is re-created by signing up on the new client after RL-022's release, which also records terms acceptance once RL-051 is live.
- [x] Each device the author uses is signed out first, or its stale session is cleared on next load, since the deleted uid no longer exists.
- [x] `docs/operations.md` records the date, what was wiped (Firestore and Auth), and the dry-run command.
- [x] The author's devices: local Dexie recipes survive the wipe but stay stamped with the deleted uid, so the new account cannot publish them (the create rule requires `createdBy.uid == request.auth.uid`). Before the wipe the author chooses per device: "Clear All Data" in Settings, or keep them as local-only recipes. The choice is noted in `backlog/QA.md`.

## Out of scope

Wiping local Dexie data on any device, and any rules or code change.

## Verification

Human only for the live run. The dry run can be done by an agent against the emulator.
