## Context

Written for RL-255's recommendations. RL-211's collection rule is owner-only with
`visibility == 'private'` fixed. The profile `followerCount` ±1 bump (`isFollowerCountBump`
pattern) is the model for a foreign counter update.

## Acceptance criteria

- [ ] Collections: read if `resource.data.visibility == 'public'` or the owner; the owner may change `visibility` between `private` and `public`, `description` (string <= 280 or null) and `lastAddedAt` (== request.time, set when `recipeIds` grows); anyone verified may bump `followerCount` by exactly ±1 and nothing else.
- [ ] `match /cookbookFollows/{followId}`: id `{uid}_{collectionId}`; create and delete by that uid, verified, only for a public collection (`get`); keys `uid, collectionId, createdAt, lastSeenAt`; update only `lastSeenAt` by the follower; read by the follower only.
- [ ] Emulator probe codes in Notes, including a signed-out read of a public (200) and a private (403) collection, a follow of a private one (403), and a +2 bump (403).
- [ ] `docs/data-model.md`, "in the repo, deployed by RL-261".
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Client.
