## Context

RL-135 stores a `PendingAction` before the link is sent and returns the link to the page.
This ticket runs it. The verified state arrives asynchronously after the link completes
(`AuthContext` `runEmailLinkCompletion`), and the Terms check (`checkTermsOnce`, RL-047) may
block contributing until accepted, so the hook must wait for a verified user whose terms are
settled. Writes reuse the existing paths: favourite `toggleFavorite` (`useFavorite` /
`useCloudFavorite`), follow `toggleFollow` (`useFollow`), suggest opens suggest mode
(`setSuggestingFor` on the recipe page, `setSuggesting` on the shared page), branch navigates
to `/recipe/<id>/vary`.

## Acceptance criteria

- [ ] `usePendingAction(match: (a: PendingAction) => boolean, run: (a: PendingAction) => void)`: when the user is verified, auth is not loading, the Terms prompt is not pending, and a stored action passes `parsePendingAction` and `match`, it clears the stored action first, then calls `run` exactly once (StrictMode-safe ref guard). A stored action that does not match the page stays stored until it expires or another page matches it.
- [ ] Recipe page and shared page: `save` turns the favourite on only if it is off (never toggles it off); `suggest` opens suggest mode when the recipe can be suggested to (otherwise nothing); `branch` navigates to `/recipe/<id>/vary`. Profile: `follow` follows only if not already following.
- [ ] Each run shows the page's existing confirmation (Saved state, Following state, suggest mode, the composer); a failure shows the page's existing error, and the action is not retried.
- [ ] An expired, malformed or mismatched action never runs. Signing out clears it.
- [ ] Tests (`usePendingAction.test.tsx` with a mocked auth context): runs once for a matching action, not for unverified, not while terms pending, not when expired, clears before running, and `save` does not unsave an already saved recipe.
- [ ] `docs/capabilities.md`: the sign-in row says the interrupted save, follow, suggest or branch now runs on return, same device only, within an hour.
- [ ] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Guest (anonymous) upgrades through `AuthModal`'s guest option beyond `save`. Any new
confirmation UI. Cross-device runs.

## Verification

Gates: tests, `ui-reviewer`, `data-integrity-reviewer` (favourite and follow writes reached
from a new trigger). Emulator walk for each of save, follow, suggest and branch: signed out,
tap, send link, open it in the same browser, see the action done once; reload the page and see
it does not run again.
