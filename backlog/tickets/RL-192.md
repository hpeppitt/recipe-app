## Context

Phase 1 records who cooked what. Everything later (Kitchen's cook log, the Cooked stat, Explore
by cooking, cook counts on the tree, the learned taste profile) reads it. The design makes
"Made N times · N would make again" and other cooks' notes public on the recipe page, which
changes what the app shows others, so it needs the author (README "What needs a human").
Constraints: decision 1a (anonymous accounts hold local bookmarks only, every cloud write needs
a verified email); decision 1b (cloud is the source of truth for a verified user's data); a
Dexie schema bump is irreversible (avoided below); the rules-only rate limits (RL-048/049,
`writeWindows`); the operator export/erase script (`scripts/data-request.mjs`, RL-055) and
Download my data (RL-056) must cover any new collection. RL-194 to RL-203 and RL-207 to RL-209 are written for the
recommendations and are regroomable.

## Questions and the groomer's recommendation

1. **Store**: a top-level Firestore collection `cooks/{autoId}`:
   `{ uid, displayName, recipeId, rootId, recipeOwnerId, vote: 'again' | 'tweak', note: string | null (<= 500 chars), branchId: string | null, createdAt (server time) }`.
   Cloud only, no Dexie table (recommended; no schema bump, works across devices).
2. **Who can log**: verified accounts only; signed-out and anonymous users get the sign-in sheet
   "Sign in to log a cook" (recommended; matches 1a).
3. **Repeat cooks**: each cook is its own document; "Made N times" counts documents, so one person
   cooking twice counts twice (recommended; the design's numbers read as events).
4. **Visibility**: public read of every field above (counts, votes, notes, cook names), so the
   Made-by row and Notes work signed out (recommended). Alternative: notes private to the cook
   and the recipe owner, counts public. The sheet would say "Notes show on the recipe for other
   cooks."
5. **Changes**: the cook may delete their own cook and may set `branchId` once (to credit a
   branch grown from the note); no other updates (recommended). The recipe owner cannot delete
   other people's notes (no moderation, as for suggestions; reporting is cut).
6. **Rate limit**: a new `writeWindows` action `cook`, 20 a day, via the same transaction
   pattern (recommended).
7. **Counting**: Firestore count aggregation (`getCountFromServer`) with equality filters on
   `recipeId` (and `vote`), no composite index, about one read per 1000 counted (recommended),
   rather than a denormalised counter that other users would have to bump.
8. **Data rights**: cooks join Download my data and the erase script; an account deletion
   removes them (recommended).
9. **Privacy policy**: a cook log paragraph drafted in RL-208, signed off by the author.
