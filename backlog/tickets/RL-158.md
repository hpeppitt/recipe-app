## Context

RL-157 decided 2026-10-20: the recommended answers, plus the moved branches' authors are notified (a `moved` notification in the same batch). Today
`allow update` on recipes is `isViewIncrement() || isFavoriteCountBump() || isOwnerUpdate()`
(`firestore.rules` ~157-160), so nobody can re-point another cook's version. In a batched write,
`get()` sees the stored state and `existsAfter()` the state after the batch, which is what makes
"only while deleting the parent" provable without a server.

## Acceptance criteria

- [ ] A new `isReparentAfterParentDelete()` joins the update rule: `verified()`; `changedKeys().hasOnly(['parentId', 'depth'])`; the stored `parentId` (the old parent P) is a string; `get(P).data.createdBy.uid == request.auth.uid`; `!existsAfter(P)`; `get(P).data.parentId` is a string (P is not an original) and equals the new `parentId`; new `depth == resource.data.depth - 1`. Comment it like the neighbouring functions.
- [ ] Notification create also accepts `type == 'moved'`, `message` a string of at most 200 chars (the deleted version's title), only when `recipeId` names the moved child, the recipient is that child's `createdBy.uid`, and `getAfter(child).data.parentId != get(child).data.parentId` (the move happens in this same batch, which the reparent rule above already restricts to the deleted version's owner). Other types unchanged; if RL-146 or RL-152 merged first, rebase onto their type list.
- [ ] Nothing else in the recipe rules changes; `hasBoundedContent` is not needed (content does not change).
- [ ] Emulator probe codes in Notes (batched REST commits): owner of P deletes P and re-points a child by another cook in one batch (200); the same update without deleting P (403); re-pointing to anything other than P's parent (403); changing `title` too (403); a third party doing it (403); P being an original (403); a `moved` notification in the reparent batch (200), the same notification without the move (403), addressed to someone other than the child's owner (403).
- [ ] `docs/data-model.md` rules paragraph, marked "in the repo, deployed by RL-160".
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
