## Context

RL-213 assumed kitchen id = uid. Now the id comes from `kitchens where memberUids
array-contains uid limit 1` (first one wins; with none, the user's own id). Member names and
avatars come from `profiles` (public).

## Acceptance criteria

- [ ] `useKitchen` resolves the kitchen id as above before subscribing, and exposes `members: { uid, name, avatar }[]`, `isOwner`, `createInvite()` (returns the `/join/<code>` URL; code from `crypto.getRandomValues`, 20 URL-safe characters), `joinKitchen(code)`, `leaveKitchen()`, `removeMember(uid)`.
- [ ] Errors: expired or missing invite "This invite has expired. Ask for a new one."; full "This kitchen is full."; generic failure copy.
- [ ] The erase script removes the user from any kitchen they are a member of and deletes kitchens and invites they own (a dry run lists the other members affected); export includes membership.
- [ ] Tests for each path.
- [ ] `docs/data-model.md`.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
