## Context

Written for the first version of the sync, which compared a local row's `updatedAt` with
the cloud doc's to keep an edit this device had not yet sent. Two writes made those values
disagree: the edit re-published the pre-edit `updatedAt`, and `addLocalCollaborator` bumped
`updatedAt` locally only.

## Acceptance criteria

- [ ] None. Dropped, see Notes.

## Out of scope

Everything; dropped.

## Verification

None.

## Notes

Dropped 2026-10-18 after the author's follow-up answers. Saves and edits are now cloud
first (RL-082, RL-083), so no device holds an edit the cloud lacks, and the sync (RL-076)
overwrites from every server snapshot with no timestamp comparison (last write wins). A
stale `updatedAt` in either store can no longer freeze or lose a change: the
`addLocalCollaborator` bump is overwritten by the snapshot the approval's `arrayUnion`
triggers, and RL-083 sets `updatedAt` on the cloud write itself.
