## Context

Spec (`docs/design/organic/export/App Spec.dc.html`, "Branch composer (6b)"): "Route
/recipe/:id/vary. One instruction, quick-change chips append to it. Grow shows a skeleton
card while generating, then opens What changed for the new branch." Markup: 6b in `Social
Auth and Generate.dc.html` and the `branch` block of `App Prototype.dc.html`.

Today `/recipe/:id/vary` is `RecipeChatPage` in variation mode: the parent preview, "How would
you like to modify this recipe?", `ChatInput` ("Describe the modification..."), then the chat
with a recipe card and "Save Variation". The seed from approving a suggestion
(`location.state.suggestion`, RL-017) prefills the composer. Saving opens the new recipe
page. This ticket changes the first screen only. After Grow the generation runs exactly as
sending the first message does today, and the result shows in the RL-111 chat with "Save
Variation"; saving still opens the recipe page. Opening "What changed" automatically after
Grow would skip the user's review and save, which is a behaviour change (author question).

Quick chips are static and generic, because the parent can be any dish: "Less sugar",
"Vegetarian", "Vegan", "Gluten-free", "Quicker", "Spicier" (groomer's choice; the design's
"Add chocolate" and "Warmer spices" were banana-bread specific). Tapping one appends its
lower-case label to the instruction, separated by ", " when the box already has text. That
join is a pure helper `appendClause(text, clause)` in `src/lib/utils.ts` with tests.

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`; neutral-700 text is `text-text-tertiary`. Light only. 44px targets.

Values to copy:

- Header: padding `12px 12px 0`, a flat `IconButton` with `X`, label "Close", running
  today's back.
- Body: padding `6px 22px 0`, column, gap 16px.
- Parent pill: `align-self: flex-start`, flex, gap 10px, padding `8px 14px 8px 8px`,
  `rounded-full bg-surface-secondary`, 13px: a 32px `bg-surface` circle with the parent's
  emoji (16px), then "Branching <b>parent title</b>". Tapping it expands today's parent
  preview below (keep that collapsible).
- Heading `h2` `font-heading` 30px, line-height 1.05: "What would you change?"
- Instruction: a textarea, min-height 110px, padding `14px 18px`, `border: 1.5px solid`
  accent, `rounded-[26px] bg-surface-secondary`, 16px, no resize, placeholder "e.g. less
  sugar, and add walnuts", visible label "What would you change?" (the heading can be the
  label). Prefilled from the suggestion seed.
- Chips: flex wrap, gap 8px; 36px pills `bg-accent-200 text-accent-900`, 14px, padding
  `0 14px` (44px hit area).
- Promise: flex, gap 10px, 13px `text-text-tertiary`, `ShieldCheck` icon: "<parent title>
  stays exactly as it is. Yours becomes a new version in its family, credited to you."
- Growing (after Grow, while the first generation runs): a card padding 16px,
  `rounded-[28px] bg-surface-secondary`, gap 10px: 13px 600 `text-accent-700` `Sparkles`
  "Growing your branch…", then three bars: 14px at 60% `bg-neutral-300`, 10px at 85% and
  10px at 70% `bg-neutral-200`, all `rounded-full`. `role="status"`.
- Footer: padding `12px 20px 28px` (plus safe area), a primary 54px full-width button, 16px,
  gap 8px, `GitBranchPlus`, "Grow this branch", disabled when the instruction is empty, while
  generating, or when the parent is unavailable.
- The parent loading, failed and missing notices from RL-111 replace the body when they
  apply, as today.
