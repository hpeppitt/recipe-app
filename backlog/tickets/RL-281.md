## Context

The flag is public profile data (privacy text: RL-283). The default is written at sign-up by
RL-282; this ticket shows it and lets the owner edit it. `country` is an ISO 3166-1 alpha-2
code, `null` when the user chose No flag, absent when never set. Helpers: RL-280. Sheets use
`components/ui/Sheet` (see `AvatarEditor` and `PantrySheet`).

### The design (the implementer has no other copy)

- The flag sits after the name in the 26px name row, at 20px, with `role="img"` and
  `aria-label` the country name ("Australia"). Nothing shows when `country` is null or absent.
- Own profile: the flag is a button "Change country, currently Australia"; with no flag, a
  text button "+ Add your country" (13px `text-accent-700`) sits in the "Cooking since" line.
- The sheet: heading "Where do you cook?" (Caprasimo 22px), a search field "Search
  countries", "No flag" first, then each country as a 52px row of flag and name, the current
  one with a `Check`. Tapping a row saves and closes; a failed save keeps the sheet open with
  "Couldn't save that. Try again.".
- Known limit: Windows shows flag emoji as two letters ("AU"). Accepted; no image set and no
  dependency.

## Acceptance criteria

- [ ] `UserProfile` has `country?: string | null`; `useOwnProfile` exposes `updateCountry(code | null)`, verified-only, which writes only codes passing `isCountryCode` or null.
- [ ] The flag shows on own and public profiles as designed, and not when null or absent.
- [ ] The sheet filters by name as you type, saves the choice or No flag, and returns focus to the trigger.
- [ ] Tests: display, change, No flag, search filter, failure, guest gets the sign-up dialog.
- [ ] `docs/capabilities.md` Profiles row.
- [ ] A `backlog/QA.md` entry: "Change your flag, choose No flag, check the public profile from another account. On Windows expect two letters."
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

The sign-up default (RL-282). Flags on recipe cards, author pills or anywhere else.

Component and page tests. Human: the QA.md walk on a phone and on a Windows browser.
