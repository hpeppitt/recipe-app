## Context

`isWellFormedReport()` (`firestore.rules` lines 214-231) allows `receivedAt` but never
checks it, on an unauthenticated write path whose other fields are carefully capped. Any
value up to the document limit is accepted, which is roughly 1 MB of free storage per
document. The beacon (`services/telemetry.ts`) always writes `receivedAt: serverTimestamp()`.
Related to RL-010 (TTL on `receivedAt`), which this does not replace.

## Acceptance criteria

- [x] `isWellFormedReport()` adds `&& (!('receivedAt' in d.keys()) || d.receivedAt == request.time)`.
- [x] `docs/data-model.md` clientErrors paragraph mentions it.

## Out of scope

The TTL policy (RL-010) and the deploy (RL-022).

## Verification

Emulator probes: a report with `serverTimestamp()` (allow), with a string `receivedAt`
(deny), with no `receivedAt` (allow). Trigger a handled error in `npm run dev:emulated` and
see the document land.
