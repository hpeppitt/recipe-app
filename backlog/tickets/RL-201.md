## Context

RL-197's Grow navigates to `/recipe/<id>/vary` with `state: { suggestion, fromCookId }`. When
that variation is saved, `setCookBranch(fromCookId, branchId)` (RL-196) records it. This is the
save path (`useRecipeChat.ts` ~355-395, cloud first, RL-082), hence tier hard: the cook update
must run only after the recipe save succeeded and must never fail the save.

## Acceptance criteria

- [ ] `RecipeChatPage` reads `fromCookId` from navigation state alongside `suggestion` and passes it to the hook.
- [ ] After a successful variation save, the hook calls `setCookBranch` fire-and-forget; a failure is reported as `cook-branch` and the save still completes and navigates.
- [ ] Only the first saved variation of that chat credits the cook (one `branchId` per cook, which the rules also enforce).
- [ ] Tests: credited after save, not on failure, failure does not block, only once.
- [ ] `docs/capabilities.md` Log a cook row mentions the credit.
- [ ] A `backlog/QA.md` entry: Needs a tweak with a note, Grow, Save Variation; the cook log shows Branched linking to the new branch.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Crediting branches grown later by hand.
