## Context

`BottomNav.tsx` lists `{ to: '/saved', label: 'Saved', icon: Bookmark }` in its five slots and
renders as the bottom bar below 1024px and the 220px rail above (RL-097, RL-115). `/saved` is
also a two-pane list origin (`ListOrigin = '/' | '/saved'` in `lib/paneMode.ts`, RL-116).
Routing and nav state, hence tier hard.

## Acceptance criteria

- [x] The slot reads Kitchen with `CookingPot`, links to `/kitchen`, and is current on `/kitchen`, `/kitchen/*` and `/saved`.
- [x] `/saved` keeps working (reached from Kitchen's Saved row) and stays a two-pane list origin.
- [x] One-time tip: the first time a returning user (one who has `recipe-lab-seen-saved` or any bookmark) opens the app after this ships, a small accent-200 bubble above the Kitchen slot (rail: beside it) says "Saved lives in Kitchen now" with a close button; it never shows again (`recipe-lab-kitchen-tip` in localStorage through `services/storage.ts`). New users never see it.
- [x] Tests: nav item, current state on the routes, tip once, not for new users.
- [x] `docs/capabilities.md` nav paragraph under Routes.
- [x] A `backlog/QA.md` entry: bottom bar at 390px and rail at 1280px show Kitchen; the tip appears once for an existing profile; Saved is reachable from Kitchen.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Kitchen's two-pane layout (RL-225).

## Verification

Tests. Human: the QA.md walk.

## Notes

- Returning user means any bookmark row in Dexie. `recipe-lab-seen-saved` is never written by the app, so it is not read (logged in DECISIONS.md). The check is async and the tip starts hidden, so nothing flashes; the flag is written on the first answer either way, so new users never see it later.
- `/saved` needed no `paneMode.ts` change: it is still a route and a list origin; the nav marks Kitchen current on it.
- The tip key lives in `services/storage.ts`, not `STORAGE_KEYS`, to stay inside the ticket's files.
- Release needs RL-227's kitchens rules deployed first or together (QA.md says so).
