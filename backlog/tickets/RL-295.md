## Context

The deploy runner (RL-296) and both workflows (RL-297, RL-298) share one ordering and
verification logic. This ticket is the pure part, testable in node with no network, like
`scripts/backlog.mjs` and `scripts/backlog.test.mjs` (Vitest already picks up
`scripts/*.test.mjs`).

The rules it encodes come from `docs/operations.md` ("Deploying", "The pending release
order", "A later Terms bump is the reverse", "Cache headers are load-bearing", "Security
headers"):

- Indexes always go first and must be READY before anything that queries them.
- Dev: indexes, wait for READY, rules, hosting. Always that order (author decision).
- Production: indexes, wait for READY, then either `rules-first` (rules, hosting) or
  `client-first` (hosting, rules). The default is rules first (author decision
  2026-10-22, matching RL-209, RL-227, RL-249, RL-261 and RL-291, which add collections the old
  client never touches). A Terms bump is always rules first. Client first happens only when a
  release asks for it explicitly, by a `deploy-order: client-first` tag line or a dispatch
  input, for releases that tighten rules an old client relies on.
- The rules literal `termsVersion()` in `firestore.rules` returns the current Terms version as
  a quoted string (`return '2026-10-22';`).
- After a deploy, the live ruleset must equal `firestore.rules` byte for byte, `/` and
  `/sw.js` must send `Cache-Control: no-cache`, an `/assets/` file must send
  `public, max-age=31536000, immutable`, every response must carry `X-Frame-Options: DENY` and
  `X-Content-Type-Options: nosniff`, and the entry script named in the live `index.html` must
  be the one in local `dist/index.html`.

## Acceptance criteria

`scripts/deploy-lib.mjs` exports, with no imports beyond node built-ins:

- [ ] `resolveTarget(arg, env)`: returns `'dev'` or `'prod'`; any other value, or none, is an
  error (there is no default target). `'prod'` is an error unless `env.GITHUB_ACTIONS ===
  'true'` and `env.DEPLOY_ENVIRONMENT === 'production'`, with a message saying production
  deploys only through the production workflow.
- [ ] `projectFor(target, firebaserc)`: the id under the `dev` or `prod` alias; an error if
  the alias is missing, or if the dev alias equals the prod alias.
- [ ] `termsVersionOf(rulesSource)`: the string `termsVersion()` returns, or null.
- [ ] `orderFromTagMessage(message)`: `'rules-first'` or `'client-first'` from a line
  `deploy-order: <value>` in an annotated tag message, else null.
- [ ] `resolveOrder({ input, tagMessage, liveRules, headRules })`: an explicit `input` of
  `rules-first` or `client-first` wins; then the tag message; then `rules-first` with reason "Terms
  version changed" when the two Terms versions differ; else `rules-first` with reason
  "default". Client first is never inferred. Returns `{ order, reason }` so the run can print
  why.
- [ ] `planSteps(target, order)`: the ordered step names. Dev is always
  `['indexes', 'wait-indexes', 'rules', 'hosting', 'verify']`; prod puts `rules` and
  `hosting` in the resolved order between `wait-indexes` and `verify`.
- [ ] `allIndexesReady(json)`: true when every index in a Firestore Admin API
  `collectionGroups/-/indexes` response has `state: 'READY'`; also returns the names still
  building.
- [ ] `rulesMatch(live, head)`: equal after normalising line endings only.
- [ ] `checkHeaders({ root, sw, asset })`: a list of problems against the header rules above;
  empty means pass. Header names compare case-insensitively.
- [ ] `entryScriptOf(html)`: the `/assets/...js` module script `src` in an `index.html`.
- [ ] `bundleTargets(text, expectedId, otherId)`: true only when the built bundle text
  contains the expected project id and not the other one, so a dev site built with production
  config (or the reverse) is refused before upload.
- [ ] `scripts/deploy-lib.test.mjs` covers each export, including: no target, `prod` outside
  CI, `prod` in CI without `DEPLOY_ENVIRONMENT`, a missing alias, dev equal to prod, each
  precedence level of `resolveOrder` (including no input and no tag line giving `rules-first`), a Terms bump detected, an index still `CREATING`, CRLF
  rules, a missing `nosniff`, `/sw.js` with a long cache, and a bundle holding both ids.
- [ ] `npm test` and `npm run lint` pass.
