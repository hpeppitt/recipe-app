## Context

Sign-in today is email link only (`services/firebase.ts`, `components/auth/AuthModal.tsx`,
`AuthSheetParts.tsx`; capabilities "Passwordless email sign-in"). Every cloud write needs
`email_verified` (RL-040) and contributing needs a current Terms acceptance recorded from the
box ticked on the email form (RL-047; docs/decisions.md "Email-link completion has a required
order of operations"). Google ID tokens carry `email_verified: true` for Google-managed
addresses, so the rules need no change. Enabling the provider is a Firebase console change and
the privacy policy must name Google as a sign-in processor, which needs the author (README
"What needs a human"). RL-188 to RL-191 are written for the recommendations.

## Questions and the groomer's recommendation

1. **Where**: a "Continue with Google" button above "Continue with email" in the sign-in sheet
   (5a) and the sign-up call to action, not on the cross-device prompt (recommended).
2. **Terms**: the same Terms box must be ticked before the Google button is enabled; the
   acceptance is recorded after the popup returns, through the existing `checkTerms` path
   (recommended).
3. **Popup or redirect**: `signInWithPopup`, falling back to `signInWithRedirect` when the popup
   is blocked or in an installed PWA on iOS (recommended).
4. **Anonymous upgrade**: `linkWithPopup` keeps the uid and bookmarks, like the email upgrade
   (recommended).
5. **Address already has an account** (`auth/credential-already-in-use` or
   `account-exists-with-different-credential`): sign in to that account with the Google
   credential and run the existing local carry-over (`runMigration`), the same outcome as the
   email "already has an account" path (recommended). Firebase's one-account-per-email setting
   stays on.
6. **Unverified Google addresses** (rare non-Google-managed): the rules deny writes; show the
   existing "confirm your email" sheet (recommended).
7. **Console**: enable Google, set the OAuth consent screen app name "Recipe Lab", support
   email, authorised domains (the Hosting domains and localhost). Done by the author in RL-191.
8. **Privacy policy**: add Google as a sign-in provider (name, email, profile photo URL received;
   only name and email used), drafted in RL-190, signed off by the author before release.
9. **Apple**: stays out, as the roadmap says.
