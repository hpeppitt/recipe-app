## Context

`ActivityPage.tsx` rows show `<b>who</b> verb <b>recipe</b>` and a detail line with the
notification `message` in quotes and the time (~84). After RL-147 a structured suggestion's
notification message is already the one-line change (`describeEdits`, e.g. "150 g light brown
sugar → 100 g and 1 more"). The design's sub-line is "<first name>: <change> · <time>" with no
quotes, so the owner can triage without opening it.

## Acceptance criteria

- [x] For `suggestion` notifications the detail line reads "<first name of fromDisplayName>: <message>" (no quotes), then the time; for `suggestion_applied` and `suggestion_branched` it reads the message without a name; other types keep today's quoted message.
- [x] The detail line stays one line with truncation; the full text is in the row's accessible description.
- [x] Old suggestion notifications (free text) render in the new format too; nothing is migrated.
- [x] Tests for each of the three formats.
- [x] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Filter chips and day headers (RL-154), branch notifications (RL-153), the verbs (RL-148).

Gates: tests, `ui-reviewer`. Human: after RL-147, send a suggestion from a second account and
