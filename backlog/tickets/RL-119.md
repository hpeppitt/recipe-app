## Context

RL-118 makes `useRecipeChat.sendMessage(text, images?)` send up to three downscaled photos to
Gemini and returns `attachmentPreviews` for the transcript. This ticket makes it reachable:
an attach button and removable thumbnails in `ChatInput`, and thumbnails in the user bubble.
It serves both `/create` and `/recipe/:id/vary`, since both render `RecipeChatPage`.

Photos are generation input only and are never stored (see RL-118 and
[docs/decisions.md](../../docs/decisions.md) decision 3). The thumbnails live in component and
hook state only. On leaving the page they are gone; a saved recipe shows no photo.

The validation, the copy and the downscale come from RL-118: `validateImageFile`,
`attachmentErrorMessage`, `ACCEPTED_IMAGE_TYPES`, `MAX_IMAGES_PER_MESSAGE` and
`MAX_IMAGES_PER_CHAT` in `src/lib/imageAttachments.ts`, and `downscaleToJpeg` in
`src/services/imageDownscale.ts`. Do not restate limits in the component.

**RL-111 (the Organic Chat 6a restyle, draft) is not a dependency.** It restyles `ChatInput`
into a 52px pill. Whichever of the two lands second rebases onto the other: if RL-111 is on
`main`, put the attach button inside its pill as the first child and change the pill's
left padding from 18px to 6px; if not, put the button left of today's textarea. The values
below are in the Organic tokens either way, so nothing is restyled twice.

**Tokens and values** (light only; 44px targets; Lucide icons at stroke 2.75 per RL-064):

- Attach button: 40px round, flat (`bg-transparent`, `text-text-secondary`), `ImagePlus` icon
  20px (add the Lucide `image-plus` path to `src/components/ui/icons.tsx`), `aria-label="Add
  photos"`, hit area at least 44px. It opens a hidden `<input type="file" multiple
  accept="image/jpeg,image/png,image/webp">` (no `capture` attribute, so phones offer both
  camera and library). Disabled when the composer is disabled or when
  `MAX_IMAGES_PER_MESSAGE` photos are already attached.
- Thumbnail tray: shown only when at least one photo is attached, directly above the
  composer, padding `0 16px 8px`, flex row, gap 8px. Each thumbnail: 56px square,
  `rounded-[16px]`, `object-cover`, `alt="Attached photo 1 of 2"` (n of total). A remove
  button overlaps the top right corner: 28px visible circle `bg-surface-secondary
  text-text-primary shadow-sm` with `X` 14px, hit area 44px, `aria-label="Remove photo 1"`.
  While a photo is downscaling, its slot shows the existing `Spinner` at 20px with
  `aria-label="Preparing photo"`.
- Privacy notice (author's decision 2026-10-19, wording in RL-120's voice): one line shown
  whenever the tray is visible, above the thumbnails, so it is on screen before any photo is
  sent: 12px `text-text-tertiary`, padding `0 16px 6px`, exactly "Photos are sent to Google's
  Gemini to write your recipe and are not saved. Leave out people and personal details." Not
  a link (leaving the chat would discard an unsaved recipe). Hidden when no photo is attached.
- Error line: under the tray, 13px `text-accent-900`, `role="alert"`, the
  `attachmentErrorMessage` copy; cleared on the next successful add or on send.
- User bubble (`ChatMessage.tsx`): when the hook's `attachmentPreviews[message.timestamp]` has
  entries, a row of 64px square `rounded-[16px]` thumbnails sits above the text inside the
  bubble, gap 6px, `alt="Your photo 1"` and so on. A photos-only send shows the
  `IMAGE_ONLY_PROMPT` text under them, as stored.

## Acceptance criteria

- [x] `ChatInput` takes `onSend: (message: string, images: ImageAttachment[]) => void`; the page passes the hook's `sendMessage`. Callers that pass a text-only handler still type-check (images is always an array, possibly empty).
- [x] Choosing files runs `validateImageFile` per file in order, with the counts of photos already in the tray and already sent in this chat (a new `sentImageCount` prop, which the page computes as `Object.values(attachmentPreviews).flat().length`). Valid files are downscaled with `downscaleToJpeg`; invalid ones and failed downscales show their `attachmentErrorMessage` and are not added. Valid files in the same pick are still added when another fails.
- [x] The file input's value is reset after each pick, so choosing the same file again after removing it works.
- [x] Send is enabled when there is trimmed text or at least one ready photo, and disabled while any photo is still downscaling. Enter sends as today. After send, the text and the tray clear.
- [x] Each thumbnail has a remove button that removes only that photo and moves focus to the next remove button, or to the attach button if none is left.
- [x] Labels: attach "Add photos", remove "Remove photo n", thumbnails "Attached photo n of m", bubble photos "Your photo n". All interactive targets are at least 44px and reachable by keyboard with a visible focus ring.
- [x] Errors: wrong type, too large, over the per-message or per-chat limit and unreadable each show their RL-118 copy in the `role="alert"` line. Offline and rate limited sends show the existing `describeGenerationError` box with Try again, and Try again resends the photos (RL-118).
- [x] The user bubble shows the sent photos from `attachmentPreviews`; the saved recipe page shows no photo, and its stored `chatHistory` has text only (spot-check with `data-integrity-reviewer`).
- [x] With no photos attached, the composer and the whole chat behave exactly as before, including the `initialValue` seed on the variation flow and the coarse-pointer autofocus rule.
- [x] `src/components/chat/ChatInput.test.tsx` (new, mock `downscaleToJpeg`): a valid pick shows a thumbnail with its alt text; a `image/gif` pick shows "Use a JPEG, PNG or WebP photo."; the fourth pick shows the per-message message and the attach button is disabled at three; remove deletes the right thumbnail; send passes the text and the images and clears both; photos-only send is allowed; text-only send passes an empty array; the privacy notice is shown only while a photo is attached.
- [x] `docs/capabilities.md`: the "Photos as generation input" row becomes `shipped`, naming `ChatInput.tsx` and RL-118/RL-119, and says photos are never stored.
- [x] The privacy notice above shows with one or more photos attached and is absent with none; its text matches exactly.
- [x] A `backlog/QA.md` entry for the walk below, plus "release together with RL-120's Privacy Policy change, after the author has signed off that wording".
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Verification

`npm test`, `npm run lint`, `npm run build`; `ui-reviewer` for targets, labels, focus and
contrast; `data-integrity-reviewer` for the saved `chatHistory`.

Human, on the preview (generation needs App Check), as a verified user at 390x844:

- iOS Safari: Add photos offers camera and library; take a photo of a printed recipe; a HEIC
  library photo arrives as JPEG and is accepted; the recipe returned follows the printed one.
- Android Chrome: three photos of a fridge, no text; a recipe comes back using what is visible;
  the bubble shows three photos and "Suggest a recipe based on these photos."
- A fourth photo is refused with the limit message; a 25 MB file and a GIF are refused.
- Remove a thumbnail, then add the same file again.
- On a variation (`/recipe/:id/vary`), send the first message in the Grow this branch screen (it has no attach button), then attach a dish photo in the follow-up message and ask to make it like that.
- Go offline, send with a photo, see the connection error, come back online, Try again: the
  photo is resent and a recipe arrives.
- Save, open the recipe: no photo anywhere; in devtools, the Dexie row's `chatHistory` and the
  Firestore document contain no `data:image` or long base64.
- Text-only create and refine still work as before.
- With VoiceOver: the attach button, thumbnails and remove buttons announce as labelled.
- The privacy notice appears above the first thumbnail and disappears when the last one is removed; at 320px it wraps without pushing the composer off screen.

## Notes

Privacy wording decided by the author at /groom on 2026-10-19: a Privacy Policy edit (RL-120,
now a dependency) plus the composer notice above, with no Terms change. The earlier blocker
("not releasable until the author decides on the privacy wording") is replaced by that
dependency. RL-120's wording still needs the author's sign-off before `/release`.

Implementation (2026-10-19): RL-111 and RL-112 were already on `main`. The attach button is the first child of the RL-111 pill (left padding 6px). `BranchComposer`, the first screen of a variation, is RL-112's and has no attach button, so on a variation photos are only available from the follow-up message; whether it should take photos is an open author question, logged in `backlog/DECISIONS.md`.

`ChatInput.onSend` may return the hook's promise: on `'message-limit'` or `'chat-limit'` the text and photos are put back and the copy shows in the alert line. The composer clears at once on send, as before, and restores on that result. A pick clears the previous error before showing its own. `Spinner` gained a `label` prop and an `icon` (20px) size. The existing assertion `onSend('hello')` became `onSend('hello', [])` because images is always an array.

jsdom tests cover behaviour only; hit areas, layout at 320px, focus rings and real decoding need the browser walk in QA.md.
