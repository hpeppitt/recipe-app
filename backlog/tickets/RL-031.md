## Context

Every function in `services/storage.ts` (lines 7-123) touches `localStorage` directly.
Where storage is blocked (some privacy modes, cookie-blocking settings) the access itself
throws `SecurityError`, and several of these run during auth start-up in `AuthContext`.
`getPreviousUids` returns whatever `JSON.parse` produced, so a corrupt non-array value makes
`addPreviousUid` throw on `.includes`. `lib/onboarding.ts` (`parseIntroState`) and
`getStrandedIdentity` in this file show the tolerant pattern.

## Acceptance criteria

- [ ] Every read in `storage.ts` is wrapped so a throw returns the documented default (`'system'`, `'original'`, `null`, `[]`, the empty intro state).
- [ ] Every write and remove is wrapped so a throw is swallowed after `console.warn`; no write throws to the caller.
- [ ] `getDeviceId` still returns a fresh id when storage is blocked (not persisted).
- [ ] `getPreviousUids` returns `[]` unless the parsed value is an array, and keeps only string entries.
- [ ] `getTheme` and `getUnitSystem` return the default for a stored value outside their allowed set.
- [ ] `src/services/storage.test.ts` stubs `globalThis.localStorage` and covers: a store whose every method throws, a corrupt JSON value, a non-array previous-uids value, and the normal round trip.

## Out of scope

Moving to another storage mechanism, and storage use outside this file.
