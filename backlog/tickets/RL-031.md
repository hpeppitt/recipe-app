## Context

Every function in `services/storage.ts` (lines 7-123) touches `localStorage` directly.
Where storage is blocked (some privacy modes, cookie-blocking settings) the access itself
throws `SecurityError`, and several of these run during auth start-up in `AuthContext`.
`getPreviousUids` returns whatever `JSON.parse` produced, so a corrupt non-array value makes
`addPreviousUid` throw on `.includes`. `lib/onboarding.ts` (`parseIntroState`) and
`getStrandedIdentity` in this file show the tolerant pattern.

## Acceptance criteria

- [x] Every read in `storage.ts` is wrapped so a throw returns the documented default (`'system'`, `'original'`, `null`, `[]`, the empty intro state).
- [x] Every write and remove is wrapped so a throw is swallowed after `console.warn`; no write throws to the caller.
- [x] `getDeviceId` still returns a fresh id when storage is blocked (not persisted).
- [x] `getPreviousUids` returns `[]` unless the parsed value is an array, and keeps only string entries.
- [x] `getTheme` and `getUnitSystem` return the default for a stored value outside their allowed set.
- [x] `src/services/storage.test.ts` stubs `globalThis.localStorage` and covers: a store whose every method throws, a corrupt JSON value, a non-array previous-uids value, and the normal round trip.

## Out of scope

Moving to another storage mechanism, and storage use outside this file.

## Notes

- Private `safeGet`/`safeSet`/`safeRemove` wrap every access, so a throwing `localStorage` getter is caught too. Writes warn naming the key.
- `getDeviceId` caches a generated id in module memory (one stable id per session when storage is blocked); it is only written to storage when storage works.
- Theme and unit system are validated against their allowed sets. `previous-uids` keeps only strings; it has no cap, as before.
- Outside this file, `src/services/firebase.ts` lines 109, 225, 230 use `localStorage` directly and can throw.
- Legacy values: `git log -S` on the hooks, `storage.ts` and `units.ts` shows theme typed `'system' | 'light' | 'dark'` since the first commit (1a12cbb) and `UnitSystem` typed `'original' | 'metric' | 'imperial'` since its introduction (e33aae8). No value outside the current sets was ever written, so no stored legacy value changes behaviour. Nothing decided.
- `getDeviceId` id generation falls back from `randomUUID` (secure contexts only) to `getRandomValues` hex to `Math.random`; nothing parses the id.
