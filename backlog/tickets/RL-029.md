## Context

- `useOwnRecipes` (`hooks/useUserRecipes.ts` lines 10-44) calls `getRecipeStats`
  (`services/firestore.ts` around line 756), which does one `getDoc` per local recipe. The
  same numbers come back from one `getUserRecipes(uid)` query, since publishing requires
  `createdBy.uid == auth.uid`.
- `getFollowingProfiles` (around line 706) re-runs the follows query that
  `useFollowingList` already ran via `getFollowingIds`, then fetches profiles one at a time
  in a `for ... await` loop.

RL-026 edits the same hooks for cancellation, so this lands after it.

## Acceptance criteria

- [x] `useOwnRecipes` builds its stats map from a single `getUserRecipes(uid)` call; `getRecipeStats` is removed if it has no other caller.
- [x] `getFollowingProfiles` takes the list of ids rather than a uid, fetches profiles with `Promise.all`, and preserves the input order.
- [x] `useFollowingList` runs `getFollowingIds` once and passes the result to `getFollowingProfiles`.
- [x] The own-profile totals and per-recipe counts are unchanged for recipes the user has published, and zero for unpublished ones, as now.

## Out of scope

Caching, and anything about the follower list.

## Verification

`npm test`, `npm run build`. Human QA in `backlog/QA.md`: own profile shows the same view and
favourite totals as before on the preview build.

## Notes

- Equivalence checked: `getUserRecipes` has no `limit`, `orderBy` or paging (one `where('createdBy.uid', '==', uid)` query, sorted client-side), and includes variations, so there is no cap on totals. Counts use `|| 0` exactly as `getRecipeStats` did. Unpublished local recipes are absent from the map and render zero. Edge: a local recipe whose cloud doc has a different `createdBy.uid` would now read zero (the old per-id read would have found it); none expected.
- `getRecipeStats` had no other caller and is removed. The stats fetch still swallows errors silently, as before.
- `getFollowingProfiles(ids)`: missing profile is skipped, as before. Failure behaviour unchanged: the old sequential loop rejected on any failed read, so `Promise.all` (not allSettled) is kept.
- `useFollowingList` keeps stamping, cancelled flag, reportError and derived loading; it chains `getFollowingIds` then `getFollowingProfiles(ids)`.
- Tests: `firestore.profiles.test.ts`, `useOwnRecipes.test.tsx`, plus a new describe appended to `useFollow.test.tsx`. No existing assertion changed; the stale `getRecipeStats` key in the `useUserRecipes.test.tsx` mock is harmless and left.
