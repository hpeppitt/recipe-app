## Context

The 1c Pantry sheet (RL-169) filters recipes to those that use every listed ingredient, with a
time limit, and offers to write a new recipe with the same constraints. `searchLibrary` in
`src/lib/library.ts` (RL-123) already matches query words against ingredient names; this adds
the pantry rule beside it. Pure logic, so it lands first with tests (CLAUDE.md convention).

## Acceptance criteria

- [x] `PANTRY_TIMES = [{ id: '15', label: '15 min', max: 15 }, { id: '30', label: '30 min', max: 30 }, { id: '60', label: '1 hr', max: 60 }, { id: 'any', label: 'Any', max: null }]` exported from `src/lib/library.ts`.
- [x] `normalizePantryItem(s)` trims, lower-cases and collapses spaces; empty strings are dropped; duplicates are removed by `pantryItems(list)`.
- [x] `matchesPantry(recipe, items, maxMinutes)` is true when every item is a substring of at least one ingredient name (case-insensitive, same matching as `searchLibrary`), and `totalTime <= maxMinutes` when a limit is set. No items means every recipe matches the time rule only.
- [x] `filterPantry(results, items, timeId)` applies it to `searchLibrary` output, keeping branches (the sheet shows originals and branches).
- [x] `buildPantryPrompt(items, timeId)` in `src/lib/createPrompt.ts` returns "Something with eggs, tomatoes and feta" (Oxford-free list: commas, then "and" before the last), plus " in under 30 minutes" / " in under an hour" for a limit, and "Something with what I have" for no items.
- [x] Tests cover substring matching ("egg" matches "eggs"), every-item semantics, time limits, normalisation, and the prompt's 0, 1, 2 and 3 item forms.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

The sheet and its entry points (RL-169, RL-170). Stemming or synonyms ("rice" still matches "licorice", the documented Search limit).

## Verification

Unit tests only.
