## Context

Ingredient rows tick through hidden checkboxes (`IngredientList.tsx`, RL-102), not persisted.
Cook mode is a route so Back closes it naturally (tier hard: routing). The Screen Wake Lock API
(`navigator.wakeLock.request('screen')`) is a platform feature, no dependency; it is released
when the tab hides and must be re-requested on `visibilitychange`. Hands-free (voice, gestures)
is "Not on the roadmap". The scale chosen on the recipe page should carry over through
navigation state.

### The design (the implementer has no other copy)

- **Offer**: when the first ingredient is ticked on a recipe page, a slim bar slides in above the
  footer for 8 seconds or until dismissed: `bg-accent-2-100`, 22px radius, `ChefHat`, 14px "Start
  cooking? Steps one at a time, screen stays on." and a 36px primary pill "Start cooking". Once
  per recipe visit.
- **Cook mode page** (outside `AppShell`, full height, ground background): top row with a 44px
  close (`X`, "Close cook mode") and 13px `neutral-700` "Step 3 of 8"; a 6px progress bar
  (`bg-neutral-200` track, `accent` fill). The step text in 24px body font (Figtree), line-height
  1.4, padded 24px, scrolling if long. Under it, a collapsible "Ingredients" (closed by default)
  listing the scaled ingredients. Footer: two 56px buttons, "Back" (secondary) and "Next step"
  (primary); on the last step the primary reads "Done" and opens `CookedSheet`.
- Swipe left and right also move steps; arrow keys too. The step region is `aria-live="polite"`.
- If wake lock is unavailable or refused, a 12px line says "Your screen may still dim."

## Acceptance criteria

- [x] Route `/recipe/:id/cook`, lazy; reads the recipe like the recipe page (`useRecipe`) and the scale from `location.state.servings` (default stored servings).
- [x] `useWakeLock(active)` requests and releases the lock, re-requests on visibility, and reports support.
- [x] Done opens `CookedSheet` for verified users and the sign-in sheet otherwise; saving returns to the recipe.
- [x] Respects `prefers-reduced-motion` (no slide animations).
- [x] Tests: step navigation, last step Done, wake lock mocked request and release, offer shown once.
- [x] `docs/capabilities.md` gains a Cook mode row and the route.
- [x] A `backlog/QA.md` entry: on a real phone, tick an ingredient, Start cooking, leave the phone for two minutes: the screen stays on; switch apps and back: still on; swipe through steps; Done opens the sheet.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Voice or gesture control. Timers.

## Notes

- Entry: `IngredientList` gained `onTick` (fires on a tick, not an untick); `RecipeContent` forwards it as `onIngredientTicked(servings)` with the servings shown at that moment, so the latest tick's servings are what Start cooking passes. `useCookedEntry` gained an optional `onSaved`.
- Saving a cook from cook mode replaces the cook route with `/recipe/:id` (not Back), because Grow it into a branch pushes `/vary` straight after the save. The replace carries `state: { cooked: true }` and the recipe page shows its own "Saved to your cook log" toast, since the sheet's toast unmounts with cook mode.
- Close, and Done on an unpublished recipe, go Back when cook mode was opened from the recipe page, else replace with the recipe.
- The offer bar sits at `bottom: 96px + safe area`, measured in Chromium at 320, 360, 390 and 768px (light and dark): 4px clear of the 92px footer when scrolled to the bottom, nothing clipped; below about 500px the pill drops under the text.
- Slide-in is a new `offer-in` keyframe in `src/index.css`, used under `motion-safe` only. The step change has no animation.
- Review fixes: step scroll resets per step; offer timer pauses on hover or focus, the bar is `role="status"` and Escape dismisses it; Back at step 0 is `aria-disabled`; edge swipes (24px) and modified arrow keys are ignored; swipe handlers cover the whole scroll area; the Start cooking pill is 36px inside a 44px button; the live region carries an sr-only "Step N of M"; the step region takes focus once on open.
