## Context

21a in `docs/design/organic/export/Recipe Parts and System.dc.html`: "Classic master-detail:
selecting in the list replaces the right pane without a navigation. Ingredients and method sit
side by side on wide screens. Works for Explore, Saved and Activity alike." Grid in the
design: `220px 420px 1fr`, the recipe pane padding `36px 48px 0`, max-width 720px.

Routing constraints (`docs/architecture.md`, Routing; `docs/decisions.md`, rejected
`createBrowserRouter`): plain `BrowserRouter` with `<Routes>`. The selected recipe must still
be in the URL so a reload, Back and a shared link work; "without a navigation" means the list
pane stays mounted and scrolled, not that the URL stays still. A workable shape, which the
implementer may improve: at `lg` and up, when the location is `/recipe/:id` and the previous
shell location was `/` or `/saved`, render the shell with the list pane (that page in a 420px
column) and `RecipeDetailPage` in the third column; otherwise render as today. Store the list
origin in navigation `state`, so a direct visit to `/recipe/:id` on a wide screen shows the
recipe alone (centred) rather than guessing a list. Below 1024px nothing changes.

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`; `--color-divider` is `border-border`. Light only. 44px targets.

Values to copy:

- List pane: 420px, padding `28px 20px 0`, column, gap 12px, its own scroll, right rule
  `box-shadow: 1px 0 0` of the divider. The selected row gets `bg-accent-100` and an inset
  `0 0 0 2px` accent ring and `aria-current="true"`.
- Recipe pane: padding `36px 48px 0`, max-width 720px, own scroll. Title `font-heading`
  44px beside a 96px `EmojiBlob` (add 96 to its sizes). At this width ingredients and method
  sit side by side: a grid `1fr 1.4fr`, gap 36px. The footer actions become an inline row
  (gap 10px, 48px buttons): "Family" secondary with `Network` to the tree, Suggest or Edit
  secondary, "Branch this recipe" primary.
- Activity on wide screens stays a single column (its rows navigate to recipes and profiles).

## Acceptance criteria

- [ ] At 1024px and wider, opening a recipe from Explore or Saved shows the list pane and the recipe pane together; the URL is `/recipe/:id`; Back returns to the list with its scroll kept; choosing another row swaps the recipe pane.
- [ ] A direct visit or reload of `/recipe/:id` on a wide screen shows the recipe pane alone, centred; below 1024px every route behaves exactly as before.
- [ ] Only one `h1` per view (the recipe title when a recipe is selected; the list heading is demoted to `h2` in the pane).
- [ ] Tests cover the routing decision (a pure helper deciding pane mode from location, state and width, unit tested in `src/lib`) and that the mobile path is unchanged.
- [ ] `docs/architecture.md` Routing section describes the wide-screen pane mode.
- [ ] A `backlog/QA.md` entry: at 1280x800 browse Explore and Saved, select several recipes, Back and Forward, reload on a recipe, resize across 1024px; at 390px nothing changed.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
