## Context

Written for RL-228's recommendations. Inputs: the user's cooks (RL-195 `Cook`) joined to their
recipes' tags and titles, and the user's own branches' `prompt`s. Branch phrases can reuse
`promptMatchesChip` synonyms from RL-177 for the common ones.

## Acceptance criteria

- [x] `learnTaste({ cookedRecipes, branchPrompts, hidden })` returns `{ cookALot: string[] (<= 5), tendToChange: string[] (<= 5), cookCount, branchCount }`: cookALot from the most frequent normalised tags and a small dish-word list (noodles, baking, eggs, curry, soup, salad, pasta, bread...) across cooked recipes, needing at least 2 occurrences; tendToChange from branch prompts grouped by `BRANCH_CHIPS` synonyms plus "shorter bake"/"quicker", "more greens", needing at least 2; anything in `hidden` removed.
- [x] `tasteHeadline(cookCount, branchCount)` returns "Learned from 14 cooks and 6 branches." with singulars, and "Cook and branch a few recipes and this fills in." at 0 and 0.
- [x] Terms are sentence case ("Noodles", "Less sugar").
- [x] Tests for thresholds, hidden, ties (by most recent), headline forms.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Notes
`src/lib/taste.ts` exports `learnTaste` and `tasteHeadline`. Recency input is explicit: each cooked recipe and branch prompt carries `at` (epoch ms), used only to break count ties, then A to Z. A term counts once per recipe or prompt. Hidden match is case-insensitive. Dish words are matched as whole title words. Branch groups reuse `promptMatchesChip` over `BRANCH_CHIPS` plus "Shorter bake" and "More greens". Nothing is stored or sent (decisions.md, RL-228).
