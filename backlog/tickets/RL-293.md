## Context

The dev workflow (RL-297) and the production workflow (RL-298) deploy with a service account
key held as a GitHub **Environment** secret, and build the client from that Environment's
variables. Environment-scoped secrets are only handed to a job that names the Environment, and
the `production` Environment only releases a job after the author approves it. That approval
plus a production key that exists nowhere else is the guardrail "nothing deploys to prod
without approval".

Today there is one repository-level secret `FIREBASE_SERVICE_ACCOUNT` (Hosting Admin on
production, used by `.github/workflows/preview.yml`) and repository-level `VITE_*` variables
holding production values (`docs/operations.md`, "Preview deploys"). Leave them in place
until RL-299 retires `preview.yml`; RL-303 deletes them. While both exist, an Environment
value overrides a repository value of the same name inside a job that names the Environment.

The repo is public, so Environment protection rules are available without a paid plan.

`recipe-lab-3832b`.

**A. Deploy service account (per project)**
- [ ] console.cloud.google.com, select the project, IAM & Admin, Service Accounts, Create

- [ ] Grant exactly these roles, then Done:
  - Firebase Hosting Admin
  - Firebase Rules Admin
  - Cloud Datastore Index Admin
  - Firebase Viewer (the CLI reads the project)
  - Service Usage Consumer (the CLI checks the APIs are enabled)
- [ ] Open the account, Keys, Add key, Create new key, JSON. The file downloads. Keep it
  outside the repo; it is pasted in section B and then deleted.
- [ ] If a later run fails naming a missing permission, add only the one role that grants it
  and write the role in Notes. Do not grant Editor or Owner.

**B. GitHub Environment `dev`**
- [ ] github.com/hpeppitt/recipe-app, Settings, Environments, New environment, `dev`.
- [ ] Deployment branches and tags: Selected branches and tags, add branch rule `main`.
- [ ] No required reviewers.
- [ ] Environment secret `FIREBASE_SERVICE_ACCOUNT`: paste the whole dev JSON key.
- [ ] Environment variables, from RL-292's private note: `VITE_FIREBASE_API_KEY`,
  `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID` (`<dev-id>`),

  `VITE_ENABLE_GOOGLE_SIGNIN` = `true` only if Google was enabled on dev. Leave
  `VITE_POSTHOG_KEY` and `VITE_POSTHOG_HOST` unset on dev.
- [ ] Delete the downloaded dev key file.

**C. GitHub Environment `production`**
- [ ] New environment, `production`.
- [ ] Required reviewers: tick it and add `hpeppitt`. Leave "Prevent self-reviews" **unticked**

  protection rules", so the approval cannot be skipped.

  from any branch, including `main`, is then refused before it can read the secret.
- [ ] Environment secret `FIREBASE_SERVICE_ACCOUNT`: paste the whole production JSON key.
- [ ] Environment variables with the production values (the same as today's repository
