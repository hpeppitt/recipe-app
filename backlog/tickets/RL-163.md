## Context

Written for RL-161's recommended answers 1 and 3. RL-162 stores `relatedFamilyId` on the new
original only. The other side finds cousins with `where('relatedFamilyId', '==', rootId)` on
`recipes` (public read, single-field equality, no composite index), limit 3. Family sizes come
from `getPublishedRecipeTree(rootId)` or the counts the feed already uses.

### Design (7d)

Card: accent-2-100, radius 28px, padding 16px, gap 10px. Eyebrow row: link icon, "Related
family", 12px semibold accent-2-800. Then a row: 44px ground circle with the family's emoji
(22px), title bold, under it a `UserPill` for the family's author and "<N> versions" (12px
accent-2-800), chevron-right; the whole row links to that recipe (44px min). Under the card on
the new original's side only: 13px accent-2-900 line "Shown on both recipes, so people browsing
either one find the other." is design commentary, not UI; do not render it.

## Acceptance criteria

- [x] On a recipe with `relatedFamilyId`, the card shows that family's original (read it with `getPublishedRecipe`); hidden while loading or if it no longer exists.
- [x] On an original, the card lists up to 3 recipes whose `relatedFamilyId` is this id, newest first, each as a row; hidden when none or offline.
- [x] The card sits below the metadata pills and above the ingredients; it carries the list origin on its links.
- [x] The query runs once per recipe view (no listener), with a 5 s bound, errors swallowed and reported once with `reportError('related-families')`.
- [x] Tests: both sides render, the empty and error cases render nothing, link targets.
- [x] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

The Move line (RL-164). Any index or rules change.

## Verification

Gates: tests, `ui-reviewer`. Human on the emulator after RL-162's walk: the new original shows
the matched family; the matched original shows the new one; both links work at 390 and 320px.

## Notes
Slot `afterMeta` added to RecipeContent so the card sits between the pills and ingredients. Newest-first uses limit(20) then a client sort, because orderBy with the equality would need a composite index (out of scope); no index or rules change. Versions per row come from `getPublishedRecipeTree` (one read per row, max 4 reads). Not verified in a browser.
