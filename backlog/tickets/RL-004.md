## Context

`RecipeContent.tsx` reads `.length` on `ingredients` and `instructions` without a guard,
so a cloud document missing either array throws during render and the page goes blank.
No error boundary exists anywhere above it. `publishRecipe` always writes complete
documents, so no real recipe triggers this today; the point is blast radius versus a
few characters of fix.

## Acceptance criteria

- [x] `RecipeContent` renders a recipe whose `ingredients` or `instructions` is missing or not an array, showing the sections it can and an inline notice for the ones it cannot.
- [x] A top-level `ErrorBoundary` component in `src/components/ui/` wraps the route outlet in `App.tsx`, rendering an `EmptyState` with a "Back to library" action and reporting the error through `services/telemetry.ts`.
- [x] A test under `src/lib` or a component test (if RL-002 has landed) covers the malformed-document path.

## Out of scope

Validating cloud documents against the Zod schema on read. That is a data-layer decision for a separate ticket.

## Verification

`npm test` with the new case. Human QA: none needed beyond the standing walk.

## Notes

RecipeContent guards ingredients, instructions, notes and tags with Array.isArray and shows an inline notice for the first two. RouteErrorBoundary wraps Routes in App.tsx and the Outlet in AppShell so the nav survives a shell-page error. Component tests cover both paths.
