## Context

`.github/workflows/preview.yml` deploys `main` to the Hosting channel `qa` of
`recipe-lab-3832b`, so QA runs on the production Auth and Firestore and QA data is real data
(`docs/operations.md`, "Preview deploys", Warnings). The author decided dev replaces it: after
RL-297, `https://<dev-id>.web.app` always serves the last green `main`, against dev data and
dev rules.

The process docs still describe the old model: `/qa-pass` triggers `preview.yml`
(`.claude/skills/qa-pass/SKILL.md` step 2); `docs/agent-workflow.md` ("QA before live",
"It cannot deploy") says the only automatic deploy is the preview channel and live deploys are
`/release`; `backlog/README.md` ("What needs a human") lists "Deploying `firestore.rules` or
`firestore.indexes.json` to production" and "Deploying to live" as human work done by hand.
Deploy tickets so far (RL-022 to RL-291) were written as "deploy X to production"; from now on
the human part of such a ticket is approving the production run and walking the live checks.
