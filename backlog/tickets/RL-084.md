## Context

Author answer of 2026-10-18 (decision 1b, RL-076): My Recipes is split into Created
(recipes the user authored from scratch) and Branched (the user's own variations, including
variations of other people's recipes), and never lists other people's recipes, which appear
only under Saved. The tab split itself belongs to the Organic rebrand (RL-062 to RL-075, on
another branch); its tab ticket should depend on this one. This ticket only makes the data
right, so the rebrand reads it rather than re-deriving ownership.

Today `buildFeed` in `src/lib/library.ts` lists roots only (`if (r.parentId) continue`),
so the user's own variation of someone else's recipe, whose root is not theirs, is never
listed anywhere in My Recipes. Ownership elsewhere is `canManageRecipe`
(`src/lib/ownership.ts`), which treats every row as the user's own when Firebase is not
configured. Saved copies from share links keep their original author's `createdBy`
(`handleSaveCopy` in `src/pages/SharedRecipePage.tsx`). Rows stamped `'local'` are pre-auth
recipes (Dexie v2 backfill).

## Acceptance criteria

- [ ] `src/lib/library.ts` exports `splitLibrary(rows, countFrom, { uid, isConfigured })` returning `{ created, branched, saved }`, each a `FeedRecipe[]` newest first, deduplicated by id, with child counts computed as `buildFeed` does.
- [ ] With Firebase configured, a row is the user's own only when `createdBy.uid === uid`; with no `uid` nothing is own. Own rows with no `parentId` go to `created`, own rows with a `parentId` go to `branched` whoever owns the parent, and every other row goes to `saved`, roots only, as today. `'local'` rows go to `saved` (see the author question in Notes).
- [ ] With Firebase not configured, every root row goes to `created` and every variation to `branched`, matching `canManageRecipe`.
- [ ] `buildFeed` and the current My Recipes tab are unchanged; nothing in `src/pages` calls `splitLibrary` yet.
- [ ] `src/lib/library.test.ts` covers: own root, own variation of own root, own variation of another user's root, saved copy, `'local'` row configured and unconfigured, signed out, and that no other user's row lands in `created` or `branched`.
- [ ] `docs/capabilities.md` Library tabs row notes that the Created, Branched and Saved split is available in `lib/library.ts` for the rebrand's tabs.
- [ ] A `backlog/QA.md` entry says there is nothing to check in a browser until the rebrand's tab ticket uses it.
- [ ] `npm run build`, `npm run lint` and `npm test` pass.

## Out of scope

The tabs, their labels and any page change (the rebrand). Fetching other people's recipes
for Saved from the cloud. Recipes the user collaborates on but did not create.

## Verification

`npm test` for `library.test.ts`. No browser check until the rebrand uses it.

## Notes

Open author question: should pre-auth `'local'` rows on a device with Firebase configured
count as Created (they predate accounts and are probably the user's) or Saved (they are not
in any account)? Saved is the default here because it claims nothing.
