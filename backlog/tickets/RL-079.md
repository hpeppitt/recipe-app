## Context

After RL-078, a verified user on a fresh device has an empty Dexie until the first server
snapshot of their own recipes lands. My Recipes (`LibraryPage.tsx`, `isLoading` for the
`mine` tab is `localRecords === undefined`) and the own profile (`OwnProfile` in
`ProfilePage.tsx`, `recipesLoading` from `useOwnRecipes`) would flash their empty states
("No recipes yet" style EmptyState on the Library, "No published recipes yet" on the
profile) for exactly the case that triggered the author's decision. Offline, they would show
the cached copy with nothing saying it may be behind.

RL-078 exposes `useOwnRecipesSyncStatus()` (`off`, `waiting`, `synced`, `error`) from
`src/hooks/useOwnRecipesSync.ts`. The Library already has the offline pattern to follow:
Explore's "Could not load" state reads `navigator.onLine === false` for offline-specific
copy. Use the existing `Skeleton` and plain text; no new component. The Organic rebrand (RL-062 to
RL-075, another branch) replaces My Recipes with Created, Branched and Saved tabs (RL-084
has the data); whichever lands second applies these states to the own-recipe tabs.

## Acceptance criteria

- [ ] On My Recipes, while the sync status is `waiting`, the device is online, and the tab would otherwise show its empty state, the existing three `Skeleton` rows show instead, for at most 6 seconds from mount; after that, or on `synced`, `error` or `off`, the page renders exactly as today.
- [ ] On the own profile's recipe list, the same rule shows its existing two `Skeleton` rows instead of "No published recipes yet".
- [ ] When the status is not `synced` and `navigator.onLine === false`, My Recipes shows the recipes it has plus one line above the list in the style of the Explore subtitle (`text-xs text-text-tertiary`): "You're offline. Showing the recipes saved on this device." It updates on the `online` and `offline` events and is not shown to anonymous, signed-out or local-only users (status `off`).
- [ ] Recipes already in Dexie are never hidden behind the skeleton: the skeleton replaces only an empty list.
- [ ] Tests in `LibraryPage.test.tsx` and `ProfilePage.test.tsx` mock the status hook and cover: waiting and empty shows skeletons; waiting with recipes shows the recipes; synced and empty shows today's empty state; offline shows the line; status `off` shows neither.
- [ ] `docs/capabilities.md` Library tabs row describes the waiting and offline behaviour of My Recipes.
- [ ] A `backlog/QA.md` entry: at 390x844 in both themes, sign a verified account with recipes into a fresh browser profile and watch My Recipes go from skeletons to the list with no empty-state flash; set DevTools offline and reload and confirm the offline line; check the line's contrast in dark mode.
- [ ] `npm run build`, `npm run lint` and `npm test` pass.

## Out of scope

Any change to sync logic or the status values (RL-078). Explore, the Following filter and
other users' profiles. A retry button: the listener resumes by itself.

## Verification

`npm test` for both page tests. Human: the QA entry, since the flash and the offline line are
timing and visual checks.
