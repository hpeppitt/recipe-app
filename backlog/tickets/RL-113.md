## Context

The author picked 12b, "Straight to the recipe, with a banner": "The same recipe page as
everywhere else, with a slim "Shared by" banner. Save and Branch trigger the contextual
sign-in sheet (5a) when needed." Markup: 12b in `docs/design/organic/export/Collaboration and
Account.dc.html` and the `sharedBanner` and shared footer parts of the `recipe` block in
`App Prototype.dc.html`. 12c ("/shared · import from a link") is not this app's `/shared`:
here `/shared` decodes a recipe carried in the URL hash (`lib/share.ts`), so 12c is not built.

Today `src/pages/SharedRecipePage.tsx` serves `/shared/:id` (Firestore) and `/shared#r=...`
(hash, validated with Zod; invalid shows "Invalid Link"). It has its own header with a
favourite heart (cloud favourite for verified, local bookmark otherwise, sign-in prompt
signed out), Suggest a Change on `/shared/:id` only (modal), and for hash links "Save to my
library" (a Dexie copy keeping the original `createdBy`) then "Open in my library". Loading,
not found and load-error states with Try Again. All behaviour stays.

Footer mapping: on `/shared/:id`, secondary "Save" is the favourite toggle (label "Saved"
when on) and primary "Make it yours" goes to `/recipe/:id/vary` (which already loads a cloud
parent and shows the sign-up screen to anyone who cannot generate); "Suggest a change" stays
as a ghost button under the pair and enters suggest mode (RL-107) the same way as on the
recipe page. On a hash link, there is no cloud copy to branch or suggest on: the primary is
"Save to my library" (then "Open in my library") and there is no secondary.

The lineage strip needs the parent's title and author, which this page does not load; on a
branch (`parentId` set) show a short sage line instead: "<author> asked for <i>"prompt"</i>."

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`. Light only. 44px targets.

Values to copy:

- Banner (instead of a header row): padding `12px 16px 0`; a pill, flex, gap 8px, padding
  `8px 8px 8px 14px`, `rounded-full bg-surface-secondary`, 13px: "Shared by", the
  `UserPill` (link to the author's profile), a spacer, and a 32px `bg-surface` 600 13px
  pill link "Open Recipe Lab" to `/` (the design's "Get the app" has nothing to install
  from on the web). The favourite heart sits at the right of the banner as a flat 44px
  `IconButton` on `/shared/:id`.
- Title block: as RL-100's original variant (34px title beside a 72px `EmojiBlob` on
  `bg-accent-200`, description), for originals and branches alike (no hero).
- Branch line: `rounded-[22px] bg-accent-2-100 text-accent-2-900`, padding `12px 16px`, 14px,
  `GitBranch` icon, gap 10px, margin-top 14px.
- Body: `RecipeContent` with the RL-102 and RL-103 layout.
- Footer: RL-104's container; secondary `flex: 1` 52px `Bookmark` "Save"; primary `flex: 2`
  52px `GitBranchPlus` "Make it yours"; the ghost "Suggest a change" under them.
- States: loading uses the RL-090 skeleton; not found, invalid link and load error use the
  19a patterns with today's copy and Try Again.

## Acceptance criteria

- [ ] Suggest on `/shared/:id` uses suggest mode (RL-107); `SuggestChangeModal.tsx` is then unused and deleted, with any test.
- [ ] Make it yours navigates to `/recipe/:id/vary`; hash links show no Make it yours and no Suggest.
- [ ] `SharedRecipePage.test.tsx` (new or extended) covers: banner with author, footer per route, hash save copy flow, invalid link state, branch line text.
- [ ] `docs/capabilities.md`: "Share a recipe by link" and "View a shared recipe signed out" rows mention the banner and Make it yours; "Suggest a change" row no longer names the modal.

- [ ] `npm test`, `npm run lint`, `npm run build` pass.
