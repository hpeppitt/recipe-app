## Context

`scripts/data-request.mjs` is the pattern: `firebase-admin` (already a dev dependency),
credentials from the environment as documented in `docs/operations.md`, production guarded by
`--confirm`, checked before `firebase-admin` loads, and pure planning functions tested in
`data-request.test.mjs`. Clients cannot update or delete feedback (RL-285); the admin SDK can.

## Acceptance criteria

- [x] `npm run feedback -- list` prints newest first: date, display name, uid, path, app version, viewport, theme, whether there is a screenshot, and the note.
- [x] `npm run feedback -- save <dir>` writes `<date>-<id>.jpg` (decoded from the data URL) and `<date>-<id>.md` (all fields but the screenshot) for every item.
- [x] `npm run feedback -- delete <id...>` and `npm run feedback -- prune --older-than 365d` delete, printing what they will delete first; against production both need `--confirm <projectId>`.
- [x] Pure parts (formatting, file names, data URL decoding, the prune cutoff) are tested in `scripts/feedback.test.mjs`.
- [x] `docs/operations.md` has a "Reading beta feedback" section.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

An in-app admin page. Email or chat notifications.
