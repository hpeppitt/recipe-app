## Context

`/new` (RL-125, `lib/createPrompt.ts` `buildCreatePrompt`) builds "Something <a> with <b> for
<c>". This adds profile terms after it: ", no peanuts, under 30 min". "Under 30 min" appears
when "Quicker" is in tendToChange (RL-229). Avoids also go into the system prompt (RL-233), so
a dropped avoid must also leave that chat's system prompt: Write it passes
`state: { suggestion, dropAvoids: string[] }` and `useRecipeChat` omits those for that chat only.

## Acceptance criteria

- [x] `buildCreatePrompt(selection, terms)` appends the kept terms; tests for none, one, several.
- [x] The terms render bold (`font-semibold`) as buttons ("Drop no peanuts for this recipe"); a dropped term is struck through and can be tapped back; drops reset each visit.
- [x] Only for verified users with a profile.
- [x] Tests and `docs/capabilities.md` Create tab row.
- [x] A dropped avoid is passed as `dropAvoids` and omitted from that chat's system prompt only (hook test).
- [x] A `backlog/QA.md` entry: with an avoid set, the sentence shows it bold; drop it and Write it: the composer text omits it and the recipe may use it; the next chat respects it again.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Changing the stored avoids from this screen.

## Verification

Component tests.

## Notes

- `lib/createPrompt.ts`: `buildCreatePrompt(selection, terms = [])`, `createTerms(avoids, tendToChange)` ("no <avoid>" per avoid, then "under 30 min" when Quicker is learned) and `keptAvoids(avoids, drop)`, which treats `drop` as untrusted and removes only stored avoids (normalised, case-insensitive).
- `/new` calls `useTasteProfile([])`, so no cooks listener and one profile read; loading, failed or refused reads show no terms and no error. Unverified users get empty values from the hook.
- Term buttons change their accessible name ("Drop no peanuts for this recipe" / "Keep no peanuts") instead of using aria-pressed, since a label that names the action and a pressed state together read ambiguously. Same 44px inline hit pattern as the cycling words.
- Write it sends `dropAvoids` only when something was dropped. `useRecipeChat(parent, fromCookId, dropAvoids)` applies `keptAvoids` when it opens a session; a new chat (new hook instance) uses all avoids.
- Review fixes: the first 3 terms show, then a "+N more" button expands the rest (focus moves to the first revealed term); Write it uses all kept terms. The hidden live sentence is replaced by a `role="status"` line announcing only the change (the new word, or "no peanuts dropped" / "no peanuts kept"). `useTasteProfile` no longer reports permission-denied reads; `loadFailed` is unchanged. Struck terms keep `text-text-tertiary`: 5.5:1 light, 8.4:1 dark on `bg-surface`.
