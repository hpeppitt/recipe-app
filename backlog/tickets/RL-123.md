## Context

The 1a Search screen (RL-124) needs its matching and filtering as pure, tested logic. Spec:
`docs/design/organic/export/App Spec.dc.html`, "Search (1a)": "One pill searches titles and
ingredients across originals and branches ... Chips filter: All, Under 30 min, Easy,
Branches." and, under "Branch recipe", "Search rows carry the same label" (the family label,
"<root title> variation"). The prototype's logic is in `App Prototype.dc.html`, script, the
block starting `const q = s.query.trim().toLowerCase();`.

Reuse, do not duplicate: `queryWords` from `src/lib/search.ts` (drops words of 2 characters
or fewer) and `countDescendantsByRoot` from `src/lib/tree.ts` via the same shape `buildFeed`
uses in `src/lib/library.ts`. `filterFeed` stays as it is; it serves Explore's tag and filter
chips and searches description and tags too, which 1a deliberately does not.

No new index, query or service: the function takes rows the caller already has.

## Acceptance criteria

- [x] `src/lib/library.ts` exports `searchLibrary(sources, { query, filter })` with `filter: 'all' | 'under30' | 'easy' | 'branches'`, and `SEARCH_FILTERS` (the four ids with their labels "All", "Under 30 min", "Easy", "Branches", in that order). `sources` is `readonly (FeedSource & { prompt?: string })[]`. No import from `services/` or `hooks/`.
- [x] Rows are de-duplicated by id, first occurrence wins (callers pass Dexie rows first).
- [x] Words are `queryWords(query)`. When that is empty but the trimmed query is not (for example "ox"), the trimmed lower-cased query is the one word.
- [x] A row matches when every word is a substring of its lower-cased title or of one of its lower-cased ingredient names (each word may hit a different field).
- [x] Empty query: only originals (no `parentId`), except with `branches`, which lists branches. Non-empty query: originals and branches.
- [x] `under30` keeps `totalTime <= 30`; `easy` keeps `difficulty === 'easy'`; `branches` keeps rows with a `parentId`.
- [x] Results are newest `createdAt` first. Each result is the `FeedRecipe` shape plus `familyLabel: string | null` and `line: string`:
  - `familyLabel` is null for an original; for a branch it is "<root title> variation" when the row with id `rootId` is in `sources`, else "Variation";
  - `line` is the description for an original and the prompt in straight double quotes for a branch with a prompt, else its description;
  - `childCount` counts descendants over all `sources`, as `buildFeed` does.
- [x] `src/lib/library.test.ts` covers: title hit, ingredient hit, two words split across title and ingredient, a word missing, case, short-word fallback, empty query roots-only and branches-only, each filter, dedup first wins, family label with and without the root present, `line` for both kinds, order. Use `makeRecipe` and `makeIngredient` from `src/test/factories.ts`.
- [x] `npm test`, `npm run lint`, `npm run build` pass.
