## Context

`/recipe/:id/tree` is `src/pages/VersionTreePage.tsx`. It reads the recipe with `useRecipe`
and the merged local and cloud tree with `useRecipeTree(recipe.rootId)`
(`src/hooks/useRecipeTree.ts`; AUDIT FUN-11 explains the merge and why loading includes the
cloud fetch). It already has three states worth keeping: loading skeletons, a cloud error
with Try again, and "no variations yet" with a Create a variation button. The comments in
the page explain each; keep that behaviour.

The Organic design (brief ticket 3) gives the page a three-way view switch, Tree (3a),
Timeline (3b), Map (3c). This ticket builds the shell those views plug into; the Tree view
itself is RL-068, Timeline RL-070, Map RL-072. Until a second view lands there is nothing to
switch between, so the control renders only when more than one view is available.

The family subtitle and the ancestry path are pure functions in `src/lib/tree.ts`.
`useRecipeLineage` in `src/hooks/useRecipe.ts` already walks the ancestor chain with a cycle
guard; that loop moves into `lib/tree.ts` so the page and the hook share one copy.

Routing: the view lives in a search param, changed with `replace`, so Back leaves the page
instead of stepping through toggles. It does not touch `useUnsavedGuard` or history
sentinels (see the `createBrowserRouter` entry in `docs/decisions.md`), which is why this is
`standard`, not `hard`.

Light only (RL-065): write no `dark:` classes.

## Acceptance criteria

- [x] `src/lib/tree.ts` exports `ancestorChain(recipes, id): Recipe[]` (root first, excluding `id`, cycle-safe, stops at a missing parent) and `useRecipeLineage` uses it for `ancestors` with no behaviour change.
- [x] `src/lib/tree.ts` exports `familySubtitle(recipes, now?)` returning, for the root's family: `"{N} versions, {M} cooks, started by {name} in {Month}"`, where N is the record count, M the distinct `createdBy.uid` count, name the root's `createdBy.displayName`, and Month the root's `createdAt` month name (`toLocaleDateString(undefined, { month: 'long' })`), with the year appended when it is not `now`'s year. Singulars "1 version", "1 cook". A null name drops "by {name}" ("started in March"). A root `createdAt` of 0 (cloud records without one, see `toRecipeLike`) drops " in {Month}". Tests in `src/lib/tree.test.ts` cover each of these and `ancestorChain`.
- [x] Header (replacing `TopBar` on this page only): a 44px round back button (same `navigate(-1)` behaviour as `TopBar`), then the view switch, then the family title (the root recipe's title) in `font-heading` at 30px, then the subtitle in `text-text-secondary` at 14px. Left-aligned.
- [x] View switch: `SegmentedControl` labelled "Tree view", options in order Tree, Timeline, Map, filtered to the views that exist (a single constant list the later tickets append to). Rendered only when more than one view exists. The value is read from `?view=` (`tree` | `timeline` | `map`, anything else or absent means `tree`) and written with `setSearchParams(..., { replace: true })`. `?view=tree` is dropped from the URL rather than written.
- [x] Sticky bottom bar: a full-width primary `Button` labelled `Branch from "<current title>"` (title truncated with an ellipsis to one line) that navigates to `/recipe/:id/vary`, where `:id` is the page's recipe. It sits on `bg-surface` with `shadow-lg` inside `max-w-lg`, and the scroll area has bottom padding so the last node is never hidden behind it. Not shown in the cloud-error and not-found states.
- [x] The loading, cloud-error ("Couldn't load the version tree", Try again) and not-found states keep their copy and behaviour, restyled with RL-063's primitives. The "no variations yet" panel keeps its copy but becomes a `bg-surface-secondary rounded-card` card; its "Create a variation" button is removed because the sticky bar now does that job.
- [x] The existing nested tree rendering stays as the Tree view body until RL-068 replaces it.
- [x] `src/pages/VersionTreePage.test.tsx` (new, following `RecipeDetailPage.test.tsx`'s mocks and `src/test/renderWithProviders.tsx`) covers: subtitle text for a mixed local and cloud family; the switch is absent with one view; an unknown `?view=` renders Tree; the Branch button navigates to `/recipe/:id/vary`; the cloud-error state shows Try again and no Branch bar.
- [x] `docs/capabilities.md` "Version tree view" row: mentions the family subtitle, the `?view=` param and the Branch from button.
- [x] A `backlog/QA.md` entry: on a family with at least three versions from two accounts, open the tree, check the subtitle numbers and month, the Branch from button label and that it opens the variation composer, and that Back from the tree returns to the recipe in one press. Check at 390 and 320 px.
