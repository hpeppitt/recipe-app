## Context

`validateDraft` (`lib/recipeEdit.ts` around lines 107-152) rejects negative servings and
times but accepts a negative ingredient amount, and has no length or count limits. Once
RL-016 caps title length and ingredient and instruction counts in the rules, an edit beyond
them saves locally and then fails to re-publish, with nothing on the edit form saying why.
That is the ordering reason for the dependency.

## Acceptance criteria

- [x] A negative ingredient amount sets `errors.ingredients` to "Amounts can't be negative."
- [x] A title longer than RL-016's cap sets `errors.title`; more ingredient or instruction rows (ignoring blank ones) than RL-016's caps set the matching error, with copy naming the limit.
- [x] The caps are exported constants in `lib/recipeEdit.ts` with a comment pointing at the matching lines in `firestore.rules`.
- [x] `src/lib/recipeEdit.test.ts` covers each new error and the at-the-limit case.

## Out of scope

Caps on description, notes or tags, and any rules change.

## Verification

`npm test`. Human QA in `backlog/QA.md`: type a negative amount on the edit page and confirm
the error shows under ingredients.

## Notes

Constants and validation in `src/lib/recipeEdit.ts`; a test reads `firestore.rules?raw` and fails if the caps in `hasBoundedContent()` differ or the pattern is missing. Title is measured trimmed (what is saved). Ingredient error precedence: existing errors, then negative amount, then count cap. The edit page already renders these errors with `role="alert"`; no page change. No docs state edit validation, so no docs change.
