## Context

`src/lib/units.ts` converts volume to weight only through the curated `GRAMS_PER_CUP` density
table and, by design, never estimates a density (comment ~98: a wrong density is the one error
it refuses to make; capabilities "Unit system toggle" row). The spec's Settings toggle asks for
the opposite for people who weigh everything: show spoons and liquids as estimated grams at
density 1 (tbsp 15 g, tsp 5 g, ml 1 g, l 1000 g), marked "≈". The roadmap says this reverses
the units rule and must be recorded when taken; RL-183 records it with the toggle. This ticket
is the pure helper only and changes no existing conversion.

## Acceptance criteria

- [ ] `estimateGrams(ingredient)` returns `{ grams: number, estimated: true, from: string } | null`: for canonical units tsp, tbsp, cup, ml, l (via `canonicalUnit`), grams come from `GRAMS_PER_CUP` when `gramsPerCup(name)` finds a density, else density 1 (tsp 5, tbsp 15, US cup 240, ml 1, l 1000). `from` is the original formatted amount ("1 tbsp"). Any other unit, or a null amount, returns null.
- [ ] Rounding: below 10 g to the nearest 1 g, below 100 g to the nearest 5 g, above to the nearest 10 g.
- [ ] Existing `convertAmount` behaviour and tests are unchanged.
- [ ] The file-level comment states the two modes: the default refuses to guess; the opt-in estimate guesses and always says so.
- [ ] Tests: each unit, a table hit (flour) vs a miss (stock), rounding bands, null cases.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
