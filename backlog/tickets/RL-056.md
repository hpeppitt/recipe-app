## Context

"Export All Recipes" in `SettingsPage` exports local Dexie recipes only. GDPR and UK GDPR give
a right to data portability, which today is met only by email (RL-055). Everything a verified
user owns in the cloud is readable by them under the rules, so a client-side export is
possible without a server: profile, own published recipes, favourites, follows where they
are either party, suggestions they made or received, their messages, notifications addressed
to them, and their `termsAcceptance` (RL-047).

## Acceptance criteria

- [ ] Settings, Data section, gains "Download my data", shown to signed-in users. Anonymous users get only local data (recipes and bookmarks), labelled as such.
- [ ] It produces one JSON file containing the local export plus the cloud data listed above, with a top-level `exportedAt`, `uid` and schema `version`.
- [ ] The assembly is a pure function in `src/lib/dataExport.ts` with tests; the Firestore reads live in `services/firestore.ts`.
- [ ] A read that fails is listed in the file's `errors` array instead of aborting the export.
- [ ] `docs/capabilities.md` updated; the Privacy Policy wording may then point at it (author re-signs per RL-046).
- [ ] A `backlog/QA.md` entry: download on the preview build and check the file contains a favourite, a follow and a suggestion made on the account.

## Out of scope

Deletion (RL-057), import of this format, and exporting other users' replies beyond the
user's own threads.

## Verification

`npm test`, `npm run build`, then the browser check above.
