## Context

Same design as RL-095 (`docs/design/organic/export/App Spec.dc.html`, "Profile (4a + 4c)",
"Variants Others: back + Follow"), applied to `PublicProfile` in `src/pages/ProfilePage.tsx`
at `/profile/:uid`. Data is unchanged: `usePublicProfile(uid)`, `useUserRecipes(uid)` (cloud
recipes by that author; the published documents carry `parentId` and `prompt`, see
`PublishedRecipe` in `src/services/firestore.ts`) and `useFollow(uid)`, whose sign-up prompt
for anonymous and signed-out visitors and error message stay as they are (RL-026, RL-041).

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`; neutral-700 text is `text-text-tertiary`; filled terracotta with cream
is `bg-primary-600 text-on-accent`. Light only. 44px targets.

Values to copy (as RL-095 unless stated):

- Header row: flat back `IconButton` (`ChevronLeft`, label "Back", `navigate(-1)` or `/` with
  no history). No `TopBar`.
- Identity row: 84px blob avatar (not tappable), name `font-heading` 26px, no sub line.
- Follow: full-width button, height 46px, 15px: "Follow <name>" primary when not following,
  "Following" secondary when following; the existing error line stays under it.
- Stats tiles: Originals, Branches, Followers (`profile.followerCount`), Following
  (`profile.followingCount`), none interactive (lists are own-profile only today). Totals
  line "<n> views · <n> favourites" as in RL-095.
- Tabs Started / Grew and `RecipeTileGrid` from RL-095, split by `parentId`.
- Loading, not found and error states use the 19a patterns from RL-090 with the existing
  copy.

## Acceptance criteria

- [ ] Started lists the author's recipes with no `parentId`, Grew those with one; meta as RL-095.

- [ ] A `backlog/QA.md` entry: open another cook's profile signed out, anonymous and verified; Follow and Unfollow; switch tabs; check 320px.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

(the spec names it; it is a new routing scheme, not layout).
