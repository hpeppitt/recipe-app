## Context

Written for RL-192's recommendations; regroom if the author chose otherwise. The rules already
have the patterns needed: `verified()`, the `writeWindows` move proved with `existsAfter`/
`getAfter` and `last` (RL-048/049, `capFor()` and `windowMsFor()` ~98-105), server-time
`createdAt` checks, and owner-only key-limited updates (`changedKeys().hasOnly`). Editing rules
in the repo is reversible; deploying is RL-209.

## Acceptance criteria

- [x] `match /cooks/{cookId}`: `allow read: if true`. Create: `verified()`; keys exactly `uid, displayName, recipeId, rootId, recipeOwnerId, vote, note, branchId, createdAt`; `uid == request.auth.uid`; `vote in ['again', 'tweak']`; `note == null || (note is string && note.size() <= 500)`; `branchId == null`; `createdAt == request.time`; `displayName` null or a string of at most 100; `recipeId` and `rootId` strings of at most 128; `recipeOwnerId` equals `get(/recipes/$(recipeId)).data.createdBy.uid` (the recipe must exist); and the `cook` window moved in the same request with `last` equal to this path.
- [x] Update: only by the cook, verified, `changedKeys().hasOnly(['branchId'])`, from null to a string of at most 128. Delete: only by the cook, verified.
- [x] `writeWindows` accepts the `cook` action: `cookCap()` 20, window one day; `capFor()` and `windowMsFor()` extended; `RATE_LIMITS.cook` in `src/lib/rateLimit.ts` and the test that ties them.
- [x] Count queries work: a `getCountFromServer` on `cooks where recipeId == X` and on `recipeId == X and vote == 'again'` is allowed signed out (public read).
- [x] Emulator probe codes in Notes: verified create with window (200), without window (403), anonymous (403), wrong uid (403), bad vote (403), note of 501 (403), client `createdAt` (403), recipe missing (403), 21st in a day (403), cook sets branchId once (200) then again (403), someone else deletes (403), signed-out count (200).
- [x] `docs/data-model.md`: collection table row, rules paragraph and access-call budget, "in the repo, deployed by RL-209".
- [x] `npm test`, `npm run lint`, `npm run build` pass.

Cost: the emulator does not report expression counts or document accesses, so these are from
the rule text, not measured. Create: 3 document accesses (`termsAcceptance`, the recipe, whose
`exists()` and `get()` count once, and the window's `getAfter()`), well under the 20 of a
transaction commit; the expression count is a few dozen, far below 1000. A `branchId` update
reads the branch recipe (1). Delete reads nothing.

Review fixes (2026-10-21): `acceptedTerms()` on create; `rootId` must equal the recipe's stored
`rootId` (read with `.get('rootId', null)`, so a recipe without one denies cleanly; `Recipe.rootId`
is required and `publishRecipe` writes the whole record, but the recipe rules do not enforce it);
`branchId` must name an existing recipe the cook owns; delete needs `signedIn()` only, like
termsAcceptance and notificationPrefs. Cooks outlive a deleted recipe (no cascade). Notes added
to RL-057 (erase cooks and cook photos) and RL-196 (displayName from the profile).
