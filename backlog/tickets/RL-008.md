## Context

The correctness half of 3.1 landed (cursor pagination at 30 per page). What remains is the
split: today one feed merges the local library with the paged cloud feed, and because
their union has no stable cursor, paging is suppressed while a search or the favourites
filter is active. Splitting makes "whose recipes am I looking at" legible and makes search
coherent per tab. Product decision 4 in `docs/decisions.md` confirms the split; do not
re-litigate it.

## Acceptance criteria

- [ ] `LibraryPage` has two tabs using the shared `SegmentedControl`: My Recipes (Dexie live query, works offline and in local-only mode) and Explore (paged cloud feed).
- [ ] Search and the favourites filter apply within the active tab; Explore keeps Load more while a search is active, searching the pages fetched so far and saying so.
- [ ] The following filter lives on Explore only.
- [ ] The last-selected tab is remembered in localStorage.
- [ ] `useRecipeLibrary` is split into a local hook and a cloud hook; the pure merge/filter logic moves to `src/lib` with tests.
- [ ] Empty states per tab: an empty My Recipes points at `/create`; an empty Explore explains that nothing has been published yet.
- [ ] `docs/capabilities.md` Library rows and `docs/architecture.md` are updated.

## Out of scope

Tag chips (RL-009). Dedup changes. Any Firestore rules or index change.

## Verification

Tests for the extracted logic. Component tests for the tab switch if RL-002 has landed.
