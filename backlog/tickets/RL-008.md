## Context

The correctness half of 3.1 landed (cursor pagination at 30 per page). What remains is the
split: today one feed merges the local library with the paged cloud feed, and because
their union has no stable cursor, paging is suppressed while a search or the favourites
filter is active. Splitting makes "whose recipes am I looking at" legible and makes search
coherent per tab. Product decision 4 in `docs/decisions.md` confirms the split; do not
re-litigate it.

## Acceptance criteria

- [x] `LibraryPage` has two tabs using the shared `SegmentedControl`: My Recipes (Dexie live query, works offline and in local-only mode) and Explore (paged cloud feed).
- [x] Search and the favourites filter apply within the active tab; Explore keeps Load more while a search is active, searching the pages fetched so far and saying so.
- [x] The following filter lives on Explore only.
- [x] The last-selected tab is remembered in localStorage.
- [x] `useRecipeLibrary` is split into a local hook and a cloud hook; the pure merge/filter logic moves to `src/lib` with tests.
- [x] Empty states per tab: an empty My Recipes points at `/create`; an empty Explore explains that nothing has been published yet.
- [x] `docs/capabilities.md` Library rows and `docs/architecture.md` are updated.

## Out of scope

Tag chips (RL-009). Dedup changes. Any Firestore rules or index change.

## Notes

- Hooks: `useRecipeLibrary.ts` now exports `useLocalLibrary` (Dexie live query) and `useCloudLibrary(enabled)` (paged feed, no read until Explore is first opened, pages kept across tab switches). Pure logic in `src/lib/library.ts` (`buildFeed`, `filterFeed`, `parseLibraryTab`) with `library.test.ts`. Component tests in `src/pages/LibraryPage.test.tsx`.
- Query shape unchanged: Explore still calls `getPublishedRecipesPage` (orderBy createdAt desc, startAfter, limit). Following still uses `getRecipesByUsers`. No rules or index change.
- Dedup unchanged: by id, first occurrence wins, roots only, variation counts across both stores. With tabs the local-wins-over-cloud overlay no longer applies, since each tab lists one store; Explore shows the cloud copy of the user's own published recipes, so those appear once per tab.
- Local-only mode: no tab control, My Recipes only (logged in `backlog/DECISIONS.md`). The "Mine" chip and first-run welcome card are gone (logged).
- Following chip shows only on Explore for verified accounts with follows, so anonymous and signed-out users never see it.
- Review round: a failed Load more now shows an inline `role="alert"` message ("Could not load more recipes. Try again.") via `loadMoreError` from `useCloudLibrary`, cleared on the next attempt; loaded pages are kept. The "loaded so far" note is `role="status"`, and the Explore favourites empty state no longer claims there are none while more pages exist. Unfixed reviewer mediums and lows are listed in `backlog/QA.md`.
