## Context

`match /profiles/{uid}` has no key list and bounds only `photoURL` (`photoURLOk()`, RL-019),
so a bio or country of any size would be accepted today. RL-279 adds `bio` and RL-281/RL-282
add `country`. Text is length-checked with `matches('(?s).{0,N}')`, which counts code points
(decision "Suggestion edit text is checked with matches(), not size()", RL-146); the client caps
by UTF-16 length, so it is never denied by the difference. `isFollowerCountBump()` must stay
untouched so other users can still follow. Deployed by RL-291.

## Acceptance criteria

- [ ] `bioOk()`: `bio` absent, null, or a string matching `(?s).{0,160}`.
- [ ] `countryOk()`: `country` absent, null, or a string matching `^[A-Z]{2}$`.
- [ ] Create requires both; the owner update requires each only when its key is in `changedKeys()`, like `photoURL`.
- [ ] Emulator probes recorded in Notes: a 160-character bio allowed, 161 denied; `country: 'AU'` allowed, `'au'`, `'AUS'` and `5` denied; a follower count bump by another user on a profile with a bio still allowed.
- [ ] `docs/data-model.md` profiles row lists `bio` and `country` with the bounds, "in the repo, deployed by RL-291".
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

A full key whitelist for profiles. Deploying (RL-291).

## Verification

Emulator probes. No production change.
