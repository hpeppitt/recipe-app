## Context

`scripts/data-request.mjs` is the only admin script that writes to a real project (export and
erase, RL-055). Without `--project` it falls back to `GCLOUD_PROJECT`, then `.firebaserc`'s
`default` (`defaultProject()`), and labels every non-emulator run `PRODUCTION`. Once RL-294
makes the default the dev project, a bare run would quietly act on dev while still saying
PRODUCTION, and a stale `GCLOUD_PROJECT` could send it anywhere. The author decided admin
scripts must name their project explicitly.

The existing safety checks stay: emulator host variables refused on a real run
(`resolveTarget`), the typed `--confirm <uid>` for a real erase (`checkConfirmation`), both
before Firebase loads. Tests are in `scripts/data-request.test.mjs` (the CLI is run as a child
process and must print nothing before its checks pass).

## Acceptance criteria

- [ ] A run without `--emulator` and without `--project` exits 1 before Firebase is
  initialised, printing that `--project` is required and naming the two aliases' ids from
  `.firebaserc` as examples. `GCLOUD_PROJECT` and `.firebaserc`'s `default` are no longer used
  to pick the project; `defaultProject()` is removed.
- [ ] `--emulator` without `--project` keeps working with a `demo-` id (`demo-recipe-lab`,
  RL-294) and refuses a `--project` that does not start with `demo-`.
- [ ] The first output line says `target PRODUCTION` only when the project is `prod`'s id in
  `.firebaserc` (or `recipe-lab-3832b` if the alias is missing), `target DEV` for `dev`'s id,
  and `target CLOUD <id>` otherwise.
- [ ] Tests cover: no `--project` on a real run, `--project` given, `--emulator` with a
  non-`demo-` project, and the three target labels; existing tests still pass.
- [ ] `.env.example`'s operator note about `GCLOUD_PROJECT` is removed or says the script
  ignores it. `docs/operations.md` "Data requests" step 3 and step 5 commands show
  `--project recipe-lab-3832b`, and the rehearsal uses `demo-recipe-lab`.
- [ ] If an admin script that reads a real project has been merged to `main` by the time
  this is implemented (for example `npm run feedback` from RL-287 in PR #284), it gets the same
  rule, or the PR names it as a follow-up.
- [ ] `npm test`, `npm run lint` pass.
