## Context

The author picked 10a, "Full thread screen": "The proposed edit is pinned at the top as a diff
row, so the conversation never buries it." Spec (`docs/design/organic/export/App
Spec.dc.html`): "Replaces SuggestionThread". Markup: 10a in `Collaboration and
Account.dc.html` and the `thread` block of `App Prototype.dc.html`.

Today `src/components/recipe/SuggestionThread.tsx` expands inline under each suggestion: it
lists `suggestions/{id}/messages`, sends replies (two participants, immutable, 30 per hour
since RL-048, offline fails within 5 seconds with "Couldn't send that reply. Please try
again.", the rate-limit copy, and the draft kept on failure). Read rules are owner or
suggester with a verified email (RL-018). Every one of those behaviours and messages stays.
Suggestions are free text, so the pinned item is the message, not a diff row (the diff row
needs structured suggestions, a new feature).

The thread becomes a route, `/recipe/:id/suggestion/:suggestionId`, outside `AppShell`,
lazy. It loads the suggestion through the same hook the recipe page uses
(`useSuggestions(recipeId, ownerUid)`) or a single read if one exists; a missing or forbidden
suggestion shows the 19a error state "Couldn't open this suggestion" with Back.

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`; neutral-700 text is `text-text-tertiary`; `tag-*` as in RL-105.
Light only. 44px targets.

Values to copy:

- Header: back (flat `IconButton`), "Suggestion" in `font-heading` 18px flex 1, status tag
  600 (`tag-accent` "Open", `tag-accent-2` "Approved", `tag-neutral` "Declined"),
  margin-right 10px.
- Body: scrolls, padding `12px 20px 0`, column, gap 12px. Pinned card: padding 16px,
  `rounded-[30px] bg-surface-secondary`, gap 12px; top row 13px, gap 10px: a 32px avatar,
  "<b>name</b> on <b>recipe title</b>" flex 1, `timeAgo` in `text-text-tertiary`; then the
  message, 14px, line-height 1.5.
- Replies: the viewer's own bubble right-aligned, max-width 260px, padding `12px 16px`,
  radius `24px 24px 6px 24px`, `bg-accent-2-200 text-accent-2-900`, 14px; the other
  person's left-aligned with a 26px avatar beside it, radius `24px 24px 24px 6px`,
  `bg-neutral-100`. Time under each in 11px `text-text-tertiary`. Newest at the bottom; the
  view scrolls to the newest on open and after sending.
- Bottom bar: padding `10px 16px 28px` (plus safe area), `bg-surface`, top rule of the
  divider, column, gap 10px. Reply pill: height 48px, `rounded-full bg-neutral-100`, padding
  `0 6px 0 18px`, input 14px with placeholder "Reply to <name>…" and a visually hidden
  label, a 36px round send button with `ArrowUp` (`bg-neutral-300` when empty, `bg-primary-600
  text-on-accent` when there is text), label "Send reply". Owner and pending: a row of two
  48px buttons, "Decline" secondary `flex: 1` and "Approve" primary `flex: 1.2`, with the
  RL-105 handlers (Decline confirms; Approve then opens the variation composer).
- Errors (send failure, rate limit) show above the pill in `text-danger-700` 12px with
  `role="alert"`, as today.

## Acceptance criteria

- [ ] `App.tsx` adds the lazy route above outside the shell; `src/pages/SuggestionThreadPage.tsx` renders the screen; RL-105's "Replies", "join the chat" and closed rows navigate to it.
- [ ] Reply sending reuses the existing service call and keeps the RL-048 limit messages, the 5 second offline failure and the kept draft; messages stay immutable.
- [ ] Only the two participants can open it (the existing listener and rules decide); anyone else sees the 19a error state, and no listener is opened for signed-out or anonymous users.
- [ ] The inline thread is removed from the recipe page; `SuggestionThread.tsx` is deleted or reduced to the shared message list used by the page.

- [ ] `docs/capabilities.md` "Reply thread on a suggestion" row names the new page and route; the Routes table gains the route.
