## Context

Two races in `contexts/AuthContext.tsx`, both reported as possible rather than observed.

1. Double migration. When an email link signs into an existing account,
   `runEmailLinkCompletion` (lines 132-153) calls `runMigration` from the saved anonymous
   uid. The `onAuthStateChanged` email branch (lines 190-233) also sees the saved anonymous
   uid, which is only cleared after the first migration resolves, and `migrationRunRef` is
   not set on the link path, so it can start a second `runMigration` concurrently.
2. Profile name. `handleSignInAnonymously` (lines 235-257) sets the generated display name
   and then calls `createOrUpdateProfile`, while `onAuthStateChanged` calls
   `createOrUpdateProfile` with the not-yet-set `displayName: null`. Both read-then-write, so
   both can take the create path and the null one can land last.

The required ordering for email-link completion is in "Email-link completion has a required
order of operations" in `docs/decisions.md`; do not disturb it.

## Acceptance criteria

- [ ] First, each race is reproduced (or shown impossible) against the Auth emulator, with the observation recorded in Notes. If one cannot happen, its criterion below is dropped with that evidence.
- [ ] `runMigration` runs at most once per old-uid/new-uid pair per page load, whichever path triggers it (for example the link path sets `migrationRunRef` before starting).
- [ ] After anonymous sign-in, the profile document's `displayName` is the generated name, not null.
- [ ] `docs/architecture.md` auth section notes the single-run guard.

## Out of scope

The server-side migration, anything in `services/firebase.ts`, and the stranded-identity
notice copy.

## Verification

Emulator walk-through per `docs/operations.md` for both paths. Human QA in `backlog/QA.md`:
on the preview build, sign in anonymously and check the profile page shows the generated name.

## Notes

Recommended for dropping (2026-10-14 regroom); left at `draft` per the coordinator's
instruction that only the coordinator changes statuses. Both races are moot under the
author's decision that anonymous accounts are local-bookmark only:

- The anonymous profile write race disappears because RL-041 stops anonymous accounts
  writing a profile at all.
- The double migration is harmless once RL-032 reduces `runMigration` to the two Dexie
  migrations: both are idempotent, so a second concurrent run moves nothing new, and there
  is no longer a stranded-identity notice to set twice.
