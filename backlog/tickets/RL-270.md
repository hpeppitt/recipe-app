## Context

A recipe's `emoji` is an unconstrained string today (`GeneratedRecipeSchema` in
`schemas/recipe.schema.ts`, the edit page's free text input, and no bound in
`firestore.rules`), so several emoji overflow `EmojiBlob` and the other icon containers. The
author wants a recipe icon to be exactly one emoji. RL-271 to RL-273 apply this helper on
every write path, on reads of stored data and in the rules. Pure logic first so it is tested
in node (CLAUDE.md: nothing in `lib/` imports from `services/` or `hooks/`).

## Acceptance criteria

- [ ] `oneEmoji(value: unknown, fallback: string): string` splits with `Intl.Segmenter` (granularity `grapheme`) and returns the first grapheme that is an emoji: it contains `\p{Extended_Pictographic}`, or is a regional indicator pair (a flag), or a keycap (contains U+20E3). Otherwise it returns `fallback`.
- [ ] `lastEmoji(value: unknown): string | null` returns the last such grapheme or null, for the edit field (RL-271), where a newly typed emoji should replace the old one.
- [ ] A non-string, an empty string and text with no emoji return the fallback (or null).
- [ ] `RECIPE_EMOJI_FALLBACK = '🍽️'` is exported for callers with no previous emoji.
- [ ] Tests cover: a single emoji; two and three emoji; a ZWJ family sequence; a skin-tone modifier; a flag; a subdivision flag (tag sequence); a keycap; an emoji with a trailing variation selector; text around an emoji; plain letters; empty; `undefined` and a number.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Calling it anywhere (RL-271, RL-272). Profile avatar emoji (`photoEmoji`).

## Verification

Unit tests.
