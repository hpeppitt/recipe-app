## Context

RL-251 left photo imports without `importedFrom`: the draft carries `PHOTO_SOURCE` (`'photo'`,
`src/lib/linkImport.ts`), but `useImportRecipe.save` drops it because `hasBoundedContent()` in
`firestore.rules` and `ImportedFromSchema` in `src/schemas/recipe.schema.ts` accept only a bounded
http(s) URL. RL-253 therefore left "Imported from a photo" unticked. The author decided on
2026-10-22: allow the exact literal `'photo'` in both places, store it, and show it as plain text
with no link. This already matches `docs/decisions.md` "Import reads through AI Logic and is
credited (RL-184)", which says an import keeps "the URL, or photo".

The rules edit stays in the repo; RL-261 deploys it. Until then the live rules deny a recipe
create carrying `importedFrom: 'photo'`, so a photo import save fails against production (the
save is cloud first, `publishThenCache`, and writes nothing on a failed publish). That is the
same "fails live until RL-261" state as RL-257 to RL-259, and RL-261 deploys rules before the
client.

`ImportedFromSchema` is shared by the own-recipe sync (`lib/recipeSync.ts`), share links
(`lib/share.ts`) and the export restore (`withBoundedImportedFrom`), so all three keep `'photo'`
once the schema accepts it. Only `components/recipe/ImportedFrom.tsx` renders the value.
