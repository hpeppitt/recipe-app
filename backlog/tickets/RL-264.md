## Context

RL-254 added the PWA `share_target`; `/import` seeds its field from `sharedImportUrl` (in
`src/lib/linkImport.ts`) and waits for Read it. The author decided on 2026-10-22: when the page
opens with a shared link and the user can read it right now, confirm first with the existing
`components/ui/ConfirmDialog.tsx`, and read only on confirm. Otherwise keep today's prefill. One
Gemini call per confirmed share, never one per share.

"Can read it now" is: link mode (not `?mode=photo`), `sharedImportUrl(...)` non-null at mount,
auth finished loading, `isConfigured`, a signed-in `user` for whom `canGenerate` is true
(`src/lib/generation.ts`), and `useOnline()` (`src/hooks/useOnline.ts`) true. Note that
`ImportPageBody` computes its `useState` initial values while auth may still be loading, so the
dialog's open state must be derived after `authLoading` clears, not fixed in the initializer.

## Acceptance criteria

- [ ] With all of the conditions above, `/import` shows `ConfirmDialog` once per page mount: title "Read this recipe from <host>?" (host from `importHost`, `www.` dropped), message "Recipe Lab reads the page with AI. You check the recipe before it's saved.", confirm "Read it", cancel "Not now".
- [ ] Confirm closes the dialog and calls `read(url)` once, exactly as tapping Read it does (status line, preview, errors unchanged).
- [ ] Cancel or Escape closes the dialog, reads nothing, and leaves the link in the field; the dialog does not reopen on that mount.
- [ ] No dialog, prefill only, when: offline at the time the dialog would open, signed out or not allowed to generate (the sign-up screen shows as now), `?mode=photo`, no usable shared link, or a direct visit to `/import`.
- [ ] Tests in `ImportPage.test.tsx` cover confirm (one read), cancel (no read, field kept), offline (no dialog), not allowed to generate (no dialog), and auth resolving after mount (dialog appears once loaded). The existing "prefills the shared link without reading" test is updated to the offline or no-user case rather than deleted.
- [ ] `docs/capabilities.md` Import from a link row: the RL-254 sentence "nothing is read until the user taps Read it" becomes the confirm behaviour.
- [ ] `docs/decisions.md`: a short dated section "A shared link asks before reading (RL-264, 2026-10-22)" with the conditions, the reason (one Gemini call only with the user's consent) and the rejected alternative (auto-read on mount).
- [ ] `backlog/DECISIONS.md`: the RL-254 row is marked `decided 2026-10-22: confirm dialog, read on confirm (RL-264)`.
- [ ] A `backlog/QA.md` entry: on an installed Android app, share a recipe page from Chrome while signed in and online; the dialog names the host; Read it reads, Not now leaves the link filled. In airplane mode the link is only prefilled.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Keeping the shared link through sign-up for signed-out users (still lost, as RL-254 notes).
iOS. Sharing images. Any change to `read` or `useImportRecipe`.
