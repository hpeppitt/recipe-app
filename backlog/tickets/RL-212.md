## Context

Written for RL-210's item shape. Ingredients are `{ amount: number | null, unit: string | null,
name, notes, group }` (`types/recipe.ts`). Scaling is `scaleIngredients` (`lib/scale.ts`);
units normalise with `canonicalUnit` (`lib/units.ts`); diffs already match ingredients by the
name before the first comma (spec §3), so use the same key. Pure logic first, tested.

## Acceptance criteria

- [x] `itemKey(name)`: lower case, before the first comma, trimmed, simple plural folded ("eggs" and "egg" match; "tomatoes" and "tomato").
- [x] `AISLES = ['Produce', 'Dairy', 'Meat and fish', 'Bakery', 'Pantry', 'Frozen', 'Other']` and `aisleFor(name)` from a keyword table (about 80 common words, e.g. banana, onion, spinach → Produce; butter, milk, egg, cheese, yoghurt → Dairy; flour, sugar, miso, rice, pasta, oil, salt → Pantry). Unknown → Other. Comment that it is a heuristic.
- [x] `addRecipe(list, recipe, servings)`: scales, then for each ingredient merges into an existing line with the same key and the same canonical unit (summing amounts, adding the source once), else adds a line; an ingredient with a null amount merges by key only and shows no amount. Different units for the same key stay separate lines.
- [x] `removeSource(list, recipeId)` subtracts that recipe's contribution, dropping lines that reach nothing.
- [x] `splitByPantry(list, pantry)` returns `{ toBuy, inPantry }` by key; `listSummary` gives "11 to buy · 5 already in the pantry" (singulars, "Nothing to buy" at 0).
- [x] `groupByAisle(lines)` in `AISLES` order, alphabetical inside.
- [x] `boughtItAll(list, pantry, now, uid)` returns the emptied list and the pantry with every line added (group `fresh` for Produce, Dairy, Meat and fish, Bakery; else `cupboard`), skipping keys already there.
- [x] `formatLineAmount(line)` uses `formatAmount` and `formatUnit` ("230 g", "2 × 90 g" is out of scope: show "180 g").
- [x] Tests for each function, including the canvas example: butter 115 g from two recipes sums to 230 g with both emoji.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

RL-211 review: the rules cap list lengths only, so a kitchen document can still pass 1 MiB. Export per-item limits from src/lib/kitchen.ts and apply them in these helpers: item name at most 80 characters, at most 8 sources per item (keep the newest), source title trimmed to 80.

### Implementation notes (RL-212)

- Item shape is RL-210's, with one addition: each source also carries its own `amount` (`{ recipeId, emoji, title, amount }`) so `removeSource` can subtract it. A line's `amount` is always the sum of its sources' amounts. `Item`, `ItemSource`, `PantryItem` and the limits (`ITEM_NAME_MAX` 80, `ITEM_SOURCES_MAX` 8, `SOURCE_TITLE_MAX` 80) are exported from `src/lib/kitchen.ts`.
- Conflict between "at most 8 sources, keep the newest" and removal: dropping the oldest source would make its recipe impossible to subtract. Chosen: a merge that would make a ninth source starts a new line with the same key and unit instead, so no source is lost and every line has at most 8. Two lines of the same item is the cost.
- The same recipe added twice (or two ingredients with the same key in one recipe) folds into that recipe's one source on the line.
- Not enforced here: the 300-item list cap (the caller, RL-213, should refuse or warn). `addedAt` is epoch milliseconds, `now` a number.
- Name stored on a line is the ingredient's text before the first comma, original case, capped at 80.
