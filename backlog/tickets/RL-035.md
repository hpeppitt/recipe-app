## Context

`formatUnit` (`lib/units.ts` lines 316-322) pluralises any unit whose canonical form is in
`PLURAL_UNITS` (`cup`, `pint`, `quart`). `pt` and `qt` canonicalise to `pint` and `quart`,
so they render as "pts" and "qts", which breaks the file's own rule, stated in the comment
above `PLURAL_UNITS`: "words take an s, symbols do not".

## Acceptance criteria

- [x] `formatUnit` pluralises only when the unit as written is the singular word form (`cup`, `pint`, `quart`, case-insensitive); abbreviations such as `pt` and `qt` are returned unchanged.
- [x] `src/lib/units.test.ts` adds `formatUnit('qt', 2) === 'qt'` and `formatUnit('pt', 3) === 'pt'`, and the existing cases still pass.

## Notes

`formatUnit` in `src/lib/units.ts` now checks the trimmed, lowercased unit as written against `PLURAL_UNITS` instead of its canonical form, so `pt` and `qt` return unchanged. Casing is unchanged: `Cup` at 2 gives `Cups`, `CUP` gives `CUPs`. Converted units still pluralise because `convertAmount` returns the bare word `cup`, which is covered by a new test. Side effect: an alias that is a word with trailing punctuation (for example `cup.`) no longer pluralises; no known data relies on it. New tests are in `src/lib/units.test.ts` under `describe('formatUnit')`; no existing assertion was changed.
