## Context

Written to RL-284's decisions (every verified account, a device-local Settings switch).
Automatic capture is RL-288; the attach tile here stays as the fallback when capture fails
and for users who prefer their own screenshot. Mount the tab in `App.tsx` beside `TermsGate`, inside
`BrowserRouter`, so it is on every route, inside and outside `AppShell`. The cook photo tile in
`CookedSheet.tsx` (RL-205: 96px dashed tile, `validateImageFile`,
`downscaleToJpeg(file, { maxSide: 800, maxBytes, shrinkToFit: true })`, `maxBytesForDataUrl`,
preview with a 32px remove button) is the pattern for the screenshot; reuse it, do not copy it.
The "Weigh spoons and liquids" switch is the pattern for a device-local Settings switch.

### The design (the implementer has no other copy)

- Tab: fixed to the right edge, vertically centred (`top-1/2 -translate-y-1/2 right-0`),
  32px wide and 96px tall, `rounded-l-[14px] bg-text-primary text-on-accent shadow-md`, label
  "Feedback" 13px semibold in `writing-mode: vertical-rl`, rotated so it reads bottom to top.
  `z-30`: above page content and the nav, below sheets and dialogs. Accessible name "Send
  feedback". Hidden while a sheet or dialog from `components/ui` is open is not required.
- Sheet (`components/ui/Sheet`): heading "Send feedback" (Caprasimo 22px); a textarea "What
  happened, or what would you change?" (4 rows, required, counter "n/1000" from 900); the
  screenshot tile "Add a screenshot" with the hint "Take a screenshot first, then add it
  here."; the line "Screenshots can show other people's names and recipes. Only the Recipe
  Lab team sees what you send." (13px `text-neutral-700`); the line "We'll include this
  page's address, the app version and your screen size." (13px `text-text-tertiary`); a
  full-width primary "Send", disabled until the note has text.
- Sent: the sheet closes and a toast says "Thanks. Feedback sent." At the cap: "You've sent a
  lot of feedback today. Try again tomorrow." Any other failure: "Couldn't send that. Check
  your connection and try again." with the note kept. Escape or backdrop with text or a
  screenshot asks "Discard this feedback?".
- Settings, in the app section: switch "Show the feedback tab", on by default, stored on the
  device.

## Acceptance criteria

- [ ] The tab shows on every route for a verified user with the switch on, and never for signed-out, guest or unverified users, or in local-only mode.
- [ ] The sheet sends through `submitFeedback` with the context of the page the tab was tapped on.
- [ ] The screenshot is held in memory only: never in Dexie, analytics or an error report.
- [ ] At 320px the tab covers no primary button on Explore, a recipe page footer, Create's sticky actions or cook mode; if it does, it moves to `top-1/3` and that is recorded in Notes.
- [ ] Keyboard: the tab is reachable by Tab, the sheet traps focus and returns it to the tab on close.
- [ ] Tests: visibility rules, send with and without a screenshot, cap and failure copy, discard confirm, Settings switch.
- [ ] `docs/capabilities.md` gains a Feedback row.
- [ ] A `backlog/QA.md` entry: "On a phone, take a screenshot, tap Feedback, attach it, send; check it arrived with the RL-289 script. Turn the tab off in Settings."
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Automatic capture (RL-288). Reading feedback (RL-289). Privacy text (RL-290).
