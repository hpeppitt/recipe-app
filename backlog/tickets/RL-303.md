## Context

The pipeline tickets can be merged and reviewed but only a real run proves them, and the first
production run is a production deploy, which is human work (`backlog/README.md`, "What needs a
human"). After RL-299 retires `preview.yml`, the repository-level secret
`FIREBASE_SERVICE_ACCOUNT` (Hosting Admin on production) and the repository-level `VITE_*`
variables are unused, and a leftover production key with no Environment gate is the one way
round the approval. The `qa` channel on production expires by itself 7 days after its last
deploy but can be deleted at once.

The first production run is the next release after RL-300 merges. If RL-291 (PR #284) is in
that release, its rules and the client ship in this run, rules first, so the tag message
carries `deploy-order: rules-first` and the author walks RL-291's live checks after.

## Acceptance criteria

**Dev**
- [ ] After a merge to `main`, the Deploy dev run is green; its summary shows the deploy, an
  empty ruleset diff after, and `https://<dev-id>.web.app`.
- [ ] On the dev site on a phone: email link sign-in completes, one recipe generates (App
  Check and AI Logic work), Google sign-in works if enabled, and `/terms` loads.
- [ ] `node scripts/deploy.mjs prod` on the laptop refuses.

**Production**
- [ ] `/release` pushes the tag; the Deploy prod run shows the plan, then waits under Review
  deployments. Approve.
- [ ] The run is green: empty ruleset diff after, headers pass, bundle matches. Record the
  version, order and both ruleset ids in `docs/operations.md` (a release record like RL-042's).
- [ ] Live walk of the release's QA lines on `https://recipe-lab-3832b.web.app`.
- [ ] A dispatch of Deploy prod from `main` (not a tag) fails before the approval prompt.

**Clean up**
- [ ] `npx firebase hosting:channel:delete qa --project prod` (or console, Hosting, the `qa`
  channel, Delete).
- [ ] GitHub, Settings, Secrets and variables, Actions: delete the repository secret
  `FIREBASE_SERVICE_ACCOUNT` and the repository variables `VITE_FIREBASE_*`,
  `VITE_RECAPTCHA_SITE_KEY` and any `VITE_FIREBASE_MEASUREMENT_ID`.
- [ ] Google Cloud console, project `recipe-lab-3832b`, IAM, Service Accounts: delete the
  old Hosting-Admin-only preview service account's key (or the account), leaving
  `github-deploy`.
