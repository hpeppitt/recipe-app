## Context

The rules cannot count graphemes, so they bound size: a hostile client could otherwise store
a long string that overflows every tile. The longest RGI emoji (a kiss or couple with two
skin tones, a subdivision flag) is 15 UTF-16 units; 24 leaves room. Rules `size()` counts
UTF-16 units (`docs/decisions.md`, RL-146 note). `hasBoundedContent()` runs on create and on
`isOwnerUpdate()`; an old document with a long emoji must stay editable when the update does
not change the emoji, so the update check applies only when `emoji` is in `changedKeys()`.
Deployed by RL-291.

## Acceptance criteria

- [x] Create: `d.emoji is string && d.emoji.size() >= 1 && d.emoji.size() <= 24`.
- [x] Owner update: the same check only when `'emoji' in changedKeys()`.
- [x] View, favourite and reparent updates are unaffected.
- [x] Emulator probes recorded in Notes: create with "🍞" allowed; create with 25 units denied; owner update of a seeded document whose stored emoji is 30 units, changing only the title, allowed; the same update setting a 30-unit emoji denied.
- [x] `docs/data-model.md` recipes row states the bound, "in the repo, deployed by RL-291".

## Notes

RL-273 (2026-10-22). `firestore.rules`: a new `emojiOk()` inside `match /recipes/{recipeId}` (`request.resource.data.get('emoji', null)` is a string of 1 to 24 UTF-16 units). The create rule calls it beside `hasBoundedContent()`; `isOwnerUpdate()` adds `(!('emoji' in changedKeys()) || emojiOk())`, the photoURL pattern. It is not inside `hasBoundedContent()` because `changedKeys()` reads `resource.data`, which a create does not have. View, favourite and reparent shapes do not call either and are unchanged. Adds about 8 expressions.
