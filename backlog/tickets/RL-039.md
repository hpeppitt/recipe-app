## Context

`npm audit --omit=dev` on 2026-10-14 reports 6 vulnerabilities (1 moderate, 3 high, 2
critical): `protobufjs` <=7.6.4 (critical), `websocket-driver` <=0.7.4 (critical),
`@grpc/grpc-js` <=1.13.5 (high), `@protobufjs/utf8` <=1.1.0 (moderate), and `react-router`
6.0.0-7.18.1 with `react-router-dom` (high). `npm ls` traces `websocket-driver` to
`firebase > @firebase/database > faye-websocket` and `@grpc/grpc-js` to
`firebase > @firebase/firestore`; both are Node transports that a browser build normally
does not include. The `react-router` advisories are largely about SSR and RSC modes this SPA
does not use, but some (open redirect via `<Link>` and `useNavigate`) are client-side.
`npm audit fix` reports a non-breaking fix for all of them.

Bumping versions of existing dependencies is not "adding a dependency" in the
`backlog/README.md` sense, so this is reversible.

## Acceptance criteria

- [x] The PR description lists each advisory and whether the vulnerable code is reachable in the browser bundle (check `dist/assets` after `npm run build` for the package, or the Vite module graph) or is Node-only.
- [x] `npm audit fix` is run without `--force`; the diff is limited to `package-lock.json` and, only if npm itself changes it, `package.json` ranges.
- [x] `npm audit --omit=dev` afterwards reports no critical or high advisories, or the PR lists the ones that remain and why.
- [x] `npm run build`, `npm run lint` and `npm test` pass.
- [x] A `backlog/QA.md` entry: the standing walk on the preview build, with attention to navigation (react-router) and live Firestore listeners.

## Out of scope

The `functions/` package (its own lockfile, undeployed per `docs/operations.md`), major
version upgrades, and `--force`.

## Notes

Before (`npm audit --omit=dev`): 6 vulnerabilities (1 moderate, 3 high, 2 critical).
After `npm audit fix` (no `--force`, only `package-lock.json` changed): 4 high vulnerabilities.
Both criticals and the moderate are cleared (protobufjs 7.6.6, websocket-driver 0.7.5), and
react-router and react-router-dom are 7.18.4. react-router no longer appears in the audit output at
all, so the client-side redirect advisories (GHSA-wrjc-x8rr-h8h6, GHSA-2j2x-hqr9-3h42) are resolved.

Reachability, by grepping `dist/assets/*.js` after `npm run build` (string grep, not a module graph):

| Advisory package | In browser bundle? |
|---|---|
| @grpc/grpc-js | No, Node-only |
| protobufjs, @protobufjs/utf8 | No |
| websocket-driver (via faye-websocket) | No |
| react-router turbo-stream, `deserializeErrors`, `RSCErrorHandler`, `__manifest` (SSR/RSC/framework mode) | No, not used by this SPA |
| react-router `<Link>`/`useNavigate` redirects | Yes, fixed by 7.18.4 |

Remaining 4 highs: @grpc/grpc-js <=1.13.5 (GHSA-m9gg-hp2v-232j getAuthContext returns unauthorized
certificates as authorized; GHSA-f596-whhp-79r4 server sends handler error messages to clients), and
its dependants @firebase/firestore, @firebase/firestore-compat, firebase. They remain because
the installed chain is firebase 12.9.0, @firebase/firestore 4.11.0, @grpc/grpc-js 1.9.16, and the
newest @firebase/firestore (4.18.0) still pins `@grpc/grpc-js ~1.9.0`. `npm audit fix --force`
would install firebase 9.14.0, a major downgrade, so it was not run. Both advisories concern
grpc-js server/TLS use, which the browser bundle does not include.

Follow-up suggestion: `npm audit fix` warned that @firebase/util, fsevents, protobufjs and esbuild
have install scripts not covered by `allowScripts`; that may deserve its own ticket.
