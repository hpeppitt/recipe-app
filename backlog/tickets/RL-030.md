## Context

`markAllNotificationsRead` (`services/firestore.ts` around line 568) puts every unread
notification in one `writeBatch`. Firestore batches are capped at 500 writes, so with more
than 500 unread the commit throws and nothing is marked. `migrateFirestoreUid` already shows
the chunking loop to copy.

## Acceptance criteria

- [x] Updates are committed in batches of at most 500.
- [x] A test in the mocked-Firestore style of `src/services/firestore.favorites.test.ts` asserts that 501 unread produce two commits of 500 and 1, and 0 unread produce no commit.

## Out of scope

Changing the notification query or the 50-item subscription limit.

## Verification

`npm test`.

## Notes

- Chunked with `BATCH_LIMIT = 500` in `src/services/firestore.ts`, same loop shape as `migrateFirestoreUid`. Query, fields and error handling unchanged. No notifications test existed, so `src/services/firestore.notifications.test.ts` was created.
- `firestore.rules` notifications update rule uses only `resource.data`, `changedKeys()` and the token-based `verified()`: no `get()` or `exists()`, so a 500-write batch is not limited by the 20-access cap.
- Not changed: `migrateFirestoreUid` still uses an inline 500. Left alone (no drive-by).
