## Context

The cloud-feed effect in `useRecipeLibrary.ts` (lines 57-81) has a catch but no cancel: a
slow first load that resolves after "Retry" bumps `reloadKey` overwrites the newer result,
and state is set after unmount. RL-008 splits this hook into a local and a cloud hook, so
this lands after it, in whichever hook owns the cloud fetch.

## Acceptance criteria

- [x] The cloud first-page effect uses a `cancelled` flag set in its cleanup and skips every `setState` once cancelled. (Proven for the retry race; the unmount half is by inspection only.)
- [x] `loadMore` does not append a page that was requested before a reload.

## Out of scope

Anything else in RL-008's split.

## Verification

A hook test if RL-002 has landed; otherwise lint, build, and the standing library walk.

## Notes

The implementation landed in RL-009 (`cancelled` flag in the cloud first-page effect, `requestId` guard in `loadMore`). This ticket adds the proving tests in `src/hooks/useCloudLibrary.test.tsx`: retry beats a slow first load (fails without the `cancelled` flag), a pre-reload `loadMore` page is not appended, and a stale `loadMore` rejection sets no error. The unmount half of criterion 1 has no test: React 19 does not warn on setState after unmount, so a test could not fail. It is covered by inspection only: the same cleanup that the retry race exercises sets `cancelled`. No hook change was needed.
