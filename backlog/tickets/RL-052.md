## Context

PostHog is the only analytics provider (author decision 2026-10-14). RL-058 removes GA4 first
and leaves `services/analytics.ts` as a no-op seam; RL-054 then routes it to PostHog. Under
GDPR and UK GDPR (which the author has decided apply), analytics cookies and identifiers need
opt-in consent, so this ticket builds the gate PostHog will sit behind. Visitors from before
RL-058 may still carry GA4 `_ga` cookies, which only need clearing.

reCAPTCHA v3 and App Check protect the AI path and are strictly necessary, so they are
disclosed in the Cookie Policy (RL-044) but not gated. The error beacon (`clientErrors`) is
not analytics and is not gated either; the Privacy Policy covers it under legitimate
interests.

## Acceptance criteria

- [x] `src/lib/consent.ts` (pure, tested) defines the stored shape `{ analytics: 'granted' | 'denied', at: number, version: number }`, a parser that treats anything malformed as "not yet chosen", and `shouldShowBanner` (true only when PostHog is configured, meaning `VITE_POSTHOG_KEY` is set, and no valid choice is stored).
- [x] The choice is stored in localStorage under a new `STORAGE_KEYS` entry through `services/storage.ts`.
- [x] Before consent is `granted`, and after `denied`, every `track*` and `setAnalyticsUserId` call in `services/analytics.ts` is a no-op.
- [x] `services/analytics.ts` exposes one consent hook point (for example `onConsentChange(granted)`) that RL-054 uses for PostHog, so no provider reads consent on its own.
- [x] `ConsentBanner` is mounted once in `AppShell`, above `BottomNav`, at 390 px in both themes. Copy: "Recipe Lab can use optional analytics to see which features get used. Nothing is tracked unless you allow it." Two buttons of equal weight, "Allow analytics" and "No thanks", and a link to the Cookie Policy (`/cookies`). It does not block the page.
- [x] `SettingsPage` gains a "Privacy" control (a toggle in the Legal section from RL-045) that shows the current choice and changes it.
- [x] Withdrawing consent stops all further analytics calls in the same session and fires the consent hook so RL-054 can opt PostHog out.
- [x] On first load after this ships, any leftover GA4 `_ga` and `_ga_*` cookies for the site domain are deleted once, whatever the choice.
- [x] Bumping `version` in `lib/consent.ts` re-shows the banner, for when providers change.
- [x] `docs/architecture.md` (analytics seam) and `docs/capabilities.md` describe the consent gate.
- [x] A `backlog/QA.md` entry: on the preview build in a fresh profile, the banner shows; "No thanks" hides it and it stays hidden after a reload; Settings shows and changes the choice; a profile with an old `_ga` cookie has it removed. The PostHog request checks are in RL-054.

## Out of scope

PostHog itself (RL-054), removing GA4 (RL-058), the policy text (RL-044), and gating
reCAPTCHA or the error beacon.

## Verification
