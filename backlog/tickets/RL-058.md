## Context

The author decided PostHog (RL-053, RL-054) replaces Google Analytics 4. GA4 lives in two
places: `services/firebase.ts` imports `getAnalytics`, passes `measurementId` from
`VITE_FIREBASE_MEASUREMENT_ID` in the Firebase config (around line 32) and calls
`getAnalytics(app)` at start-up (around line 85); `services/analytics.ts` creates the
instance lazily and sends every `track*` event through one private `logEvent`, and
`setAnalyticsUserId` sets the GA4 User-ID. This lands before RL-052, so the consent banner
only ever gates PostHog.

## Acceptance criteria

- [ ] `services/firebase.ts` no longer imports `firebase/analytics`, calls `getAnalytics`, or passes `measurementId`.
- [ ] `services/analytics.ts` no longer imports `firebase/analytics`. Every exported `track*` function and `setAnalyticsUserId` keeps its signature, so no caller changes; `logEvent` and `setAnalyticsUserId` become no-ops with a comment saying RL-054 routes them to PostHog behind RL-052's consent.
- [ ] `VITE_FIREBASE_MEASUREMENT_ID` is removed from `.env.example` and from `docs/operations.md`'s env var table.
- [ ] `docs/capabilities.md`'s "GA4 analytics" row says GA4 was removed on this date and PostHog replaces it (keep the event list, which RL-054 reuses). `docs/architecture.md` analytics mention updated.
- [ ] `npm run build` shows no `firebase/analytics` chunk or import in `dist/assets`.
- [ ] A `backlog/QA.md` entry: on the preview build, devtools shows no request to `google-analytics.com` or `googletagmanager.com` and no new `_ga` cookie.

## Out of scope

Consent (RL-052), PostHog (RL-054), and the GA4 property in the Google console (the author may
delete it; not required).

## Verification

`npm run build`, `npm run lint`, `npm test`, then the devtools check.
