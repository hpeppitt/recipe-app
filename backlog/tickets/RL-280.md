## Context

Settled by the author on 2026-10-22: the profile flag defaults from the device time zone at
sign-up (`Intl.DateTimeFormat().resolvedOptions().timeZone`, mapped to a country), and the user
can edit it. The client has no IP geolocation (Spark, no functions; decision 2). `Intl` has no
time zone to country mapping, so a static table is needed: generate it once from the IANA
`zone1970.tab`/`zone.tab` data (each zone's first country code), plus the common
`backward` link names (for example `Australia/ACT`, `US/Eastern`, `Asia/Calcutta`). Commit the
generated table as a plain `Record<string, string>` in `src/lib/timeZoneCountry.ts` with a
comment naming the tzdata release used; no dependency.

## Acceptance criteria

- [x] `countryFromTimeZone(tz: string | undefined): string | null`: the code for a known zone, null for unknown zones, `UTC`, `Etc/*` and undefined.
- [x] `flagEmoji(code: string): string` builds the regional indicator pair; `countryName(code, locale = 'en')` uses `Intl.DisplayNames` with `type: 'region'` and falls back to the code.
- [x] `isCountryCode(v: unknown)`: true only for `^[A-Z]{2}$` codes in the list.
- [x] `COUNTRY_CODES`: every code that appears in the table, sorted by English name, for RL-281's picker.
- [x] Tests: `Australia/Sydney` is AU, `Europe/London` is GB, `America/Los_Angeles` is US, `Asia/Kolkata` and `Asia/Calcutta` are IN, `Pacific/Auckland` is NZ, `UTC` and `Foo/Bar` are null; `flagEmoji('AU')` is "🇦🇺"; `isCountryCode('au')` is false.
- [x] The table file is under 20 KB.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

Table generated from system tzdata 2026e (/usr/share/zoneinfo/zone.tab plus tzdata.zi link lines, 518 zones, 100 links, 14.5 KB). Country names come from Intl.DisplayNames at runtime, no hand-written list. Etc/* and UTC are excluded.
