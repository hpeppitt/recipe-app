## Context

In `LibraryPage.tsx`, `ownRecipes` (line 52) is computed from `recipes`, which
`useRecipeLibrary` has already filtered by the search text. So the Mine chip (around line
140) disappears while it is the active filter as soon as a search matches none of the user's
recipes, and the empty state for `mine` (around line 306) says "You haven't created a
recipe yet" to someone who has.

Separately, the comment above `isOwnRecipe` (line 48) says it is "the same rule
canManageRecipe uses". It is not: `canManageRecipe` (`lib/ownership.ts`) treats every
locally stored recipe as the user's, including saved copies of other people's recipes. Which
rule "Mine" should use is a question for the author (see the grooming report); this ticket
only makes the comment true.

RL-008 later replaces the chip with a My Recipes tab. This fix is cheap and ships first;
RL-008 should keep the "only with no search" rule for its empty state.

## Acceptance criteria

- [ ] Mine chip visibility is computed from the unfiltered own-recipe set (for example a count `useRecipeLibrary` exposes before search filtering), not from the search results.
- [ ] With `filter === 'mine'` and a non-empty search with no matches, the page shows the existing no-results state for a search, not "You haven't created a recipe yet".
- [ ] "You haven't created a recipe yet" appears only when the search is empty and the user has no own recipes.
- [ ] The `isOwnRecipe` comment describes what it actually does and how it differs from `canManageRecipe`. Behaviour unchanged.
- [ ] A `backlog/QA.md` entry: select Mine, type a search matching none of your recipes, confirm the chip stays and the no-results copy shows.

## Out of scope

Changing which recipes count as "Mine", and the tab split (RL-008).
