## Notes

Rules in `firestore.rules` after `notificationPrefs`, with literals `tasteAvoidCap()` 12,
`tasteHiddenCap()` 50 and `tasteTermMax()` 40, tied to `TASTE_AVOID_MAX`, `TASTE_HIDDEN_MAX` and
`TASTE_TERM_MAX` in `src/lib/taste.ts` by a test in `src/lib/taste.test.ts`. Delete uses
`signedIn()` (erasure works if verification lapses), read and writes `verified()`, matching
`notificationPrefs` and `termsAcceptance`. Keys are exact (`hasOnly` plus `hasAll`).

Per-element bounds (revised after review): avoids are sent to Gemini, so `tasteAvoidsOk()`
checks each of the 12 slots by index with `tasteAvoidOk(a, i)`: `a.size() <= i || (a[i] is
string && a[i].size() <= tasteTermMax())`. `hidden` only filters the device's learned terms, so
it keeps the cheap bound: `join('').size()` at most 50 x 40. That bounds the document but not
each element: one 41-character hidden term passes if the total fits, and `join` stringifies a
non-string element instead of failing (both probed, 200, by design). Each hidden term's type and
length is the client's job (RL-231 Notes). Expression cost: the full write (12 avoids x 40, 50
hidden x 40) still commits (200); the avoid checks are about 50 expressions, well under the
1000-per-request limit, and read no documents.
