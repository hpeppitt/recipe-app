## Context

The author picked 14a: "One compact sheet. Photo mode swaps the swatches for Upload and Take
photo plus a circular crop." Markup: `docs/design/organic/export/Collaboration and
Account.dc.html` 14a.

Today `src/components/profile/AvatarEditor.tsx` renders inline on the own profile with a
`SegmentedControl` of three types that map to the profile's `photoType`: `generated`
(initials and colour from the uid), `emoji` (food emoji plus a background hex in
`photoBgColor`), `uploaded` (a 128x128 base64 JPEG, the 100000-character rule in
`docs/data-model.md`). `onSave` writes through `useOwnProfile().updateAvatar`. Only verified
accounts may write a profile (decision 1a); anonymous users get the sign-up prompt instead,
which stays as it is.

**Design token map:** `--color-bg` is `bg-surface`; neutral-700 text is
`text-text-tertiary`; filled terracotta with cream is `bg-primary-600 text-on-accent`.
Light only: no `dark:` classes. 44px targets.

Values to copy, inside `Sheet` (RL-089) with gap 18px:

- A 120px preview, centred: the live `Avatar` for the current draft, at 120px with a
  `font-heading` 52px initial for the generated type.
- A three-way segmented control, full width, segments `flex: 1` centred: "Photo",
  "Initials", "Emoji" (in that order; values `uploaded`, `generated`, `emoji`).
- Emoji mode: a "Colour" label (12px, 600, `text-text-tertiary`, margin-bottom 10px) and a
  row of six 44px swatches spaced between, selected swatch ringed `0 0 0 3px` of the ground
  then `0 0 0 5px` of the text colour; swatches are `#ffe1d0` (accent-200), `#ffc6a5`
  (accent-300), `#e1eecc` (accent-2-200), `#ccdbb2` (accent-2-300), `#dcd3c4`
  (neutral-300), `#f6a06b` (accent-400), stored as those hex values in `photoBgColor`.
  Under it the existing food emoji list as a 5-column grid of square circles,
  `bg-surface-secondary`, selected `bg-accent-200` with a 2px accent ring, emoji 28px.
- Initials mode: no swatches (the generated colour comes from the uid; choosing one would
  be new profile data).
- Photo mode: the existing upload and crop control, as a secondary pill button with the
  `Image` icon, "Upload a photo".
- A full-width primary "Save", 52px. Saving closes the sheet; a failure keeps it open with
  the existing error handling.

The old 12 saturated `BG_COLORS` are replaced by the six above; avatars already saved with an
old hex keep rendering it (no migration).

## Acceptance criteria

- [ ] `AvatarEditor` renders as the content of a `Sheet` with the layout above and keeps its `onSave` contract and upload size limits unchanged.
- [ ] The own profile opens it by tapping the avatar (verified users only; anonymous users still get the existing sign-up prompt). The Settings account row (RL-093) opens it for verified users instead of navigating.
- [ ] Swatches are buttons named "Background <name>" with `aria-pressed`; emoji buttons are named by the emoji and have `aria-pressed`.
- [ ] `AvatarEditor.test.tsx` covers: mode switch shows and hides swatches, choosing an emoji and colour calls `onSave` with `photoType: 'emoji'` and the hex, initials saves `generated`.
- [ ] A `backlog/QA.md` entry: as a verified user on the preview, open the sheet from the profile and from Settings, save an emoji avatar on each new swatch, switch to initials, upload a photo; tap the backdrop to close without saving; check at 320px that six swatches fit.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

"Take photo" (camera capture), a colour choice for initials, the 14b full-screen variant,
the profile page layout (RL-095).
