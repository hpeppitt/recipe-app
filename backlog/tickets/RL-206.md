## Context

Written for RL-193's recommendations: the photo is derived (newest remaining `cookPhotos` doc for
the recipe), never written to the recipe. `RecipeHeader.tsx` (RL-100) draws an original as a
title beside a 76px emoji blob (2a) and a branch with a 230px hero on `accent-200` with floating
44px controls (2b). One extra read per recipe visit.

## Acceptance criteria

- [x] `getRecipePhoto(recipeId)`: `cookPhotos where recipeId == X orderBy createdAt desc limit 1` (add the composite index to `firestore.indexes.json` and `indexes.test.ts` if required, deployed by RL-209), bounded at 6 s, reported as `recipe-photo`; `useRecipePhoto` reads it once per visit.
- [x] Branch: the hero shows the photo with `object-fit: cover` in the washed treatment, controls unchanged, and a 12px credit chip at the bottom left on a translucent ground pill: "Photo by <name>".
- [x] Original: the 76px blob shows the photo cropped to the blob shape, washed, with the credit as 12px `neutral-700` text under the description.
- [x] Alt text: "<recipe title>, cooked by <name>".
- [x] Owner: the More sheet gains "Remove photo" (19a confirm "Remove this photo? It came from <name>'s cook.") which deletes that `cookPhotos` doc; the next one, if any, shows.
- [x] The cook can remove their own photo from the Notes sheet row (RL-199) as "Remove photo".
- [x] No photo, loading or failure: today's emoji layout, no layout shift for originals (reserve nothing; the blob swaps in place).
- [x] Tests for both layouts, credit, owner removal, fallback.
- [x] `docs/capabilities.md` recipe page rows.
- [x] A `backlog/QA.md` entry: a branch and an original with a cook photo at 390px and 1280px, light and dark; the owner removes it; signed out it still shows.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Photos on Explore tiles, search rows and profile tiles (per-tile reads; a later decision). An author-chosen photo.

## Verification

Tests, both reviewers. Human: the QA.md walk.

## Notes

Query cookPhotos where recipeId == X orderBy createdAt desc limit 1; add the composite index (recipeId asc, createdAt desc) to firestore.indexes.json and indexes.test.ts (deployed by RL-209). Skip a photo whose cook no longer exists. Render only in an <img> (never CSS url() or innerHTML).

Done 2026-10-21. `getRecipePhoto(recipeId, knownCooks)` reads `cookPhotos` one doc at a time (limit 1, startAfter, at most 3) (index added, `indexes.test.ts` extended), takes the first whose cook exists (name from the page's cook summary, else one `getDoc`), 6 s bound. `useRecipePhoto` waits for the cook summary, reads once, `refresh` after a removal. Header shows the photo in an `<img>` only. Removal reuses `deleteCookPhoto`. Limits: `/shared/:id` has its own header and is not changed.
