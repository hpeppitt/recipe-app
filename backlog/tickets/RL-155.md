## Context

RL-152 adds the owner-only `notificationPrefs/{uid}` document (`branch`, `suggestion`,
`follow`, `updatedAt`) to the rules in the repo. Notifications are still written for every
event; the preference decides what the recipient sees (decision in RL-152, record the user-facing
effect in `backlog/DECISIONS.md`: switching a type back on shows the old ones again).
`useNotifications` (`src/hooks/useNotifications.ts`) feeds both Activity and the BottomNav unread
badge. Settings is grouped surface cards (`SettingsPage.tsx`, `Group`, `CARD`, `ROW`).

### Design (13a)

A group labelled "Notify me when" (12px semibold `neutral-700`, 6px left) holding a surface card
(radius 28px, padding 4px 16px) with three rows, 15px text, 13px vertical padding, divider
between: "Someone branches my recipe", "I get a suggestion", "Someone follows me". Each has a
switch 44x26, fully round; on: track `accent-2-600`, knob ground 20px at left 21px; off: track
`neutral-400`, knob at left 3px. Shown only to a verified user with Firebase configured.

## Acceptance criteria

- [x] Each switch is a `button role="switch"` with `aria-checked`, its row text as the accessible name, a 44px hit area, focus ring, and a 150ms knob transition under `motion-safe:` only.
- [x] Defaults are all on when no document exists. Toggling writes the whole document (`setDoc`, `updatedAt: serverTimestamp()`), optimistic, reverting with an inline error "Couldn't save that. Try again." on failure. `useNotificationPrefs` subscribes to the owner's document only for a verified user.
- [x] Mapping: branch off hides `branch`; suggestion off hides `suggestion` and `suggestion_reply`; follow off hides `follow`. Outcome types (`suggestion_applied`, `suggestion_branched`, `suggestion_approved`, `suggestion_rejected`) and `favorite` always show. Implemented as a pure `visibleFor(prefs)` in `src/lib/notifications.ts` with tests.
- [x] `useNotifications` applies it, so the Activity list, "Mark all read" visibility and the unread badge count agree.
- [x] Data export (`fetchCloudDataForExport`, `src/lib/dataExport.ts`) gains a `notificationPrefs` section (bump `DATA_EXPORT_VERSION` only if the file contract requires it; say which in the PR), and `scripts/data-request.mjs` exports and erases the document with the rest of the uid's data, with its test updated.
- [x] Tests: toggling writes and reverts on failure; hidden types leave the list and the count; signed-out Settings shows no card.
- [x] `docs/capabilities.md` Notifications row and `docs/data-model.md` updated. `src/content/legal/*` is not edited (see Notes).
- [x] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Push or email notifications. Writer-side suppression. Per-cook bells (profile extras, not v1).
Privacy policy wording (author's sign-off).

## Verification

Gates: tests, `ui-reviewer`, `data-integrity-reviewer`. Human on the emulator at 390px: switch
Someone follows me off, have a second account follow you, the row and badge do not appear;
switch it on, they do. Keyboard and VoiceOver on the switches. Dark theme track contrast.
