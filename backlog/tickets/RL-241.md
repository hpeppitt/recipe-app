## Context

The RL-118 photo path (downscale in the browser, `inlineData` through AI Logic, never stored) is
the model; decision 3's dated notes cover generation-input photos. Receipts can show card digits
and store addresses, so the prompt must return only food item names, and the privacy line comes
in RL-248. Generation path, hence tier hard.

## Acceptance criteria

- [x] `readReceipt(photo)` in `services/gemini.ts`: one request with a schema `{ items: string[] }`, prompt "List only the food and drink items bought, as short plain names, no prices, brands, quantities or any other text", bounded at 30 s.
- [x] The add field's placeholder becomes "Add things, or snap a receipt…" with a 40px `Camera` button; after reading, a sheet lists the items as ticked chips to confirm, with "Add N to the pantry".
- [x] The photo is held only in memory, never in Dexie, Firestore, analytics or telemetry (test).
- [x] Gated like generation (`canGenerate`); errors "Couldn't read that receipt. Try a clearer photo."
- [x] Tests and docs (`capabilities.md` Pantry row, `architecture.md` AI path).
- [x] A `backlog/QA.md` entry: snap a real receipt; only food items appear; nothing personal.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Prices or quantities.

## Verification

Tests, both reviewers. Human: the live check.

## Notes

- 2026-10-21 implementer: `readReceipt` in `services/gemini.ts` (schema in `schemas/receipt.responseSchema.ts`), prompt, Zod validator and normalising in `lib/receipt.ts` (drops names with a digit in any script, `@`, `*`, `#`, `+`, no letters or more than six words, trims, caps at `ITEM_NAME_MAX`, dedupes by `itemKey`, max 40), `components/kitchen/ReceiptSheet.tsx`, camera button on `PantryPage`. The prompt lives in `lib/receipt.ts` rather than `lib/prompts.ts` so the receipt logic sits together. The camera is 40px visual with a 44px hit area, `aria-disabled` while reading (keeps focus, so the sheet returns it) and `disabled` during a kitchen write. Items already in the pantry are filtered out before the sheet; all-duplicates says so instead of opening an empty sheet. A failed read is reported (redacted) as `read-receipt`; an empty list throws the same message but is not reported.
