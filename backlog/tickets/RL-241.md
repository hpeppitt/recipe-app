## Context

The RL-118 photo path (downscale in the browser, `inlineData` through AI Logic, never stored) is
the model; decision 3's dated notes cover generation-input photos. Receipts can show card digits
and store addresses, so the prompt must return only food item names, and the privacy line comes
in RL-248. Generation path, hence tier hard.

## Acceptance criteria

- [ ] `readReceipt(photo)` in `services/gemini.ts`: one request with a schema `{ items: string[] }`, prompt "List only the food and drink items bought, as short plain names, no prices, brands, quantities or any other text", bounded at 30 s.
- [ ] The add field's placeholder becomes "Add things, or snap a receipt…" with a 40px `Camera` button; after reading, a sheet lists the items as ticked chips to confirm, with "Add N to the pantry".
- [ ] The photo is held only in memory, never in Dexie, Firestore, analytics or telemetry (test).
- [ ] Gated like generation (`canGenerate`); errors "Couldn't read that receipt. Try a clearer photo."
- [ ] Tests and docs (`capabilities.md` Pantry row, `architecture.md` AI path).
- [ ] A `backlog/QA.md` entry: snap a real receipt; only food items appear; nothing personal.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Prices or quantities.

## Verification

Tests, both reviewers. Human: the live check.
