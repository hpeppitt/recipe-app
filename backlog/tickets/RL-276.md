## Context

`lib/createPrompt.ts` holds three cycling slots (`CREATE_OPTIONS`, `cycleWord`,
`buildCreatePrompt`). The author wants buttons that add another ingredient (cycling through
vegetables), a time, and a cooking method. Pure logic first; RL-277 adds the buttons.

Options (groomer's choice, logged in `backlog/DECISIONS.md` by RL-277):

- Extra ingredient: spinach, peppers, courgette, broccoli, sweet potato, carrots (mushrooms is
  already a main option, so it is not repeated).
- Time: "in 15 minutes", "in 30 minutes", "in an hour".
- Method: "on the stove", "in the oven", "in the air fryer", "in the pressure cooker"
  (the author's list).

Sentence shape: "something {quick} with {chickpeas}[ and {spinach}][ {in the oven}][, ready
{in 30 minutes}] for {two}". `buildCreatePrompt` builds the same order, then the RL-235 terms.

## Acceptance criteria

- [x] The selection type gains three optional slots (`veg`, `time`, `method`), each `number | null`, null meaning not added; the three existing slots behave as before.
- [x] `addSlot`, `removeSlot` and `cycleWord` work on the new slots (cycling wraps).
- [x] `selectedWords` and `buildCreatePrompt` produce the sentence shape above; with no extra slots the output is byte-identical to today's.
- [x] `createTerms` drops the learned "under 30 min" term when a time slot is added, so the prompt never has two times.
- [x] Tests for each slot, combinations, wrap-around, and the unchanged default.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

## Notes

Selection stays a tuple; slots 3 to 5 (veg, time, method) are optional elements, so existing `[0,0,0]` callers compile unchanged. `addSlot`, `removeSlot` and `cycleWord` handle them (cycling an unset slot starts at option 0). `createTerms` takes a third arg `hasTimeSlot` that drops "under 30 min"; RL-277 must pass `selection[4] != null`. Time words are phrased "in 15 minutes" so the sentence reads "ready in 15 minutes".
