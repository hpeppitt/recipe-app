## Context

Written for RL-184's recommended answers; regroom if the author chose otherwise. RL-185 reads
the page. Saving must follow the cloud-first sequence of a chat save (decision 1b, RL-082:
`buildRecipe` in `db/recipes.ts`, `publishRecipe` bounded at 4 s with `withTimeout`, then
`cacheRecipe`; a failed publish writes nothing). Extract that sequence from
`useRecipeChat.ts` (~355-395) into a shared helper rather than copying it, and keep the chat's
behaviour byte-for-byte. `/import` is gated like `/create` (`canGenerate`; others see the
sign-up call to action). Dedup uses the same search as the chat (`searchSimilarRecipes` scoring
with the RL-178 cached window if available) and `matchKind` (RL-177).

### The design (the implementer has no other copy)

- Header: close button (44px, `X`, name "Close") and "Add from a link" (Caprasimo 22px).
- A URL pill (52px, `bg-neutral-100`, `shadow-sm`, `Link` icon, placeholder "Paste a recipe
  link") with a primary "Read it" button inside at the right (40px, accent, Caprasimo 13px).
  Paste into an empty field reads automatically.
- Reading: a skeleton card with "Reading the page…" (13px `accent-700`, `Sparkles`).
- Preview card on `bg-surface-secondary`, 30px radius, padding 16px: 56px emoji circle, title
  Caprasimo 20px, "9 ingredients · 6 steps · 35 min" 13px `neutral-700`, and the host as a 12px
  tag "seriouseats.com". When `uncertainCount > 0`: a line on `bg-accent-100` "One amount was
  unclear. You can fix it after saving." (or "N amounts").
- Dedup notice when a match is `same`: a sage card (`bg-accent-2-100`, 24px radius) "There's
  already a <Title> family with N versions", the match's `UserPill`, and two buttons stacked:
  primary "Add to <Title> family" and ghost "Save as a new original". Without a same match:
  only primary "Save as a new original".
- Errors: the RL-185 message inline under the pill, with the field kept.

## Notes

- Shared save helper: `publishThenCache(recipe, onPublished?)` in `src/services/recipeSave.ts` (publish bounded at 4 s, then `cacheRecipe`; resolves to the error to show or null). The chat calls it with `notifyBranched` as `onPublished`, so the notify still fires between publish and cache; the chat tests pass unchanged. `searchSimilarRecipes` is now exported from `useRecipeChat.ts` and reused by the import with `readPublishedWindow` (the RL-178 cached window).
- The family is named by its original when that row is on the device or in the window (a branch match would otherwise name it by the branch), with the original's author for the UserPill. The dedup check is bounded at 4 s; a failure or timeout hides the notice.
- The saved recipe drops each ingredient's `uncertain` flag (the null amount is what stays editable) and stores `importedFrom`, `importedVia` and `chatHistory: []`. A retry after a failed publish reuses the built record's id, as the chat does.
- `ImportedRecipeSchema` (export-file restore) now keeps `importedFrom` and `importedVia`, using one `ImportedFromSchema` (http(s), max 2048, bad value dropped) shared with `lib/share.ts`. `toLocalRecipe` (own-recipe sync) also keeps both; without it the sync would strip them from the Dexie copy right after the save.
- Firestore rules: the recipe create has no key whitelist. On review, `hasBoundedContent` gained an `importedFrom` bound (absent, null, or a string <= 2048 matching `https?://.*`); in the repo, undeployed, not emulator-checked. Published reads (`withBoundedImportedFrom`) and the own-recipe sync apply the same bound client side.
- Review fixes: Add to family notifies the original's author like the chat (only when the root row was found, never yourself); `publishThenCache` catches a throwing `onPublished` (reported as `save-recipe-notify`) so the cache still runs, which also applies to the chat's notify. Page a11y: readOnly field while busy, focus to the preview title and back to the failed save button, a persistent status line, paste fills the field and reads, Saving… with a spinner, editing clears the preview, PageFallback while auth loads.
- The sign-up gate markup is a copy of the chat's, not a shared component, to keep the chat page untouched.
