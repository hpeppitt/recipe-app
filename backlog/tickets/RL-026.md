## Context

`useFollowers` in `hooks/useFollow.ts` is the pattern to copy: state stamped with the key it
belongs to, a `cancelled` flag, and a `.catch` that reports and settles. Its neighbours do
none of that:

- `useFollow` (lines 22-45): the lookup has no catch or cancel and is never reset when
  `targetUid` changes, so "Following" from profile A shows on profile B until B's lookup
  returns. `toggle` has no catch, so a failed follow is an unhandled rejection with no
  feedback.
- `useCloudFavorite` (`hooks/useFavorites.ts` lines 119-156): the same three problems.
- `useFollowingList` (`useFollow.ts` lines 96-111): no catch, so a failure leaves
  `isLoading` true forever; no cancel.
- `useUserRecipes` and `useFollowingRecipes` (`hooks/useUserRecipes.ts` lines 47-98): no
  cancel, so profile A's late response renders under profile B.
- `useFavoriteIds` (`useFavorites.ts` line 28) builds a new `Set` every render, which
  defeats the `useMemo` in `useRecipeLibrary` that depends on it.

RL-041 changes what these hooks do for anonymous users (local bookmark only, follow routes to
sign-up) and lands first. The hygiene below then applies to the verified-user cloud paths
that remain.

## Acceptance criteria

- [ ] `useFollow` and `useCloudFavorite` keep their lookup result keyed by `uid:targetId`, derive `false` when the key does not match the current one, ignore responses after cleanup, and on lookup failure call `reportError` and settle as not following / not favourited.
- [ ] Both toggles catch failures, call `reportError`, leave the previous state in place, and expose an `error` string that clears on the next toggle and on id change.
- [ ] `ProfilePage` shows the follow error inline under the Follow button and `SharedRecipePage` shows the favourite error inline near the favourite control, in existing secondary text styles. Copy: "Couldn't update that. Check your connection and try again."
- [ ] `useFollowingList`, `useUserRecipes` and `useFollowingRecipes` use a `cancelled` flag and, where missing, a `.catch` that reports and settles `isLoading` to false.
- [ ] `useFavoriteIds` memoises the `Set` on the `favorites` array.
- [ ] No `setState` runs synchronously in an effect body (the lint rule `useFollowers` was written around).

## Out of scope

`useRecipeLibrary` (RL-027), the N+1 reads in the same hooks (RL-029), and the local
`useFavorite` hook, which already handles failures.
