## Context

The author decided on 2026-10-22 to follow Firebase's guidance of one Firebase project per
environment: the local emulators, then a dev project, then production (`recipe-lab-3832b`).
Every merge to `main` will deploy to dev (RL-297) and a release tag will deploy to production
after approval (RL-298). This ticket is the console work only a human can do: an agent cannot
create projects, providers or keys. A staging project is out of scope for now; it can be added
later as a third Firebase project and GitHub Environment with the same workflow.

The dev project must behave like production, so it copies production's settings: Firestore
region, sign-in methods (`src/services/firebase.ts`: anonymous, email link, Google),
Firebase AI Logic on the Gemini Developer API (`src/services/gemini.ts` uses
`GoogleAIBackend`), and App Check with a reCAPTCHA v3 site key enforced on AI Logic
(`docs/operations.md`, "Environment variables"). It stays on the free Spark plan, like
production: Blaze is not needed for anything here.

The production Firestore region is not recorded anywhere in the repo (`firebase.json` has no
location; the only region in the code is the undeployed `functions/` at `us-central1`), so the
first step reads it.

## Acceptance criteria

Click by click. Tick each box as you go and write the values asked for in Notes.

**1. Read the production region**
- [ ] Firebase console, project `recipe-lab-3832b`, Build, Firestore Database. The database
  list (or the panel above the Data tab) shows the location, for example `nam5` or
  `europe-west2`. Or run
  `gcloud firestore databases describe --database='(default)' --project recipe-lab-3832b --format='value(locationId)'`.
  Write it in Notes.

**2. Create the project**
- [ ] console.firebase.google.com, Create a project. Name `recipe-lab-dev`. Under the name,
  check the project id it proposes; edit it to `recipe-lab-dev` if that is free, otherwise
  accept the suffixed one. Write the final id in Notes: every later ticket calls it `<dev-id>`.
- [ ] Google Analytics for this project: off. Create project.
- [ ] Leave the plan on Spark (no billing account).

**3. Add the web app**
- [ ] Project overview, Add app, Web (`</>`). Nickname `Recipe Lab dev`. Tick "Also set up
  Firebase Hosting for this app". Register app.
- [ ] Copy `apiKey`, `authDomain`, `projectId` and `appId` from the config shown into a
  private note (not the repo). They are public identifiers, but they go into GitHub variables
  in RL-293, not into any file. Skip the CLI install and deploy steps the wizard shows.

**4. Firestore**
- [ ] Build, Firestore Database, Create database. Edition: Standard if asked. Location: the
  same value as step 1 (it cannot be changed later). Start in production mode (deny all; the
  pipeline deploys the real rules). Create.

**5. Authentication**
- [ ] Build, Authentication, Get started.
- [ ] Sign-in method, Email/Password: Enable, and also enable "Email link (passwordless
  sign-in)". Save.
- [ ] Sign-in method, Anonymous: Enable. Save.
- [ ] Sign-in method, Google: Enable, choose a support email, Save. (Recommended on dev so
  RL-188's button can be tested without touching production; skip if not wanted and leave
  `VITE_ENABLE_GOOGLE_SIGNIN` unset for dev in RL-293.)
- [ ] Settings, Authorized domains: confirm `localhost`, `<dev-id>.firebaseapp.com` and
  `<dev-id>.web.app` are listed. Add any that are missing.

**6. Firebase AI Logic**
- [ ] Build, AI Logic, Get started. Choose the **Gemini Developer API** (not Vertex AI, which
  needs Blaze). Let it enable the APIs and create the key; the key stays server-side and is
  never copied anywhere.

**7. reCAPTCHA key for App Check**
- [ ] google.com/recaptcha/admin/create. Label `recipe-lab-dev`. Type: Score based (v3).
  Domains: `<dev-id>.web.app` and `<dev-id>.firebaseapp.com`. Submit.
- [ ] Copy the **site key** to the private note (it becomes `VITE_RECAPTCHA_SITE_KEY` for dev).
  Keep the **secret key** for the next step only.

**8. App Check**
- [ ] Build, App Check, Apps tab, the `Recipe Lab dev` web app, reCAPTCHA. Paste the secret
  key. Save.
- [ ] APIs tab: Firebase AI Logic, Enforce (production enforces it). Leave Cloud Firestore
  unenforced, as in production until RL-050.
- [ ] Apps tab, the web app's menu, Manage debug tokens, Add debug token, name it after your
  machine. Keep the value for a local `.env` that points at dev (`VITE_APPCHECK_DEBUG_TOKEN`).

**9. Hosting**
- [ ] Build, Hosting, Get started, click through to the end without running any command. The
  default site `<dev-id>` now exists for the pipeline to deploy to.

**10. Record**
- [ ] Notes below hold the dev project id, the production region and the dev region (equal),
  and whether Google sign-in was enabled on dev.
