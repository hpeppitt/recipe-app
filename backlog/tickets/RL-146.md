## Context

Editing `firestore.rules` in the repo is reversible; deploying it is not and is RL-156. Today
(`firestore.rules` ~219-264): suggestion create requires `status == 'pending'`, the real
`recipeOwnerId` and a moved write window; update is owner only, `changedKeys().hasOnly(['status'])`,
new status `in ['approved', 'rejected']`. Notification create (~296-320) allows types
`favorite`, `follow`, `suggestion`, `suggestion_reply`, `suggestion_approved`,
`suggestion_rejected` with a fixed key set. The model is RL-145 (`SuggestionEdit`). Rules cannot
loop over a list, so edits are capped at 10 and checked by explicit index.

## Acceptance criteria

- [ ] Suggestion create: if `edits` is present it is a list of 1 to 10 items, each passing `validEdit(e)`: a map whose keys are only `kind`, `index`, `name`, `from`, `to`, `why`; `kind in ['ingredient','step','general']`; `from` string ≤ 500; `to` string 1 to 1000; optional `index` int 0 to 99; optional `name` string ≤ 200; optional `why` string ≤ 200. Implemented as `edits.size() <= i || validEdit(edits[i])` for i = 0..9. Everything else about create is unchanged.
- [ ] Suggestion update by the recipe owner: allowed only when `resource.data.status == 'pending'`, `changedKeys().hasOnly(['status', 'branchId'])`, and either the new status is `'rejected'` or `'applied'` with no `branchId`, or it is `'branched'` with a string `branchId` whose recipe exists, has `parentId == resource.data.recipeId` and `createdBy.uid == request.auth.uid` (one `get()`). `'approved'` is no longer writable. Closed suggestions cannot change.
- [ ] Notification create: types `suggestion_applied` and `suggestion_branched` join the message-allowed list; nothing else changes.
- [ ] `MAX_EDITS = 10` and the size caps are exported from `src/lib/suggestion.ts` and a test reads `firestore.rules?raw` (as `rateLimit.test.ts` does) to check the numbers match; a test in `notifications.test.ts` checks every `AppNotification['type']` the client knows appears in the rules' type lists.
- [ ] Probed on the emulator per docs/agent-workflow.md (`firebase emulators:exec`, scratchpad REST script, unsigned `email_verified` tokens). Record real status codes in Notes for: create with 1 and 10 valid edits (200), 11 edits (403), an edit with an extra key (403), bad kind (403); owner pending to rejected, applied (200); branched with a real child branch (200), with another recipe's id (403); non-owner update (403); applied to rejected (403); approved (403); the two new notification types (200).
- [ ] `docs/data-model.md` "What the rules permit" describes the new create and update rules and notification types, and says they are in the repo, deployed by RL-156.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
