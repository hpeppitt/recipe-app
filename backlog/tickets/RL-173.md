## Context

`ProfilePage` has Started / Grew tabs over `RecipeTileGrid` (4c tiles). RL-172 records
`collaboratorUids`. One query, `where('collaboratorUids', 'array-contains', uid)`, is served by
the automatic single-field index (no composite index because there is no `orderBy`; sort by
`createdAt` on the client). `recipes` reads are public, so no rules change.

## Acceptance criteria

- [ ] `getCollabRecipes(uid, max = 50)` in `services/firestore.ts` and `useCollabRecipes(uid)` (bounded at 6 s, reported as `collab-recipes`, read once per profile visit), newest first, excluding recipes the person owns.
- [ ] A third tab "Collabs" (tab labels become "Started N", "Grew N", "Collabs N" when counts are known, as in 4a's "Originals N / Branches N / Collabs N") on the own and other profiles, same tile grid; a tile shows the recipe's owner as a `UserPill` under the title.
- [ ] Empty: "No collabs yet" with one line "Recipes where their suggestion was applied show up here." (own profile: "your suggestion"). Error: the 19a error pattern with Try again. Local-only mode hides the tab.
- [ ] Tabs keep `role="tablist"` semantics and arrow-key movement.
- [ ] Tests for the hook and the tab states.
- [ ] `docs/capabilities.md` Profiles row; `docs/data-model.md` adds the query to the read-cost notes (one read per recipe returned).
- [ ] A `backlog/QA.md` entry: with two verified accounts on the emulator or live, apply A's suggestion on B's recipe, then A's profile Collabs shows it.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Branches kept for a suggester by the owner showing anywhere else. Forest (RL-175).
