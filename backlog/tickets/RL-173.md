## Context

`ProfilePage` has Started / Grew tabs over `RecipeTileGrid` (4c tiles). RL-172 records
`collaboratorUids`. One query, `where('collaboratorUids', 'array-contains', uid)`, is served by
the automatic single-field index (no composite index because there is no `orderBy`; sort by
`createdAt` on the client). `recipes` reads are public, so no rules change.

## Acceptance criteria

- [x] `getCollabRecipes(uid, max = 50)` in `services/firestore.ts` and `useCollabRecipes(uid)` (bounded at 6 s, reported as `collab-recipes`, read once per profile visit), newest first, excluding recipes the person owns.
- [x] A third tab "Collabs" (tab labels become "Started N", "Grew N", "Collabs N" when counts are known, as in 4a's "Originals N / Branches N / Collabs N") on the own and other profiles, same tile grid; a tile shows the recipe's owner as a `UserPill` under the title.
- [x] Empty: "No collabs yet" with one line "Recipes where their suggestion was applied show up here." (own profile: "your suggestion"). Error: the 19a error pattern with Try again. Local-only mode hides the tab.
- [x] Tabs keep `role="tablist"` semantics and arrow-key movement.
- [x] Tests for the hook and the tab states.
- [x] `docs/capabilities.md` Profiles row; `docs/data-model.md` adds the query to the read-cost notes (one read per recipe returned).
- [x] A `backlog/QA.md` entry: with two verified accounts on the emulator or live, apply A's suggestion on B's recipe, then A's profile Collabs shows it.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Branches kept for a suggester by the owner showing anywhere else. Forest (RL-175).

## Notes

- 2026-10-21 (from RL-172 review): render `collaboratorUids` defensively and treat a non-array as empty. The rules bound (a list of at most 50) is in the repo only until RL-156 or RL-160 deploys, and older recipes lack the field.
- 2026-10-21 (RL-173 implementer): `collaboratorUids` is never rendered; the query only matches docs where it is an array, and the hook treats any non-array result as an error rather than empty. Tablist criterion: the premise was wrong, the profile tabs are a `SegmentedControl` radiogroup, not a tablist. It is now keyboard-complete per the ARIA radiogroup pattern (roving tabindex, arrows/Home/End move and select), which is what ticks the criterion. Review fixes: reads only when Collabs is first opened, 5 min per-uid cache, `limit(51)` with a "50+" label and "Showing the first 50." line, live region, compact EmptyState icon sizing fixed for all callers. Owned recipes are dropped after the read, so they can use some of the 50 limit.
