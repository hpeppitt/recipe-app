## Context

Product decision 5 keeps "Delete Recipes on This Device" local only (`clearAllRecipes` in
`src/db/recipes.ts`). Its helper text and confirm dialog in `src/pages/SettingsPage.tsx`
say shared recipes stay in the shared library and that the delete "cannot be undone". After
RL-078 a verified user's own recipes come back from their account the next time the app
opens, so for them "cannot be undone" is false. This is copy about where data is kept, so
the wording below is the author's to approve at /groom; approving this ticket approves it.
RL-076 adds the dated note on decision 5 that points here.

## Acceptance criteria

- [x] For a verified user (`user.emailVerified`, Firebase configured), the helper text under the button reads: "Recipes saved to your account stay there and load again the next time you open the app. To remove one for good, delete it from its own page."
- [x] For a verified user, the confirm dialog message reads: "This deletes all recipes, variations and favourites stored on this device. Recipes saved to your account stay there and load again the next time you open the app."
- [x] Everyone else (anonymous, signed out, local-only) sees today's text unchanged.
- [x] `SettingsPage.test.tsx` covers both variants.
- [x] `docs/capabilities.md` "Delete Recipes on This Device" row says a verified user's account recipes reload.
- [x] A `backlog/QA.md` entry: as a verified user on the preview, read the helper text and dialog at 390 px in both themes, confirm, reload, and see the account recipes return.
- [x] `npm run build`, `npm run lint` and `npm test` pass.

## Out of scope

Changing what the control deletes, removing it for verified users, or clearing Dexie on
