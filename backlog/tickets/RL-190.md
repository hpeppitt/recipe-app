## Context

Policies live in `src/content/legal/` (RL-044, signed off in RL-046). RL-120 is the precedent:
the agent drafts the change, the author signs the wording before `/release`. Bumping
`TERMS_VERSION` (`src/lib/legal.ts`, tied to the rules literal by `legal.test.ts`) would make
every contributor re-accept and needs a rules deploy, so do not bump it unless the author says
so in RL-184 or RL-187.

## Acceptance criteria

- [ ] Privacy Policy: Google is listed as a sign-in option and processor (what Google sends: name, email, profile photo URL; what is kept: email and display name only), in the same style as the existing processor entries; `lastUpdated` changed.
- [ ] Privacy Policy: link import sends the URL to Google Gemini to read the page; the URL is stored on the recipe as its source.
- [ ] Terms: importers must have the right to share what they import; the source link stays on the recipe and credits the original.
- [ ] No `TERMS_VERSION` change unless an RL-184/RL-187 answer says otherwise.
- [ ] A `backlog/QA.md` entry: "Author: sign off the Google and import wording in /privacy and /terms before release."
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Any other policy change.
