## Context

Organic has no dark palette. The app supports light, dark and system
(`src/hooks/useTheme.ts`, persisted by `getTheme`/`setTheme` in `src/services/storage.ts`,
chosen in `SettingsPage` through a `SegmentedControl` labelled "Theme"), with about 66
`dark:` classes in 27 files. After RL-062, dark mode shows the old dark grey surfaces with
the terracotta `primary` ramp: legible, not designed.

**Blocked on an author decision; this ticket is not executable until one option is
chosen and the other deleted at grooming.** The screen tickets (RL-067, RL-068, RL-070,
RL-072, RL-073, RL-075) depend on this one because the answer decides whether they write
`dark:` classes at all.

## Acceptance criteria

### If (a) light-only, toggle hidden

- [ ] `useTheme` always removes the `dark` class, whatever is stored. The stored preference is **not** deleted (so restoring dark later needs no migration), and `getTheme`/`setTheme` are unchanged.
- [ ] The Theme row in `SettingsPage` is not rendered. `SettingsPage.test.tsx` asserts it is absent.
- [ ] `index.html` keeps one `theme-color` meta, `#f5ead8`, with no media query.
- [ ] Existing `dark:` classes stay in place, inert (removing them is churn with no user effect; a later dark Organic reuses the structure). New UI after this ticket writes no `dark:` classes.
- [ ] `docs/capabilities.md` Theme row: "partial: light only since RL-065; dark returns with a dark Organic design". `docs/decisions.md` entry with the reason and the alternative (b).

### If (b) temporary dark Organic mapping

- [ ] The `.dark` block in `src/index.css` maps: `surface` `#201e1d`, `surface-secondary` `#2e2b25` (neutral-900), `surface-tertiary` `#474238` (neutral-800), `text-primary` `#f9f4ed` (neutral-100), `text-secondary` `#dcd3c4` (neutral-300), `text-tertiary` `#c0b6a5` (neutral-400), `border` `#474238`, `border-strong` `#645c50`. Measured at grooming: text-tertiary is 8.28 / 7.04 / 4.98:1 on the three dark surfaces; `primary-400` (accent-500) link text is 5.53 / 4.70 / 3.32:1, so dark links on `surface-tertiary` use `primary-300` (4.83:1) instead.
- [ ] Dark `theme-color` meta is `#201e1d`.
- [ ] New UI after this ticket gives every raw `accent-*`, `accent-2-*` or `neutral-*` background a `dark:` counterpart from the tokens above.
- [ ] `docs/capabilities.md` Theme row says dark is a temporary mapping; `docs/decisions.md` entry with the reason and the alternative (a).

### Either way

- [ ] A `backlog/QA.md` entry: in Settings, the theme control behaves as decided; with the OS in dark mode, the app looks as decided on Library, a recipe and the version tree.

## Out of scope

- A designed dark Organic palette (design work, brief ticket 8).
- Removing the 66 existing `dark:` classes.

## Verification

`npm test` (the Settings test), `npm run build`, `npm run lint`; `ui-reviewer`. A human
checks with the OS set to dark (QA.md).
