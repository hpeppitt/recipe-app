## Context

**This ticket reverses a recorded product decision and must not run until the author approves
that exact change at `/groom`.** `docs/decisions.md`, "Light only until a dark Organic exists
(RL-065, 2026-10-18)": the app is light only, the Theme control is removed, `useTheme` always
removes the `dark` class, the stored preference is kept, and about 66 `dark:` classes stay
inert. A dark Organic design now exists (20a), which is the condition that decision named. If
approved, set `status: ready` and name the approval in Notes; otherwise `dropped`. It depends
on every layout ticket so the dark mapping is tested once against final screens.

Spec (`docs/design/organic/export/App Spec.dc.html`, "Dark Organic (20a)"): "Set on
[data-theme="dark"]. Base roles change; every 100 to 900 ramp is reversed (100 ↔ 900), so
"tint fill + 800 text" pairs keep working unchanged." Tokens (Light then Dark):

| Token | Light | Dark |
|---|---|---|
| `--color-bg` (`surface`) | #f5ead8 | #1e1915 |
| `--color-surface` (`surface-secondary`) | #ebddc5 | #2b241e |
| `--color-text` (`text-primary`) | #201e1d | #f3e8d6 |
| `--color-accent` | #c67139 | #e8925a |
| `--color-accent-2` | #7a8a5e | #aebf92 |
| `--color-divider` | ink 16% | cream 14% (`rgba(243,232,214,.14)`) |
| `--color-*-N00` ramps | step N | step 10 minus N |
| `neutral-100` / `neutral-200` | #f9f4ed / #eee7db | #2a2520 / #332c25 (set by hand) |
| `--shadow-*` | ink 14 to 22% | black 40 to 55% |

Muted text in 20a is #b6a994. Settings in 13a shows the Appearance segment "Light / Dark /
System". The app's dark variant is class based (`.dark, .dark *`), so either apply the class
or switch the variant to `[data-theme="dark"]`; pick one and remove the other.

Known traps to check by measurement, not by eye:

- `primary-600` is accent-700 for AA on cream (RL-062). Flipped, accent-700 becomes
  accent-300 (#ffc6a5), and cream `on-accent` text on it fails. Dark needs its own
  `on-accent` (dark ink) or a different primary mapping; every primary button, badge and
  user bubble must reach 4.5:1.
- RL-075's QA note: two of the three carousel card tints are light-only with themed text;
  pin the text colour on those tints.
- The old `.dark` block in `src/index.css` holds pre-Organic greys; replace it, and remove or
  rewrite the inert `dark:` classes that would now fire with the wrong colours.
- `index.html` has one `theme-color` (#f5ead8); add the dark value with a media query or set
  it from `useTheme`.

Implemented 2026-10-19. The approval above is recorded in `docs/decisions.md` ("Dark Organic is back, Warm night 20a"), which supersedes the RL-065 entry. Class-based `dark` variant kept. `.dark` in `src/index.css` replaces the pre-Organic greys with 20a: base roles, flipped neutral, accent and accent-2 ramps (neutral-100/200 by hand), flipped danger/success/warning scales, divider, shadows (through new `--shadow-ink-*` variables, since Tailwind inlines `--shadow-*`), `color-scheme: dark`. Dark-only overrides, logged in `backlog/DECISIONS.md`: primary-600/700/800 = accent / accent-600 / accent-700 with `on-accent` `#1e1915`; `text-tertiary` `#bfb29d` (20a's `#b6a994` fails on two tints); `text-secondary` `#dcd3c4`. `useTheme` applies light, dark or system again, always listens to the OS and reads the store, and sets `theme-color`; `index.html` applies the class and `theme-color` before first paint. Settings' Appearance card has the Theme segment (Light / Dark / System), tested in `SettingsPage.test.tsx` and `useTheme.test.tsx`. Every old `dark:` class (22, in 8 files) was the flip done by hand and is removed; two `text-white` on primary fills became `text-on-accent`; dialog and sheet scrims get `dark:backdrop:bg-black/60` (`neutral-900` flips to cream). The grep for hex and `rgb(` in `src` found only the avatar swatches and `uidToColor` (theme independent) and the image downscale canvas fill; the tree, map and timeline SVGs use token variables only.

Fix round: `Button` danger gets `dark:text-on-accent` (white on dark danger-600 was 2.77:1; ink 6.30:1, hover on danger-500 4.63:1), with a test. `useTheme` guards a missing `matchMedia` and falls back to `addListener`/`removeListener`, with tests for that and for removal on unmount. `TermsUpdateDialog` keeps Tailwind's `shadow-xl`: swapping to the themed `shadow-lg` would change light, so it is noted in QA.md instead.
