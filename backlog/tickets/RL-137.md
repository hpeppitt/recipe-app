## Context

In the chat (`RecipeChatPage.tsx`, RL-111) each assistant reply is a `RecipeCardMessage` whose
Save button lives inside the card (~130). The newest card is expanded by default and the user
can collapse it (`toggled[i]`, `expanded={toggled[i] ?? i === lastAssistantIdx}` ~387); once
collapsed, Save is easy to miss. Punch list: "Pin a compact Save in the composer row while the
card is collapsed." The composer is `ChatInput` in the sticky footer (~525-560).

## Acceptance criteria

- [x] When the newest assistant card is collapsed, nothing is loading and `latestRecipe` exists, a compact Save shows at the start of the composer row: a 44px tall primary pill (`bg-primary-600`, `text-on-accent`, 14px heading font, padding 0 16px, `Bookmark` icon then "Save"), left of the input pill. `ChatInput` takes an optional `leading?: ReactNode` slot for it; nothing else in `ChatInput` changes.
- [x] It calls the same `saveRecipe` the newest card's Save calls (same recipe, same `promptFor(messages, lastAssistantIdx)` prompt), is disabled while `isSaving`, and its accessible name is the card's label ("Save Recipe" or "Save Variation").
- [x] It disappears when the card is expanded again, while generating, and once the page navigates after a save.
- [x] Tests: collapse the newest card, the compact Save appears and saving calls the save path once; expanded, it is absent; while loading, it is absent.
- [x] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

The card itself, refinement chips, the dedup panel, the header (the 6a canvas also draws a Save
in the header; not asked for).

## Verification

Gates: tests, `ui-reviewer`. Human at 320 and 390px: generate, collapse the card, the Save sits
left of the input without squeezing it below a usable width (check 320px with the keyboard
open), tap it and land on the saved recipe.

## Notes

Compact Save passed through a new optional `leading` slot on ChatInput (the composer row is now a wrapper flex with the slot plus the unchanged pill). It saves messages[lastAssistantIdx].recipe, the same recipe the card saves, not latestRecipe, which can be stale after a failed refinement.
