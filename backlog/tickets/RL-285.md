## Context

Written to RL-284's decisions (author, 2026-10-22). Follow `cookPhotos`
(`isWellFormedCookPhoto`: fixed keys, JPEG data URL regex, 200000-character cap,
`createdAt == request.time`) and the write window pattern (`capFor`, `windowMsFor`,
`movedWindow`, and the writeWindows read rule's id list; "Suggestions and replies are
rate-limited in the rules alone" in `docs/decisions.md`). `rateLimit.test.ts` reads the rules
file and fails if the caps disagree. Deployed by RL-291.

## Acceptance criteria

- [ ] `match /feedback/{feedbackId}`: create if `verified()`, keys exactly `uid, displayName, note, path, appVersion, viewport, theme, userAgent, screenshot, createdAt`; `uid == request.auth.uid`; `displayName` null or string of at most 100; `note` matches `(?s).{1,1000}`; `path` string of at most 300 starting with `/`; `appVersion` at most 40; `viewport` at most 20; `theme` `'light'` or `'dark'`; `userAgent` at most 400; `screenshot` null or a `data:image/jpeg;base64,` string of at most 200000; `createdAt == request.time`; `movedWindow('feedback', 'feedback/' + feedbackId)`.
- [ ] Read (get and list) only when `resource.data.uid == request.auth.uid`; update and delete denied to clients.
- [ ] `feedbackCap()` is 10 on the day window; `capFor`, `windowMsFor` and the writeWindows id list include `feedback`; `FEEDBACK_CAP` and `RATE_LIMITS.feedback` in `lib/rateLimit.ts` match and the test passes.
- [ ] Emulator probes recorded in Notes: a valid create with and without a screenshot; an extra key, a 1001-character note, a PNG data URL and a 200001-character screenshot denied; the eleventh in a day denied; another user's get denied.
- [ ] `docs/data-model.md` gains the `feedback` row, "in the repo, deployed by RL-291".
- [ ] `npm test`, `npm run lint`, `npm run build` pass.
