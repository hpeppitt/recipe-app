## Context

Written for RL-187's recommendations; regroom if the author chose otherwise. Auth tier: the
email-link completion order (decisions.md 2026-08-07) and the terms recording (RL-047) must be
kept for both paths. The Auth emulator supports the Google provider with fake accounts, so the
whole flow is testable before RL-191 enables it live. Until RL-191 is done, this must not be
released (the button would fail live): say so in QA.md.

### The design (the implementer has no other copy)

In the sheet's first step, above "Continue with email": a 52px secondary block button with the
Google "G" mark (an inline SVG in `components/ui/icons.tsx`, the official four colours are the
one allowed exception to token colours; comment it) and "Continue with Google". The Terms box
moves above both buttons on this step; both stay disabled until it is ticked, with the existing
hint.

## Acceptance criteria

## Notes

Built behind `VITE_ENABLE_GOOGLE_SIGNIN` (off by default, documented in `.env.example` and docs/operations.md) so main stays releasable: with it off the sheets are unchanged. RL-191 turns the flag on (local `.env` for the release, and mapping it in `preview.yml`) after enabling the provider. `AuthContextType.signInWithGoogle` is defined only when the flag is on, and the sheets show the button only then.

Service: `signInWithGoogle` and `completeGoogleRedirect` in `services/firebase.ts`, tested with mocked Auth SDK calls in `services/firebase.google.test.ts` (popup, link, blocked popup to redirect, standalone, closed popup, credential already in use, redirect completion). `AuthContext` shares the upgrade steps with the email path (`applyUpgrade`), then claims the stored intent. The Terms tick is stored before the popup with owner `google.com`, accepted by `checkTerms` only for a Google-provider user (backlog/DECISIONS.md).

Not done: the emulator walk (no browser in this run; the QA.md entry covers it). Not built: decisions.md's "unverified Google address gets the confirm your email sheet" (not in the criteria, and no such sheet exists in the client to hook into; follow-up ticket needed, noted in QA.md); no analytics event for Google sign-in.

Review fixes: redirect completion runs once per page load; a failure after sign-in is reported but still counts as signed in; `auth/account-exists-with-different-credential` gets "That email already has an account. Sign in with your email link instead."; redirects resolve `'redirecting'` and keep the tick and intent; an abandoned redirect's tick is cleared on the next load; SignUpDialog's tick is shared with the email step both ways; first focus goes to the Terms box when unticked; the sheets cannot be dismissed while the popup is open; the busy button is named "Signing in with Google" with `aria-busy`; the Google error clears when the box is toggled or the guest option runs, and is tied to the button.
