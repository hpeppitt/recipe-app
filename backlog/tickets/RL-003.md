## Context

`useSuggestions` subscribes to `suggestions` regardless of auth state, and the rule is
`allow read: if signedIn()`, so every signed-out visit to a recipe page throws an uncaught
`permission-denied` and files a `clientErrors` document. That is every shared-link visit,
the app's main growth loop, and the beacon collection fills with it. Full history in
AUDIT.md under FUN-17. A fix was written on `wip/fun-17-suggestions-gate` and left
unmerged because it could not be browser-verified; read that branch first.

## Acceptance criteria

- [x] `useSuggestions` does not call `onSnapshot` until there is a signed-in user, and tears down on sign-out.
- [x] Results are keyed on `uid:recipeId` as `useSuggestionThread` already does, so a sign-out cannot leave the previous account's suggestions on screen.
- [x] A signed-out visitor sees the suggestions area in whatever state the page already shows for "nothing to show", not an error.
- [x] No `permission-denied` is thrown or beaconed on a signed-out recipe visit.

## Out of scope

Swallowing `permission-denied` in the listener's error handler. That hides real denials.

## Verification

Unit-test the gating logic if it can be extracted; otherwise a hook test once RL-002 lands.
Human QA: open a `/shared/:id` link in a fresh signed-out profile and confirm an empty
console. Record that check in `backlog/QA.md`.
