## Context

`SuggestMode.tsx` (RL-107) lets a visitor tap ingredient rows, type a new amount and a why, add
a free note in a separate textarea ("Note for <author>"), and sends one composed string through
`onSend(message)` → `useSubmitSuggestion` → `createSuggestion` (`src/services/firestore.ts`
~580), which also notifies the owner with that text. RL-145 adds `SuggestionEdit`,
`parseAmountText`, `describeEdits` and the extended `composeSuggestionMessage`. The current
suggestion create rule does not restrict keys, so an `edits` field is accepted before RL-146
lands; RL-146 then validates it.

### Design (9b, existing tokens)

Sage banner "Tap any line to suggest a change · Cancel" (unchanged). Ingredient rows and the
inline editor are unchanged (accent-100 card, 2px accent-700 ring, old amount struck, arrow,
new amount pill, "Why? (optional)"). New, in this order after Ingredients:
- **Method**: heading 20px like Ingredients; each step a row button (min 44px, 15px, numbered
  disc as on the recipe page, the step text) named "Suggest a change to step N". Tapping opens
  the same inline card holding the old text struck (13px, neutral-700) above a textarea prefilled
  with the step (rows 3, max 1000), and the Why field and undo X as for ingredients.
- **General note** row at the end of the list: a row button with a `MessageCircle` icon, "General
  note" and, once written, the first line of the note; tapping opens the same card with a
  textarea "Anything that is not one line" (max `MAX_NOTE`). This replaces the separate note
  textarea.

Footer: "<N> changes to suggest" counts ingredient edits that change the amount, step edits that
change the text, and the note if it has text. CTA "Send to <first name>" as now.

## Acceptance criteria

- [x] Method step rows and the General note row work as above; Escape and the X undo an open edit and return focus to its row, as ingredient edits do.
- [x] An ingredient's new amount must parse with `parseAmountText`; otherwise the card shows "Use a number, and a unit if it has one, like 80 g" (role alert, linked by `aria-describedby`) and the change is not counted. Send is disabled while any open edit is invalid.
- [x] Sending builds `edits: SuggestionEdit[]` (ingredient: `index`, `name`, `from` the shown amount, `to`, `why`; step: `index`, `from` the old text, `to`, `why`; general: `from: ''`, `to` the note) and `message = composeSuggestionMessage(...)`; unchanged edits are dropped. `onSend` becomes `onSend({ message, edits })` on both pages that mount suggest mode; `createSuggestion` and `useSubmitSuggestion` write `edits` alongside `message`.
- [x] The owner's notification `message` is `truncateNotificationMessage(describeEdits(edits))` when there are edits, else the message as today.
- [x] The over-length check still uses the composed message (`MAX_MESSAGE`).
- [x] Tests: step edit and note produce the right `edits` and count; invalid amount blocks send; unchanged edits dropped; `createSuggestion` called with both fields (mocked); notification text from `describeEdits`.
- [x] `docs/capabilities.md` "Suggest a change" row: structured edits on ingredients and steps plus a general note.
- [x] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

How the owner sees or acts on edits (RL-148 to RL-150). Editing ingredient names or adding and
removing lines in a suggestion. Rules (RL-146).

Gates: tests, `ui-reviewer`, `data-integrity-reviewer`. Human with two verified accounts on the
