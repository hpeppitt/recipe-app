## Context

The spec's Grow generates the branch and then opens What changed. In this app a grown branch is
a draft in the chat until "Save Variation" (decision 1b: save is cloud first and explicit,
RL-082). Auto-saving on Grow would change that decision, so this ticket moves only the landing:
after a variation is saved, the app opens `/recipe/<newId>/changes` (What changed vs the parent,
RL-073) instead of `/recipe/<newId>`. The save itself is unchanged. Log the reading in
backlog/DECISIONS.md; the alternative (auto-save on Grow) is an author question.

## Acceptance criteria

- [x] After a successful variation save (`useRecipeChat.ts` ~350 and ~391 build the navigation today), the app navigates to `/recipe/<id>` and then pushes `/recipe/<id>/changes` carrying the same `state: { saved, note }`, so `RecipeChangesPage` shows the same `SavedToast` and its Back (`goBack`, ~252, which follows history) lands on the new branch, not the chat. Do it without a visible flash of the recipe page (a `replace` to the recipe then a push, in one effect, or a history entry written with `navigate(..., { replace: true })` followed by `navigate(changes)`); log the mechanism.
- [x] "Cook this one" in the footer opens the recipe as today.
- [x] New originals still open the recipe page (they have no parent).
- [x] The save code path (publish, cache, errors, rate limit) is untouched; tests prove only the target changed.
- [x] `docs/capabilities.md` Save a generated recipe row.
- [x] A `backlog/QA.md` entry: branch a recipe, Grow, Save Variation: What changed opens with the toast; Back lands on the new branch.
- [x] `npm test`, `npm run lint`, `npm run build` pass.
