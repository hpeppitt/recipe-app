## Context

A suggestion today is free text: `Suggestion.message` plus `status: 'pending' | 'approved' | 'rejected'`
(`src/types/social.ts`). Suggest mode composes ingredient amount edits into that text
(`composeSuggestionMessage`, `src/lib/suggestion.ts`). Approving adds the suggester to the
recipe's `collaborators` and opens the variation composer prefilled (decisions.md "Suggestion
approval writes the collaborator first (RL-017)"; `useSuggestionReview.ts`;
`updateSuggestionStatus` in `src/services/firestore.ts` ~718).

The author decided on 2026-10-20 that v1 has structured suggestions: `edits[]` of
`{ kind: 'ingredient' | 'step' | 'general', index?, from, to, why? }`; the recipe owner can
**Apply** (edits the recipe in one tap), **Decline**, or **Keep as branch** (creates a branch
credited to the suggester); statuses open / applied / declined / branched. This ticket is the
pure model and the written decision every later ticket builds on (RL-146 rules, RL-147 suggest
mode, RL-148 write paths, RL-149 and RL-150 screens, RL-151 Activity). New logic in `src/lib`
comes with tests and imports nothing from `services/` or `hooks/`.

### The model (groomer's design; record it in decisions.md)

```ts
export interface SuggestionEdit {
  kind: 'ingredient' | 'step' | 'general';
  /** Position in the recipe when suggested: ingredients[index] or instructions[index]. Absent for general. */
  index?: number;
  /** Ingredient only: the ingredient name when suggested, so the diff row and the stale check do not depend on the index. */
  name?: string;
  /** ingredient: old amount as shown ("150 g", "" when none); step: old step text; general: "". */
  from: string;
  /** ingredient: new amount as typed ("100 g"); step: new step text; general: the note. */
  to: string;
  why?: string;
}
```

`name` is one key beyond the spec's shape, so the diff row can show "**100 g** light brown sugar
~~150 g~~" without re-reading the recipe. Stored statuses keep today's values where they mean the
same thing, so no document is migrated: `'pending'` is shown as Open, `'rejected'` as Declined;
`'applied'` and `'branched'` are new; `'approved'` stays readable on old documents and shows as
Approved. `Suggestion` gains `edits?: SuggestionEdit[]` (absent on old ones) and
`branchId?: string` (set with `'branched'`). `message` is still written, composed from the
edits, so old clients, notifications and data exports keep reading text.

## Acceptance criteria

- [x] `src/types/social.ts`: `SuggestionEdit` as above, `Suggestion.edits?`, `Suggestion.branchId?`, status union `'pending' | 'approved' | 'rejected' | 'applied' | 'branched'`. Every `switch`/map over status compiles (fix exhaustiveness only; UI copy changes belong to RL-149/150).
- [x] `src/lib/suggestion.ts` adds, with tests in `suggestion.test.ts`:
  - `parseAmountText(text): { amount: number | null; unit: string | null } | null`: "100 g", "1/2 cup", "½ tsp", "1 1/2 cups", "1.5 kg", "2" (unit null); "" and "a pinch" return null.
  - `describeEdit(edit)`: ingredient "150 g light brown sugar → 100 g" (no old amount: "light brown sugar → 100 g"); step "Step 3: <to, cut to 60 chars with …>"; general the note cut to 80.
  - `describeEdits(edits)`: the first description, plus " and N more" when there are more.
  - `composeSuggestionMessage` keeps its current output for ingredient edits and also writes step edits ("Change step 3 to: <text>.") and the general note, so `message` stays readable.
  - `applySuggestionEdits(recipe, edits)`: returns `{ ok: true, patch }` with new `ingredients` and `instructions` arrays (amount and unit from `parseAmountText(to)`, step text from `to`; general edits change nothing), or `{ ok: false, stale: number[] }` (edit positions) when an ingredient at `index` no longer has `name` (case-insensitive, trimmed) and no single other ingredient does, or its shown amount no longer equals `from`, or a step at `index` no longer equals `from`. All or nothing.
  - `hasApplicableEdits(edits)`: true when there is at least one ingredient or step edit.
  - `buildBranchFromSuggestion(parent, suggestion, owner, id, now)`: a new `Recipe` with `parentId = parent.id`, `rootId = parent.rootId`, `depth = parent.depth + 1`, `createdBy = owner`, `collaborators = [suggester]`, `prompt = describeEdits(edits)`, title, emoji, description, times, servings, tags, notes and nutrition copied from the parent, the edits applied, `chatHistory: []`, `createdAt = updatedAt = now`. Throws if the edits are stale.
- [x] `docs/decisions.md`: a new entry "Structured suggestions replace Approve (2026-10-20)" stating the model, the stored status values and their labels, that Apply edits in place through the cloud-first edit path (RL-083) and adds the suggester to `collaborators` in the same write, that Keep as branch makes a new branch owned by the recipe owner with the suggester as collaborator and no AI call, that free-text suggestions (no edits) and general-only ones get Decline and **Mark applied** (status applied, recipe untouched), that existing `'approved'` suggestions and the collaborators they added are left as they are, and that Approve is no longer offered. Mark the RL-017 entry superseded, pointing at it.
- [x] `docs/data-model.md`: the `suggestions` row lists `edits`, `branchId` and the status values.
- [x] `npm test`, `npm run lint`, `npm run build` pass.
