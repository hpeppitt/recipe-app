## Context

Written for RL-161's recommended answers 4 to 6; regroom otherwise. An owner may already
rewrite their own recipe's `parentId`, `rootId` and `depth` (`isOwnerUpdate` checks only
ownership, `createdAt` and content bounds), so no rules change is needed when every version that
moves is the mover's. The write must be cloud first (decision 1b; the own-recipe sync would undo
a local-only change), bounded in time like other writes, and then mirrored to Dexie with get
then put.

### Design (7d)

Under the Related family card, on the new original only, when the viewer is its author: a
surface card (radius 24px, padding 14px 16px, 13px, gap 10px) with a git-merge icon in a small
circle and "Is this really a version of <family title>? **Move it into that family**. You stay
the author." where the bold part is a button. It opens a `ConfirmDialog`: title "Move into
<family title>?", body "It becomes a branch of <matched title>, with its <N> branches. You stay
the author.", Keep it / Move.

## Acceptance criteria

- [ ] Pure `planFamilyMove(subtree, target)` in `src/lib/tree.ts`: for the moving original and its descendants returns the new `parentId` (the original's becomes the target id), `rootId` (target's root) and `depth` (target depth + 1 + old depth) per id. Tests: single recipe, a two-level subtree, target that is a branch.
- [ ] The Move line shows only to the author and only when every version in its family is theirs; otherwise it reads "Only you can move this while every branch in it is yours." with no button.
- [ ] Move commits one batch of owner updates (`parentId`, `rootId`, `depth`, `relatedFamilyId: null`) within 10 s, then puts the same changes in Dexie; on failure nothing local changes and an inline error shows. After success the page reloads the lineage and shows the family label and version pill of its new family.
- [ ] After success the target family's author is notified with the RL-153 `branch` notification if RL-153 is merged (recipe id = the moved original); otherwise skip and note it.
- [ ] Tests: the batch contents, the guard for other cooks' versions, failure leaves Dexie untouched.
- [ ] `docs/capabilities.md` (a Related family row) and `docs/architecture.md` (the write) updated.
- [ ] A `backlog/QA.md` entry. `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Moving recipes that contain other cooks' versions, unlinking, moving branches between families
in general.
