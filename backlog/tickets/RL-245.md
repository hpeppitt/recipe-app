## Context

Cooks carry `rootId` (RL-192), so a family's cooks are one query `cooks where rootId == X
limit 1000` (equality, automatic index). `familyLeader` is in RL-242.

## Acceptance criteria

- [x] `getFamilyCooks(rootId, max = 1000)` and `useFamilyCooks(rootId)` returning `{ countById: Map, total, leaderId, loading }`, bounded at 6 s, reported as `family-cooks`, read once per tree visit.
- [x] A family with more than 200 cooks counts the newest 200 (decision: 200 not 1000, composite index) (shortcut comment).
- [x] Tests.
- [x] `docs/data-model.md` read cost.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

UI.

## Verification

Tests, `data-integrity-reviewer`.

## Notes

Default max is 200 and the query needs a composite index (rootId asc, createdAt desc), deployed with RL-209; see DECISIONS.md. Counts are distinct people. Cache is per rootId in memory only.
