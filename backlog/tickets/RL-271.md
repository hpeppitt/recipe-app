## Context

Every path that creates recipe content passes through one Zod field: `GeneratedRecipeSchema.emoji`
in `schemas/recipe.schema.ts` is extended by the import output schema (`lib/linkImport.ts`),
the file import schema (`ImportedRecipeSchema`, `lib/import.ts`) and the shared hash link
schema (`lib/share.ts`), and `services/gemini.ts` parses generation output with it. The
remaining write path is the editor: `RecipeEditPage.tsx` has a free text "Emoji" input and
`lib/recipeEdit.ts` saves `draft.emoji.trim() || previous.emoji`. Helper: RL-270.

## Acceptance criteria

- [x] `GeneratedRecipeSchema.emoji` is `z.string().transform((s) => oneEmoji(s, RECIPE_EMOJI_FALLBACK))`, so a model or file returning "🍞🧈" yields "🍞" and one returning "bread" yields the fallback. A parse never fails on the emoji alone.
- [x] The response schema's emoji description says "Exactly one food emoji, nothing else."
- [x] `recipeEdit.ts` saves `oneEmoji(draft.emoji, previous.emoji)`.
- [x] The edit page's Emoji input keeps one emoji: on change it holds `lastEmoji(value)`, so typing or picking a second emoji replaces the first; deleting it leaves the field empty and the save keeps the previous emoji (existing behaviour). The 72px `EmojiBlob` preview never shows more than one.
- [x] Tests: a schema test for two emoji and for text; a `recipeEdit` test; an edit page test that typing a second emoji replaces the first.
- [x] `docs/data-model.md` says `emoji` is one emoji grapheme; `docs/capabilities.md` edit row mentions the one-emoji field.
- [x] A `backlog/QA.md` entry: "Edit a recipe's emoji on a phone: pick two emoji from the keyboard; only the last stays, and the icon fits its circle."
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Stored data (RL-272), the rules (RL-273), an emoji picker UI, avatar `photoEmoji`.

## Verification

Unit and page tests. Human: the QA.md walk with the iOS and Android emoji keyboards.

## Notes

`GeneratedRecipeSchema.emoji` now transforms through `oneEmoji`, so the import, file and share schemas that extend it inherit it. Save uses `oneEmoji(draft.emoji, previous.emoji)`. The edit input uses `typedEmoji(prev, next)` (new in `src/lib/emoji.ts`), so the newly added emoji wins wherever the caret was; it skips normalising while composing and normalises on compositionend. `recipeToDraft` seeds `oneEmoji(recipe.emoji, '')`; an empty field previews the recipe's current emoji with a hint line.
