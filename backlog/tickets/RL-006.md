## Context

`npm run build` warns that the main chunk exceeds 500 kB after minification. Nothing is
code-split, so the whole app ships as one bundle, which works against the mobile-first
premise and against the PWA precache in RL-007.

## Acceptance criteria

- [x] Pages are loaded with `React.lazy` behind a `Suspense` fallback that uses the shared `Spinner`, with the Library page kept eager so first paint is unchanged.
- [x] The Firebase SDK is in its own chunk (manual chunk or natural split) so local-only mode does not download it eagerly if that is achievable without a client-visible behaviour change; if not, say so in Notes.
- [x] The 500 kB warning is gone and the largest chunk size is recorded in the ticket Notes.
- [x] Navigating between routes shows no flash of empty content longer than the spinner.

## Out of scope

Tree-shaking individual Firebase modules or changing imports in `services/`.

## Verification

`npm run build` output. Human QA: the standing walk, watching for a visible loading flash.

## Notes

- Before: one chunk, `index` 987.54 kB (300.97 kB gzip), with the 500 kB warning.
- After: `index` 461.47 kB (145.29 kB gzip), `firebase` 412.12 kB (126.68 kB gzip), seven page chunks of 3 to 21 kB (RecipeDetailPage 20.64, RecipeChatPage 20.10, ProfilePage 16.70, RecipeEditPage 11.08, SharedRecipePage 7.65, SettingsPage 4.53, VersionTreePage 3.03) plus small shared chunks (TagList 9.15, SuggestChangeModal 9.89, RecipeContent 4.07, AuthModal 3.25 and a few under 3 kB). No warning; `chunkSizeWarningLimit` untouched.
- Firebase: `services/` imports it statically from the Library path, so it cannot be deferred without changing `services/` (out of scope). It is its own cacheable chunk but still downloads at start; local-only mode still fetches it.
- Suspense sits inside the RouteErrorBoundary in `App.tsx` and `AppShell.tsx`, so a failed chunk load shows the existing fallback. The fallback is a 50dvh centered spinner (`components/ui/PageFallback.tsx`).
- No pages are imported from components, hooks or lib. No PWA manifest or service worker exists yet (RL-007).
- Not browser-tested here; offline chunk-load and flash checks are in QA.md.
