## Context

`decodeRecipeFromHash` (`lib/share.ts` line 79) returns `JSON.parse(json) as SharedRecipe`
with no validation. A hand-built `/shared#r=` link missing `ingredients` blanks the page,
and whatever it contains is saved to Dexie by "Save a copy" in `SharedRecipePage.tsx`.
`src/schemas/recipe.schema.ts` already has `GeneratedRecipeSchema` and a `CreatedBy` shape.
Related to RL-004 (render guard and error boundary), which protects the page but does not
validate input.

## Acceptance criteria

- [ ] `decodeRecipeFromHash` validates the parsed value with a schema built from `GeneratedRecipeSchema` plus an optional `createdBy` (`{ uid: string, displayName: string | null }`), and returns `null` on failure, which `SharedRecipePage` already renders as the "Invalid Link" state.
- [ ] Unknown extra keys are stripped, not passed through.
- [ ] `src/lib/share.test.ts` covers: a round trip of `hashShareUrl` output, a payload missing `ingredients` (null), a payload with `ingredients` as a string (null), and a payload with an extra key (stripped).

## Out of scope

Authenticating `createdBy` on hash links (they are unsigned by nature; see the questions in
the grooming report), validating cloud documents on read, and changing `SharedRecipePage`.

## Verification

`npm test`. No human check beyond the standing `/shared` walk.
