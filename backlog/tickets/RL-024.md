## Context

`decodeRecipeFromHash` (`lib/share.ts` line 79) returns `JSON.parse(json) as SharedRecipe`
with no validation. A hand-built `/shared#r=` link missing `ingredients` blanks the page,
and whatever it contains is saved to Dexie by "Save a copy" in `SharedRecipePage.tsx`.
`src/schemas/recipe.schema.ts` already has `GeneratedRecipeSchema` and a `CreatedBy` shape.
Related to RL-004 (render guard and error boundary), which protects the page but does not
validate input.

## Acceptance criteria

- [x] `decodeRecipeFromHash` validates the parsed value with a schema built from `GeneratedRecipeSchema` plus an optional `createdBy` (`{ uid: string, displayName: string | null }`), and returns `null` on failure, which `SharedRecipePage` already renders as the "Invalid Link" state.
- [x] Unknown extra keys are stripped, not passed through.
- [x] `src/lib/share.test.ts` covers: a round trip of `hashShareUrl` output, a payload missing `ingredients` (null), a payload with `ingredients` as a string (null), and a payload with an extra key (stripped).

## Out of scope

Authenticating `createdBy` on hash links (they are unsigned by nature; see the questions in
the grooming report), validating cloud documents on read, and changing `SharedRecipePage`.

## Verification

`npm test`. No human check beyond the standing `/shared` walk.

## Notes

- `decodeRecipeFromHash` now parses with `GeneratedRecipeSchema.extend({ createdBy: CreatedBySchema.optional() })` (`CreatedBySchema` is now exported from `recipe.schema.ts`; `GeneratedRecipeSchema` is unchanged). z.object strips unknown keys at every level, so ingredients, instructions and nutrition are stripped too.
- Older shapes checked via git history of `lib/share.ts` and `types/recipe.ts`: 1a12cbb (no createdBy, no nutrition), d0497f5 (adds createdBy, which may lack displayName after JSON round trip; `.catch(null)` covers it), bafcce3 (adds `nutrition`, emitted as null when absent). Content fields have been the same types since the first commit. Tests cover an old link without createdBy and nutrition.
- Save a copy: `SharedRecipePage` already falls back for a missing createdBy; the validated object carries every field it reads. No coercion is applied: a hand-edited string `servings` now yields Invalid Link.
- Decoded value is cast to `SharedRecipe` because that Pick type says `createdBy` is required while old links lack it (page already uses `?.`). Not changed, out of scope.
