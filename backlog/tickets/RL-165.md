## Context

A signed-out user cannot reach Settings, so they cannot change the theme or units. The own
profile renders the "You're browsing" empty state for `!user` (`src/pages/ProfilePage.tsx`
~600) with no header, and the Settings cog exists only in the signed-in profile header
(`ProfilePage.tsx` ~212, `IconButton variant="flat" label="Settings" href="/settings"`).

`/settings` itself has no auth guard (`src/App.tsx:64`), but it is not built for a signed-out
user: the Account row shows "Sign in / Not signed in" and navigates to `/profile`
(`SettingsPage.tsx` ~185-222), and account-only controls assume a user.

## Acceptance criteria

- [x] The signed-out "You're browsing" state on the You tab shows the same Settings cog, in the
      same place and style as the signed-in profile header (top right, `IconButton
      variant="flat"`, label "Settings", `href="/settings"`). Reuse the existing markup.
- [x] Signed out, Settings shows no user-specific data: no avatar, name, email or guest line,
      no Sign out, and nothing that reads or writes the cloud account (including any
      account-only rows added by other tickets, such as Notify me when in RL-155, if merged
      first; hide them when `!user`).
- [x] Where the Account card usually is, a signed-out user sees a Sign in row (same card and
      row style, a log-in or user-round icon, "Sign in", sub-line "Save, branch and follow
      cooks"). Tapping it opens the existing `AuthModal` with `action={{ kind: 'continue' }}`
      on the Settings page, not a navigation to `/profile`. After sign-in the user stays on
      Settings and the Account card appears.
- [x] Appearance (theme, units), Your data (device export, delete recipes on this device) and
      Legal stay available signed out, unchanged.
- [x] When Firebase is not configured (`!isConfigured`) behaviour is unchanged: no Account
      group, no Sign in row.
- [x] Tests: ProfilePage signed out renders a link named "Settings" to `/settings`;
      SettingsPage signed out renders a "Sign in" button that opens the auth dialog, and no
      "Sign out" button; signed in still renders the account row.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Desktop rail changes (the rail already lists its items); new settings; guest-specific copy
beyond what exists.

## Verification

Gates: tests. Human: signed out on a phone, open You, tap the cog, switch to Dark, tap Sign
in, finish the email link, land back on Settings with the account shown.

## Notes
Cog reuses the existing markup in the signed-out branch. Settings splits the Account group into a signed-out Sign in row and the unchanged signed-in row. Notify card already hides without a uid. Tests added to ProfilePage and SettingsPage suites.
