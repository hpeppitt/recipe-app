## Context

Save stays one tap (the bookmark, `useFavorites`, RL-122); the sheet is optional. It opens only
after a save (not an unsave) by a verified user. Auto-dismiss must respect WCAG 2.2.1: pause the
timer on any focus, hover or touch inside the sheet.

### The design (the implementer has no other copy)

Sheet (12px 22px 28px, gap 12px): a 22px `bg-accent-2-600` check circle and Caprasimo 20px
"Saved. Add to a collection?". Rows (padding 10px 12px, 22px radius, gap 12px,
`bg-surface-secondary`; chosen: `bg-accent-100` with an inset 2px `accent` ring): a 52px square
(18px radius) showing a 2x2 grid of the first four recipes' emoji at 14px, then the name 15px
bold over "7 recipes" 12px `neutral-700`, and a radio dot at the right. Tapping a row adds the
recipe and closes with the toast "Added to <name>". Last, a 14px semibold `accent-700` "New
collection" (`Plus`) that turns into a name field with "Create"; creating adds the recipe.

## Acceptance criteria

- [x] Opens after a save on the recipe page and `/shared/:id`; never after an unsave; never for guests.
- [x] Closes after 4 s with no interaction; any interaction cancels the timer; Escape and backdrop close.
- [x] With no collections, it shows only "New collection".
- [x] Tests with fake timers: auto-close, pause on interaction, add, create.
- [x] `docs/capabilities.md` Save row.
- [x] A `backlog/QA.md` entry: save a recipe and wait (it closes); save another and add to a new collection.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

Collections in Kitchen (RL-224).

Component tests. Human: the QA.md walk.

## Notes
Sheet is `CollectionSheet` (body mounts per open, so the collections listener exists only while open). `useCollectionSheet` opens it when the favourite flips on within 10 s of a verified save tap, so failed saves and unsaves open nothing. No page-level tests added for the wiring; the sheet and its timers are tested.
