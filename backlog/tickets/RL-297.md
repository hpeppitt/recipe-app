## Context

The author decided that every merge to `main` deploys to dev automatically, in the order
indexes, rules, hosting, with a ruleset diff after. RL-296's runner does the steps; this
ticket is the workflow around it.

It must only deploy what passed the gates. `.github/workflows/preview.yml` deliberately does
not wait for CI (`docs/operations.md`, "Preview deploys"), so a red `main` still deploys there;
this workflow fixes that by triggering on `workflow_run` of the `CI` workflow
(`.github/workflows/ci.yml`) completing with success for a push to `main`. A `workflow_run`
workflow runs from the default branch's file, so it must check out the commit CI tested
(`github.event.workflow_run.head_sha`), not the tip of `main`.

Credentials and client config come from the GitHub Environment `dev` (RL-293): the
`FIREBASE_SERVICE_ACCOUNT` secret and the `VITE_*` variables. Until the author creates it,
the workflow must skip with a note, as `preview.yml` does today.

## Acceptance criteria

- [ ] `.github/workflows/deploy-dev.yml` runs on `workflow_run` (workflows `[CI]`, type
  `completed`) and on `workflow_dispatch`. Its job runs only when the CI run concluded
  `success`, its event was `push` and its branch `main` (or when dispatched from `main`).
- [ ] The job names `environment: dev` with the URL `https://${{ vars.VITE_FIREBASE_PROJECT_ID }}.web.app`,
  `permissions: contents: read`, a 30 minute timeout, and concurrency group `deploy-dev`
  with `cancel-in-progress: false` (a deploy is never cut off between rules and hosting; the
  next one queues).
- [ ] Without the `FIREBASE_SERVICE_ACCOUNT` secret it writes "Dev deploy skipped: the dev
  Environment is not set up. See RL-293 and docs/operations.md, Environments." to the job
  summary and succeeds, running nothing else.
- [ ] Steps: checkout at the CI run's `head_sha` (or the dispatched ref), Node 22 with npm
  cache, `npm ci`, `npm run build` with `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`,
  `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`, `VITE_RECAPTCHA_SITE_KEY`,
  `VITE_ENABLE_GOOGLE_SIGNIN`, `VITE_POSTHOG_KEY` and `VITE_POSTHOG_HOST` from `vars`;
  `google-github-actions/auth@v2` with `credentials_json` from the secret;
  `google-github-actions/setup-gcloud@v2`; then `npm run deploy:dev`.
- [ ] A failed deploy fails the job; the summary written by the runner shows the step that
  failed and the rollback ruleset id.
- [ ] `docs/operations.md` describes the dev pipeline: trigger, gate on CI, Environment,
  order, where the URL and ruleset ids appear, how to rerun (Actions, Deploy dev, Run
  workflow), and that dev data is test data that may be wiped.
- [ ] `backlog/QA.md` gets a line: after the next merge to `main`, the Deploy dev run is green
  and its summary shows an empty ruleset diff after deploy.
- [ ] `npm run backlog -- validate` passes; `actionlint` is clean if available (otherwise say
  so in the PR).
