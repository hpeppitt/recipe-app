## Context

The author picked 9b, "Tap a line, edit it in place": "The page becomes the form: sage banner
replaces the header, tapping an ingredient opens an inline amount editor with the accent
ring." Spec: `docs/design/organic/export/App Spec.dc.html`, "Suggest mode (9b)"; markup: 9b in
`Collaboration and Account.dc.html` and the `suggest`, `sel` row and suggest footer parts of
the `recipe` block in `App Prototype.dc.html`.

The design sends "a structured edit the author can apply in one tap". That needs new fields on
`suggestions` and a rules change, which is a new feature and not in this ticket. Here the edits
are composed into the existing free-text `message` by a pure helper, so the write path
(`useSubmitSuggestion`, the RL-048 limit, the RL-017 owner check, the RL-047 terms rule) is
untouched. Because a free-text message is what a suggestion already is, a note row at the end
keeps today's ability to suggest anything (the design calls this the "General note" gap; here
it is the existing behaviour, not a new one).

Today Suggest opens `SuggestChangeModal`, which shows the sign-up call to action to anyone
without a verified email and the messages "Suggestion sent", "That didn't send. Check your
connection and try again." and "You've sent a lot of suggestions recently. Try again in a
while." (`docs/capabilities.md`, Suggest a change). Those outcomes and copy stay. The shared
page keeps the modal until RL-113.

**Design token map:** ramps keep their names; `--color-bg` is `bg-surface`; neutral-700 text
is `text-text-tertiary`; filled terracotta with cream is `bg-primary-600 text-on-accent`.
Light only. 44px targets.

Values to copy:

- Entering: the footer "Suggest" (RL-104) and the More sheet's "Suggest a change" enter suggest
  mode for a verified user; anyone else gets the existing sign-up prompt (`SignUpDialog` with
  the modal's sign-up copy) and the page stays as it is.
- Banner (replaces the header and hero while in the mode): padding `12px 16px 0`; a pill,
  flex, gap 10px, padding `10px 10px 10px 16px`, `rounded-full`, `bg-accent-2-700
  text-accent-2-100`, 13px 600, `MessageCircle` icon, "Tap any line to suggest a change"
  flex 1, and a "Cancel" button: 32px tall (44px hit area), padding `0 14px`,
  `rounded-full bg-accent-2-100 text-accent-2-900` 600. Cancel with edits asks "Discard your
  suggestion?" in a `ConfirmDialog`.
- Under the banner the title in `font-heading` 28px and a 13px `text-text-tertiary` line "by
  <author> · <total time> · <servings> servings". The lineage strip, pills, stepper,
  nutrition, suggestions and carousel are hidden in the mode; scale resets to the stored
  servings.
- Ingredient rows become buttons named "Suggest a change to <ingredient>". Tapping one opens
  it in place: margin `6px -10px`, padding 12px, `rounded-[24px] bg-accent-100`, inset ring
  `0 0 0 2px` accent; first line, gap 8px, 15px: the old amount struck in
  `text-text-tertiary`, `ArrowRight`, an input 84px wide, height 38px (44px hit area),
  `rounded-full bg-surface`, 700, inset ring 1.5px accent, `aria-label="New amount"`,
  prefilled with the old amount and unit, then the name flex 1, then a 32px round
  `bg-surface` "Undo this change" button with `X`. Second line: a `bg-surface`
  `rounded-[18px]` input, padding `10px 14px`, 14px, placeholder "Why? (optional)".
  Several rows can be open at once.
- After the ingredients: a "Note for <author> (optional)" textarea in the same `bg-surface`
  `rounded-[18px]` style, for anything that is not one line.
- Footer: padding `12px 20px 28px`, flex, gap 10px, top rule; 13px `text-text-tertiary`
  flex 1: "Tap any line to change it" with no edits, "<b>1 change</b> to suggest" or
  "<b>n changes</b> to suggest"; a primary 52px button, padding `0 22px`, 15px, `Send` icon,
  "Send to <author first name>", disabled until there is an edit or a note.
- Sending: `composeSuggestionMessage` builds the message and calls the existing submit. On
  success the mode closes and a toast says "Sent to <author>". On failure the mode stays with
  the existing error copy in a `role="alert"` line above the footer.

## Notes

SuggestionThreadPage.tsx is listed for one class (`whitespace-pre-line`) so composed line breaks show in the pinned message.

Implemented as SuggestMode (own ingredient rows, IngredientList untouched), page swap keyed by recipe id,
sign-up via SignUpDialog with the modal's copy. No length cap: the suggestion rule has no size check and
notifications truncate themselves. The ref guard against a double send is belt and braces (the button is
also disabled while sending); a test cannot tell them apart. Not measured: 320px layout.
