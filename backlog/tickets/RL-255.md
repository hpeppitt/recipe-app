## Context

27b publishes a collection: a description, a public URL, cards naming the recommended branch,
and "Follow this cookbook" so new additions land in Activity. Collections are private today
(RL-210/211). Notifications are written by the acting user, one small rate-limited transaction
each, at most 60 an hour (RL-049), so telling every follower by writing a notification each
does not scale and would hit the limit. Publishing changes who can see what, so it needs the
author. RL-256 to RL-260 are written for the recommendations.

## Questions and the groomer's recommendation

1. **Publishing**: the owner turns on "Share as a cookbook" on a collection, which sets
   `visibility: 'public'` and a `description` (<= 280); public collections are readable by
   anyone, signed out included, like recipes (recommended). Turning it off makes it private
   again; existing links then show "This cookbook is private".
2. **URL**: `/c/<collectionId>` (recommended).
3. **Contents**: only published recipes can be in a public cookbook; private (unpublished) ones
   are hidden from visitors (recommended).
4. **Following**: `cookbookFollows/{uid}_{collectionId}` (`{ uid, collectionId, createdAt,
   lastSeenAt }`), created and deleted by the follower, verified; readable by the follower only
   (recommended).
5. **Telling followers**: a pull model with no fan-out: the collection keeps `lastAddedAt`;
   Activity reads the user's followed cookbooks (at most 30) and shows "New in <cookbook>" when
   `lastAddedAt > lastSeenAt` (recommended). Alternative: a notification per follower (hits the
   RL-049 limit).
6. **Owner sees followers**: a count only (`followerCount` bumped ±1 like profiles), not who
   (recommended).
7. **Privacy policy**: a cookbook paragraph in RL-260.
