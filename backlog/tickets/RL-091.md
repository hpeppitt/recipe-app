## Context

The five-slot nav (RL-097) has a Saved tab. Decision 1b in `docs/decisions.md` already says
what it holds: "My Recipes is to be split into Created (own, no parent) and Branched (own
variations ...), with other people's recipes only under Saved." `splitLibrary` in
`src/lib/library.ts` (RL-084) returns `{ created, branched, saved }` and no page calls it yet.
This ticket builds the Saved page component only; RL-097 adds the `/saved` route and tab.

Data, unchanged: `useLocalLibrary()` (Dexie live query) for rows, `countFrom` the same rows
(as `LibraryPage` does for variation counts), `useAuth()` for `uid` and `isConfigured`, then
`splitLibrary(rows, rows, { uid, isConfigured }).saved`. Favourites (hearts) are NOT listed
here: a favourite stores only `{ uid, recipeId, createdAt }` and listing them needs a cloud
read per recipe, which is a feature decision for the author (see Out of scope).

Design, from the `saved` block in `docs/design/organic/export/App Prototype.dc.html`:

**Design token map:** `--color-bg` is `bg-surface`; `--color-surface` is
`bg-surface-secondary`; neutral-700 text is `text-text-tertiary`; neutral-800 text is
`text-text-secondary`. Light only: no `dark:` classes. 44px targets.

- Header: "Saved" in `font-heading` 30px, padding `16px 20px 0` (the design's 52px top is
  the phone status bar).
- List: padding `14px 20px 0`, gap 12px. Each row is a link to `/recipe/:id`: flex, gap 14px,
  padding 14px, `rounded-[28px]`, `bg-surface-secondary`; a 52px circle `bg-neutral-100`
  with the emoji at 26px; a block with the title in `font-heading` 17px and under it a 12px
  `text-text-tertiary` row (gap 8px) with `UserPill` (RL-088) for the author and the total
  time (`formatTime`); a `ChevronRight` at the end.
- Empty (19a, via `EmptyState` full page from RL-090): bookmark icon, "Nothing saved yet",
  body "Recipes you keep from a shared link or an import wait for you here." (the design's
  "Tap the bookmark" copy would be false here, see Notes), action "Explore recipes" to `/`.
- Loading: `localRecords === undefined` shows three 19a list skeleton rows.

## Acceptance criteria

- [x] `src/pages/SavedPage.tsx` exports `SavedPage` rendering the header, list, empty and loading states above from `splitLibrary(...).saved`, newest first (as `splitLibrary` already sorts).
- [x] Each row is one link with an accessible name equal to the recipe title; the `UserPill` is inside it, not a nested link.
- [x] Local-only mode (`isConfigured` false): every row is the user's own per `splitLibrary`, so Saved is empty and shows the empty state; its action still goes to `/`, which lists the device's recipes in local-only mode (RL-098).
- [x] `SavedPage.test.tsx` covers: saved rows listed and own rows excluded, empty state copy and action, loading skeleton.
- [x] No route is added here (RL-097 does it).
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

The `/saved` route and nav tab (RL-097). Listing favourites or bookmarks here, and turning
the heart into a bookmark (author decision). Removing My Recipes from `LibraryPage` (RL-098).

`npm test`; `ui-reviewer`. Browser check happens with RL-097's QA entry (open Saved after

## Notes

Copy note: the design's empty text says "Tap the bookmark on any recipe", but in this app the
heart favourites a recipe without putting it in Saved. The body copy above says what really
fills the list. If the author decides favourites belong in Saved, revert to the design copy.


Implementer notes: `SavedPage` built from `splitLibrary(...).saved`; empty action is a Button that navigates to `/`. No route added.
Accessible name: the link uses `aria-labelledby` on the title, so its name is exactly the title; author and time are exposed through `aria-describedby`.
