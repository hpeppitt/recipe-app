## Context

Written for RL-210's recommendations: `collections/{autoId}` owner-only, `recipeIds` up to 200.
One listener per session on `where ownerUid == uid` (equality only, no composite index), sorted
on the client by `updatedAt`.

## Acceptance criteria

- [x] `createCollection(name, firstRecipeId?)`, `renameCollection`, `deleteCollection`, `addToCollection(id, recipeId)` (`arrayUnion`, refused past 200 with "This collection is full."), `removeFromCollection` (`arrayRemove`), all bounded at 5 s and setting `updatedAt`.
- [x] `useCollections()` returns `{ collections, loading, error, ...actions }` for verified users; others get an empty list without reading.
- [x] Name validation 1 to 60 characters after trimming ("Give it a name." / "Keep it under 60 characters.").
- [x] Tests (Firestore mocked) for each action, caps and validation.
- [x] `docs/data-model.md` costs.
- [x] `npm test`, `npm run lint`, `npm run build` pass.

## Notes

RL-211 review: cap each recipeIds element at 36 characters client-side. The number of collections per user is unbounded in the rules (accepted for now).

RL-222 implementation: `addToCollection` is a transaction that reads the stored document, skips the write when the recipe is already there, refuses at 200 with "This collection is full.", then writes `arrayUnion` plus `updatedAt`, so the cap holds against the latest server state and not just the listener's. The hook also refuses from the listener's list before calling. Validation (`collectionName`, `checkCollectionRecipeId`, `checkCollectionRoom`, `CollectionRefusedError`) lives in `src/lib/kitchen.ts` with tests; the name bound is tied to the rules text. Name length uses UTF-16 `length`, which is never below the character count the rules measure, so it is conservative. A refused write rejects with its copy and does not set the hook's page `error`. A listener failure shows "Couldn't load your collections. ..." rather than the update copy. No emulator walk run.

RL-222 review fixes: the listener's retry is re-armed after a good snapshot; a collection missing from the listener is treated as gone (delete resolves without writing; rename, add and remove reject with "That collection no longer exists." on not-found or permission-denied); remove skips the write when the recipe is not in the listener's copy; create is refused client-side at 100 collections (`COLLECTIONS_PER_USER_MAX`).
