## Context

Written for RL-210's recommendations: `collections/{autoId}` owner-only, `recipeIds` up to 200.
One listener per session on `where ownerUid == uid` (equality only, no composite index), sorted
on the client by `updatedAt`.

## Acceptance criteria

- [ ] `createCollection(name, firstRecipeId?)`, `renameCollection`, `deleteCollection`, `addToCollection(id, recipeId)` (`arrayUnion`, refused past 200 with "This collection is full."), `removeFromCollection` (`arrayRemove`), all bounded at 5 s and setting `updatedAt`.
- [ ] `useCollections()` returns `{ collections, loading, error, ...actions }` for verified users; others get an empty list without reading.
- [ ] Name validation 1 to 60 characters after trimming ("Give it a name." / "Keep it under 60 characters.").
- [ ] Tests (Firestore mocked) for each action, caps and validation.
- [ ] `docs/data-model.md` costs.
- [ ] `npm test`, `npm run lint`, `npm run build` pass.

## Out of scope

UI (RL-223, RL-224). Public cookbooks (RL-256).
