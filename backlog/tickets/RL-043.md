## Context

Favourites are dual-written for a verified user (Dexie, then `favorites/{uid}_{recipeId}`),
but nothing ever reads the cloud collection back into Dexie, so signing in on a second device
shows an empty Favorites filter. The library filter and hearts read Dexie only
(`useFavoriteIds`). Under the 2026-10-14 decision, anonymous bookmarks are local-only (RL-041)
and verified users sync, so this gap now applies only to verified users. The favourites read
rule already allows a user to read their own documents.

RL-034 covers the other direction on upgrade: an anonymous user's local bookmarks are pushed
into cloud favourites when they add an email. This ticket then makes those favourites appear
on the user's other devices.

## Acceptance criteria

- [x] When a verified user is signed in, their cloud favourites are fetched once per session (`where('uid','==',uid)`) and any missing from Dexie are added with their cloud `createdAt`.
- [x] Hydration never deletes a local favourite, and never writes to the cloud or bumps `favoriteCount`.
- [x] Anonymous and signed-out users trigger no fetch.
- [x] The merge logic (given cloud rows and local rows, return the rows to add) is a pure function in `src/lib` with tests.
- [x] `docs/capabilities.md` favourites row and `docs/architecture.md` dual-store section describe the hydration.
- [x] A `backlog/QA.md` entry: favourite on one browser profile, sign into the same account on another, see the favourite.

## Out of scope

Removing local favourites that were removed elsewhere (a deletion sync), and real-time listeners.

## Verification

`npm test` for the pure merge. Browser check with two profiles against the emulator.

## Notes

Pure merge `selectFavoritesToHydrate` in `src/lib/favoritesMigration.ts`; read-only `getCloudFavorites` in `services/firestore.ts` (8 s `withTimeout`, failure reported as `favorites-hydrate`, returns null); `addMissingFavorites` in `src/db/favorites.ts` (one `rw` transaction, re-reads local rows, `bulkAdd` of missing rows only); `useHydrateFavorites` in `hooks/useFavorites.ts`, called by `useFavoriteIds` and `useFavorite`, once per session per verified uid after auth has loaded. `removeFavorite` records a session removal set so a read in flight cannot re-add an unfavourite. Emulator (`demo-rl043`, unsigned tokens, REST `runQuery`): owner verified, own uid 200 (2 docs); owner querying another uid 403; signed out 403. Visible gap logged in backlog/DECISIONS.md: a hydrated favourite whose recipe is not in Dexie is absent from My Recipes > Favorites and appears in Explore > Favorites only once its page is loaded. No rules, index, schema or dependency change.
