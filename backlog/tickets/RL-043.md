## Context

Favourites are dual-written for a verified user (Dexie, then `favorites/{uid}_{recipeId}`),
but nothing ever reads the cloud collection back into Dexie, so signing in on a second device
shows an empty Favorites filter. The library filter and hearts read Dexie only
(`useFavoriteIds`). Under the 2026-10-14 decision, anonymous bookmarks are local-only (RL-041)
and verified users sync, so this gap now applies only to verified users. The favourites read
rule already allows a user to read their own documents.

## Acceptance criteria

- [ ] When a verified user is signed in, their cloud favourites are fetched once per session (`where('uid','==',uid)`) and any missing from Dexie are added with their cloud `createdAt`.
- [ ] Hydration never deletes a local favourite, and never writes to the cloud or bumps `favoriteCount`.
- [ ] Anonymous and signed-out users trigger no fetch.
- [ ] The merge logic (given cloud rows and local rows, return the rows to add) is a pure function in `src/lib` with tests.
- [ ] `docs/capabilities.md` favourites row and `docs/architecture.md` dual-store section describe the hydration.
- [ ] A `backlog/QA.md` entry: favourite on one browser profile, sign into the same account on another, see the favourite.

## Out of scope

Removing local favourites that were removed elsewhere (a deletion sync), and real-time listeners.

## Verification

`npm test` for the pure merge. Browser check with two profiles against the emulator.
