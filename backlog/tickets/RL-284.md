## Context

The author approved the feedback ticket set (RL-285 to RL-291) and answered every question at
`/groom` on 2026-10-22. This ticket only writes those answers down so later readers find them.
Constraints behind them: Spark plan with no functions (decision 2), so no email and no Storage;
cook photos already store a downscaled JPEG data URL of at most 200000 characters in Firestore
(RL-193), which is the pattern here. PostHog was rejected because it is consent-gated, so
feedback from anyone who declined analytics would be lost.

## Decided 2026-10-22

1. **Destination**: a Firestore `feedback` collection.
2. **Who sees the tab**: every verified account, with a device-local Settings switch "Show the
   feedback tab" (on by default) to hide it.
3. **Screenshot**: captured automatically when the tab is tapped, with `html-to-image`
   (approved by the author by name as a client dependency, loaded only on tap; RL-288). The
   user can remove it before sending, and can attach their own instead (RL-287).
4. **Sent with each note**: page path (no query string), app version, screen size, theme,
   user agent, uid and display name.
5. **Limit**: 10 feedback items a day per user, through a `feedback` write window (RL-048
   pattern).
6. **Reading**: with `scripts/feedback.mjs` only (RL-289). There is no in-app inbox.
7. **Retention**: deleted once handled, and kept at most 12 months.
8. **Privacy**: a screenshot can show other people's names and content and the sender's own
   private lists. The sheet says so; only the operator reads feedback; the sender can read
   their own (for Download my data); it joins export and erase; the policy paragraph is RL-290.

Rejected: PostHog (consent-gated), email (needs a server), html2canvas (larger), an allowlist of
beta testers (a rules change and a read per load), an in-app inbox.
