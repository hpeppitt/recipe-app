## Context

The cook write (`useRecipeCooks().log`, RL-197) is the closest pattern: a transaction that
moves `writeWindows/{uid}_cook` and creates the document, bounded with `rejectAfter` (not
`withTimeout`, which would swallow `RateLimitedError`; see the RL-048 decision). Rules:
RL-285.

## Acceptance criteria

- [x] `lib/feedback.ts` (pure): `feedbackContext({ pathname, width, height, theme, userAgent, appVersion })` returns the bounded fields (path without query string or hash, truncated to the rule limits, viewport as "390x844"); `cleanNote(text)` trims and caps at 1000 UTF-16 units. Tests.
- [x] `submitFeedback(user, { note, screenshot }, context)` in `services/firestore.ts` creates `feedback/{autoId}` with exactly the RL-285 keys and moves the `feedback` window in the same transaction; rejects after 15 s; throws `RateLimitedError` at the cap; reports a cap hit once as `rate-limited-feedback`.
- [x] A screenshot over 200000 characters is refused before any write.
- [x] Tests with the Firestore mocks used by `firestore.cookbook.test.ts`: payload keys, window move, cap error, timeout.
- [x] `docs/architecture.md` notes the feedback write beside the other rate-limited writes.
- [x] `npm test`, `npm run lint`, `npm run build` pass.
