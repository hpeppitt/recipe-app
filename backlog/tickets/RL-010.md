## Context

`clientErrors` only grows: no read path, no prune, no TTL. RL-003 removes the biggest
source of noise, but retention is still zero. The cheap answer is a Firestore TTL policy
on `receivedAt`, which is a console or gcloud action with no code.

## Acceptance criteria

- [ ] A TTL policy on `clientErrors.receivedAt` (30 days suggested) exists in production.
- [ ] `docs/operations.md` records the policy and the gcloud command that creates it.
- [ ] `docs/data-model.md` notes the retention on the `clientErrors` row.

## Out of scope

A triage UI.

## Verification

Console. Human only, because it changes production.
